# [ST-12] 重新編排第一章的劇情與過場

> 狀態：待辦

## 內文

### 需求
目前過場動畫太多、太瑣碎，看不出在做什麼（推進劇情？），表達的事情又太少。很多事情可以直接在地圖上說（對話氣泡、無線電、環境敘事、戰鬥中的短句），不需要全部做成過場動畫。需要重新設計並重新編排第一章的劇情：判定哪些事真的需要過場（改變世界狀態、角色關係不可逆、新區域或新能力的首次揭露、章末），其餘改成地圖上的表達；過場數量與長度大幅降低但每一段都有明確的敘事目的；新增「地圖上的短對話」功能（不鎖操作、不停遊戲、可自動消失）。

### 來源
2026-10-06，使用者試玩第一章後回報：「目前過場動畫非常不懂在幹嘛，推進劇情嗎？有時候可以直接在地圖上說話，不見得所有東西都要過場動畫。過場動畫表達的事情也太少了，就像我剛剛說的，非常瑣碎。幫我重新設計然後重新編排」。

### 驗收條件
- [ ] 劇情窗口表：第一章每個劇情窗口的目的（要讓玩家知道或感受什麼）、手法（環境、氣泡、廣播、過場）、位置、字數；過場清單附判準說明
- [ ] 過場全章 ≤ 3 次（開場 ≤ 20 秒、中段大事 ≤ 45 秒、章末 ≤ 60 秒），一律可跳過；兩次過場之間至少 8 分鐘遊玩；過場佔總時長 ≤ 5%
- [ ] 地圖上的短對話功能：不鎖操作、不停遊戲；每句 ≤ 18 字、同屏 ≤ 2 個、顯示時間隨字數；戰鬥中只出 ≤ 10 字的短句；死亡重來時不重播
- [ ] 原有過場的內容拆成氣泡、廣播與環境物件（文件、海報、塗鴉），重要資訊用氣泡加 HUD 一行重複
- [ ] 每個保留的過場都表達更多事情（關係、世界狀態改變、伏筆），並通過 skill `scene-staging` 的構圖與比例檢查
- [ ] 劇本資料通過 `StoryLint` 與過場檢查；台詞符合文風規則
- [ ] 重新跑完整章：沒有「走一段路就被打斷」的感覺（任兩段地圖對話之間至少 20 秒純遊玩）
- [ ] 本票統整出的規則、數值與檢查方法，寫進 skill `chapter-design`（`.claude/skills/chapter-design/`），參考多個不同業界實例並附出處；之後設計章節都必須先讀這份 skill

### 測試流程
1. 從新遊戲玩到章末，計算過場次數與長度
2. 確認地圖上的對話不鎖操作，戰鬥中不出長對話
3. 逐一確認每段過場的敘事目的
