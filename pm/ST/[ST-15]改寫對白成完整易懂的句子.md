# [ST-15] 改寫對白成完整易懂的句子

> 狀態：待辦

## 內文

### 需求
目前的對白有大量兩三個字就斷一句的寫法，看起來很酷，但玩家看不懂。要把遊戲裡**所有玩家會讀到的文字**改寫成完整、易懂的句子，並加上自動檢查避免之後再出現。規則與量測見 `design/13-story-v2/DIALOGUE_READABILITY.md`。

範圍：過場與場景對白（`data/story/*.json`）、地圖氣泡、廣播、戰鬥短句、NPC 對話、死亡與復活的場景、路牌與提示、道具與文件描述、任務與地圖文字（NE-223）、選單 tooltip。角色的聲音（凜、老 K、芽、航等）要保留，但靠用詞與語氣，不靠斷句。

### 來源
2026-10-07 使用者回報：「不要用一些看起來很酷的 1、2 個字來講話，現在的對話文本有大量兩三個字就一個斷句的，看起來很酷但我覺得會看不懂。」並要求開票、確實修復相關的所有問題、寫清楚驗收目標。

### 驗收條件
- [ ] 量測並記錄現況：列出所有違規行（至少含目前已知的 10 行，如「地點，碼頭倉庫。目標，保險箱裡一片資料盤。」），含氣泡、提示、道具描述等其他文字來源
- [ ] 依 `DIALOGUE_READABILITY.md` 的規則改寫全部違規文字：一句講完一件事、沒有單獨成句的一兩個字、同一行最多一個三字以內的子句且不連續、首次出現的專有名詞用一句話說明
- [ ] 角色聲音仍可分辨：每個主要角色挑五行對照改寫前後，確認口吻（凜直接不道謝、老 K 碎念加「喔」、芽嘴碎愛玩笑、航問題多）仍在，並更新 `CHARACTERS.md` 與 `WRITING.md` 中要求「短句」的段落，改成上述規則
- [ ] 放寬並更新氣泡長度規則（每句 ≤ 30 字、戰鬥中 ≤ 16 字且是完整的話），同步修改設計文件與資料檢查的門檻
- [ ] StoryLint 新增可讀性檢查（單獨成句的短片段、連續短子句、平均子句字數、名詞並列斷句、氣泡長度），門檻用現有對白校準；改寫完成後全部文字 0 錯誤、0 警告
- [ ] 逐場景人工通讀一遍（第一章全部場景、氣泡與廣播），每個場景在票上記錄「第一次玩的人能說出：誰在哪裡、要做什麼、為什麼」，不能的場景改寫到能為止
- [ ] 改寫不破壞原有功能：故事資料驗證、連續性檢查（`ContinuityAudit`）、節奏估計、故事相關測試全部通過；台詞行數改變造成的節奏估計變化在票上說明且仍在目標範圍
- [ ] 更新 skill `chapter-design` 與 `scene-staging`（以及 `continuity-qa`），寫入「完整句子、不用斷句裝酷」的規則與檢查步驟

### 測試流程
1. 執行 StoryLint 與連續性檢查，確認 0 錯誤、0 警告
2. 遊玩第一章，閱讀所有對白與氣泡，確認好懂
3. 故事、節奏相關測試通過，完整平行測試無新失敗
