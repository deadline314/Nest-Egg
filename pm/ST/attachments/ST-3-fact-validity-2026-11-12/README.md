# 正式條件的事實有效性

未知旗標、道具與收據、失效事實回呼、不可信帳本及壞派生來源，原本可能被當成 false，再由反向條件變成可用。現在正式入口保留有效性，壞來源不能被 not 或 any 放行。合法未完成旗標、未持有道具、缺收據、候選回呼及既有 null 預設比較保留；只檢查派生來源，不改唯讀時的原存值。重算遇壞來源也不覆寫原值。

三份產品來源與原始 21 檔交付包均逐 bytes／SHA 核對。主工作樹的 NPC 測試工作只插入新測試呼叫與案例，其餘保留；提交另用經測試的純主線測試來源。

|---|---|
| 原真反例 | 14 個事實邊界、5 個派生來源、5 個預設回呼別名反例保留 |
| 最終短驗證 | 永久案例140／0、正式比較5,764／0、原23列、派生8／0、別名8／0、實際重載3／0 |
| 原2fa基準完整受影響範圍 | 22組45,566／0，exit0，726秒；13,157份來源前後一致，0SCRIPT |
| 最新81主線接合 | 原五組2,927／0，exit0，77秒；同三份候選、13,157份來源前後一致，0SCRIPT／退出診斷 |

原22保留145條預期負向 ERROR，以及2條原過濾器允許的關閉錯誤；同一shard另記6個Area RID、7個CanvasItem、25個ObjectDB及13個資源的退出診斷，不宣稱整批零 ERROR／洩漏。最新五組另有79條原負向 ERROR；兩個基準與所有舊失敗、工具錯誤分開保存。不能把舊2fa的45,566項改稱已在81基準執行。

完整有效的 all／any 會檢查後面的事實，合法結果不變，回呼讀取刻意增加3,742次；不再沿用前次結構階段的「讀取次數相同」結論。當前24份正式交易資源提供定義，每根只共用一次帳本證明，不保留跨根的可信捷徑。這不是泛用耐久來源授權、真人遊玩或整票完成聲明；沒有畫面改動，不挪用其他情境截圖。

原始 ZIP、索引、三份來源、命令、完整輸出與獨立讀取器在 [original](original/README.md)。執行 `python -X utf8 verify.py` 可在沒有原工作樹的地方重讀三包資料，不需 Godot。

保護清單的版本差異另在 `protected-context-v23.json`：舊v22的頂層count誤繼承388，但實際files與所有當時來源檢查均為392份。原v22與舊原生紀錄完整保留；新v23明列此誤植並按實際393份更新，未回填舊證據。
