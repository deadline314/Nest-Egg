# [ST-5] 加入區域與出入口讓場景互相連接

> 狀態：完成

## 內文

### 需求
目前一個關卡就是一條由左到右的長地圖，沒有門、沒有分區。新的故事要像《惡靈古堡》一樣，由許多小場景用門相連、可以反覆路過。需要「區域」：每個區域是一張獨立的小地圖，用出入口連到其他區域；玩家從出入口進出，世界狀態在本輪保留（殺掉的敵人、撿過的東西、開過的閘門、頭目的傷），死亡後回到最近的電話亭所在的區域。

### 來源
2026-10-05，使用者要求第一章依新的地圖設計重新做；設計見 `design/13-story-v2/CH01_LEVEL.md` 第 8、9 節。

### 驗收條件
- [x] 地圖資料可以放出入口：互動才進入的門，或走進就切換的出口；每個出入口指定目標區域與目標出入口，並可指定需要的旗標與鎖住時的提示
- [x] 進入新區域時玩家出現在目標出入口，有轉場，不閃黑畫面；鏡頭直接就位
- [x] 本輪的世界狀態在區域之間保留：殺掉的敵人不重生、撿過的信用點與道具不重生、開過的閘門與機關保持、頭目的傷保留（死後回復一部分，比例是資料）
- [x] 電話亭記錄所在的區域；死亡後回到該區域的電話亭；沒有電話亭時回到本區域起點
- [x] 區域進場時可以自動播出過場，過場結束後可自動走出指定出入口，或讓本章結束
- [x] 同一張地圖可以用不同的光影與進場過場當成另一個區域（天亮版的當舖）
- [x] 只放資料就能新增區域，不需要改程式；缺少目標區域或出入口時記錄具體位置並安全退回，不崩潰
- [x] 舊關卡的行為不變（死後敵人重生、世界還原到存檔），完整測試套件全數通過

### 測試流程
1. 從區域 A 的門進入區域 B，確認玩家出現在對應的出入口
2. 在區域 B 殺掉敵人、撿起道具、開啟閘門，回到區域 A 再回來，確認狀態保留
3. 死亡，確認從最近的電話亭所在的區域重生，敵人與閘門狀態保留
4. 故意讓一個出入口的目標不存在，確認記錄錯誤且遊戲不崩潰
5. 執行完整測試套件

# Commit-1

## 內文

關卡原本是一條由左到右的長地圖，沒有門也沒有分區。現在加入「區域」：每個區域是一張獨立的小地圖，用出入口相連。

- 出入口（`PortalData`、`Portal`）：在關卡 legend 把字元對應到它就會出現一扇門。可以互動才進入，或走進就切換；指定目標區域與目標出入口，可要求旗標，鎖住時顯示提示；沒有目標的門是鎖死的擺設。玩家從出入口出現時暫時不觸發，離開一次才啟用，不會來回彈跳。
- 持久世界（`LevelData.persistent_world`）：殺掉的敵人、撿走的拾取物、機關與閘門的狀態、受傷的頭目血量，存在 `GameState.area_states`，離開、再回來、死亡後都保留；死亡時頭目回復已損血量的一部分、扣信用點一個比例（比例都在 `LevelData`），帶走現在的裝備，不再回溯成檢查點當下。舊關卡維持原本的行為。
- 電話亭記錄所在區域（`checkpoint_level_path`），死亡後 Main 載入那個區域；穿過出入口時帶著生命值。
- 進場過場結束後可自動走出指定出入口，或直接結束本章（`after_intro_portal`、`complete_after_intro`），章節標題卡只在第一個區域顯示，其餘區域顯示區域名稱。
- 多資料夾道具庫（`EnvironmentTheme.extra_prop_dirs`）、劇情旗標（`GameState.set_flag/has_flag`）。
- 目標區域或出入口不存在時記錄具體位置並退回起點或拒絕通行，不崩潰。

測試：新增 `AreasSuite`（77 項檢查，含兩個測試區域的來回走、狀態保留、頭目的傷與死亡回復、信用點扣款、檢查點區域、鎖住與缺旗標的門、壞資料、自動離開與結束），既有測試套件全數通過。
無法在這個環境截圖（沒有 GPU），畫面請在有顯示的環境確認門的外觀與轉場。
