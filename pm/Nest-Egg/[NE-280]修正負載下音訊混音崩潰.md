# [NE-280] 修正負載下音訊混音崩潰

> 狀態：完成

## 內文

### 需求

負載較高時，遊戲回歸在混音執行緒讀取已釋放資料而崩潰。要保留正常音效、空間音效與音量行為，修正資料釋放邊界並提供可重建的執行環境。

### 來源

2026-10-26，ST-10八程序回歸兩次真實SIGSEGV；使用者要求高穩定、高容錯並保留所有原有功能。反組譯與上游[Godot 124217](https://github.com/godotengine/godot/issues/124217)指出同版混音資料生命週期風險。[設計與判讀界線](../../design/20-campaign-experience/AUDIO_MIX_LIFETIME.md)。

### 驗收條件

- [x] 保存原版本崩潰、相同負載對照與獨立音訊情境結果，重現與未重現分開記錄。
- [x] 舊音訊資料只在混音不再使用後釋放，不依賴固定兩影格、CPU空閒、關閉音效或略過測試。
- [x] 修後八程序的原受影響回歸通過，沒有新失敗、腳本錯誤或崩潰；選擇器、錯誤篩選與已知失敗清單保持。
- [x] 正常與空間音效仍有實際非零混音、音量與播放進度，正式Main及Forward+功能不退步。
- [x] CI與開發環境可依固定來源與修補重建，核對引擎收據；已驗平台與其他平台建置指引明確。

### 測試流程

1. 在原引擎執行原八程序負載，保存退出碼與崩潰堆疊。
2. 獨立移動音源並讀取真正混音資料，保留未重現與實際失敗。
3. 重建修補環境，重跑原回歸、音訊負載與正式Main互動。
4. 核對CI快取／來源／patch／二進位收據與原篩選器。
