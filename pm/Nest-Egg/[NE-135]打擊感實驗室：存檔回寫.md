# [NE-135] 打擊感實驗室：存檔回寫

> 狀態：完成

## 內文

### 需求
調好的參數要能寫回專案資料檔，而不是看過就忘。要做驗證、差異預覽、安全寫入與備份，匯出版唯讀。

### 來源
2026-10-04，使用者要求處理打擊感；研究與設計見 `design/15-game-feel/RESEARCH.md`（第 8 節），母票 NE-130。

### 驗收條件
- [x] 可把目前參數儲存到回饋資料檔，寫入前先驗證並顯示差異預覽
- [x] 驗證失敗時不寫入並指出具體位置
- [x] 寫入是安全的（寫暫存檔再替換），並留下備份；檔案差異只含被改的項目
- [x] 寫入後重新載入的結果與寫入前一致（測試）
- [x] 匯出的遊戲版本不能寫回

### 測試流程
1. 改幾個參數後儲存，檢查檔案差異只含這些項目
2. 故意輸入不合法的值，確認不寫入

# Commit-1

## 內文

調好的參數看過就忘，沒有辦法寫回專案資料。
實驗室新增「預覽差異」與「儲存」：預覽只列出記憶體與檔案不同的參數（事件.參數：舊 → 新），不寫入；儲存會先驗證整份回饋資料，失敗就不寫並指出事件與欄位；通過後寫暫存檔、把舊檔備份成 .bak、再用暫存檔替換，所以不會寫到一半壞掉；檔案格式固定，所以差異只會出現在被改的那幾行。匯出的遊戲版本資料唯讀，不能寫回。
驗收：回饋套件新增寫回檢查（沒改動不動檔案、預覽不寫入且只列被改的兩項、備份內容等於原檔、檔案只有兩行不同、暫存檔不殘留、重新載入與寫入的值一致、寫入後記憶體與檔案一致、不合法的值被拒絕且不寫入並指出事件），連同其他回饋與實驗室套件共 429 項、0 失敗。為了讓差異只含被改的行，回饋事件資料檔改成實驗室寫出的標準格式（整數值寫成帶小數點）。依指示沒有跑完整測試套件。
