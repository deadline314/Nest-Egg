# [NE-270] 讓單分子鞭像真的鞭子一樣甩動

> 狀態：封存（由 NE-276 取代）

## 內文

### 需求
單分子鞭揮出去時是一條從身體筆直伸出去、只在原地上下抖的波浪線，看起來很僵硬，不像鞭子。要讓它有真正鞭子的動作：先往後帶、從握把開始把一道波沿著鞭身傳到鞭梢，鞭梢最後甩直、有一下清脆的「啪」（鞭梢最快的那一瞬間），之後鞭身因為慣性往下垂、彎著收回來；不同招式（甩打、回甩）的軌跡看得出不同。命中判定、距離、時間與傷害維持現有招式資料，只改看到的動作與鞭身的樣子。

鞭身的畫法要精緻：有粗細漸變（握把粗、鞭梢細）、分節的高光與一條較亮的芯，顏色沿用這把武器的洋紅；之後 NE-260 換上新的武器圖與發光時能直接套用，不必重寫動作。

### 來源
使用者 2026-10-11（附截圖：主角往右甩出一條洋紅色的直線波浪）：「為什麼這個近戰武器那麼僵硬？我以為是類似鞭子之類的東西，可以給它合適的動畫跟紋理讓它看起來很精緻嗎？」

查到的做法（實際讀到的內容）：
- 繩子與鞭子常用 Verlet 積分的一串節點：每個節點用「這一格與上一格的位置差」當速度往前推、加重力，再反覆數次把相鄰節點拉回固定距離；迭代次數越多越不像彈簧。兩端可以釘在指定位置，只解中間的節點。來源：[Game Developer〈Ropes in Contraption Maker〉](https://www.gamedeveloper.com/design/ropes-in-contraption-maker)。
- 第一格要把節點沿起點到終點直線排好，否則會先垂直再「啪」一下跳到位置（實際踩過的坑）。來源：[itch.io 開發者討論](https://itch.io/post/7667977)。
- 動畫的要點是「波」的傳遞與最後的「啪」：鞭子動畫要做好 wave principle，snap 非常重要。來源：[Dreams 論壇〈How do I animate a whip?〉](https://forums.indreams.me/hc/pt/community/posts/360013989338-How-do-I-animate-a-whip)。
- 分節的鞭身會隨揮動的力道拉開節距（Bloodstained 的 Sword Whip 描述）。來源：[Bloodstained Wiki：Sword Whip](https://bloodstained.fandom.com/wiki/Sword_Whip)。
- 採用：握把跟著手、鞭梢由招式時間帶出一道沿鞭身傳遞的波，鞭身用 Verlet 節點與距離限制跟上（固定節點數、不配置新物件），出招的有效段鞭梢拉直並在最遠點「啪」；收招時保留慣性下垂再收回。不採用：真實的鞭子物理決定命中（命中仍照招式資料，避免手感不穩定）。

### 驗收條件
- [ ] 甩打與回甩各有：後帶、波從握把傳到鞭梢、鞭梢甩直的「啪」、慣性下垂與收回；不再是從身體筆直伸出的抖動線
- [ ] 鞭梢在有效段的位置與實際命中範圍一致（最遠點落在招式距離上），揮空與命中都一樣，不提早或延後
- [ ] 鞭身粗細漸變、分節高光與亮芯；顏色沿用武器資料，亮度不超過既有的軌跡亮度上限，主角白髮不過曝
- [ ] 兩個面向、上中下瞄準、站／跑／跳都不穿過身體、不斷開；換武器、受擊、死亡時鞭子立即收好
- [ ] 每影格不配置新物件，節點數固定；鞭子不在畫面上時不計算
- [ ] 招式的傷害、距離、時間與連段行為和修前完全相同（既有近戰測試全過，不改測試）
- [ ] Forward+ 放慢連拍兩招的修前修後並排；本機原生畫面確認

### 測試流程
1. 拿單分子鞭，站著對空甩打、回甩各一次，放慢看波與「啪」
2. 對著敵人甩，看鞭梢最遠點與命中的位置
3. 上下瞄準、跑、跳各甩一次；甩到一半被打、換武器
4. 跑既有的近戰測試與受影響範圍

# 封存

戰鬥組在雲端分支上做過本票的版本（節點模擬的鞭身，出招開始那一格整條甩直），使用者看過後覺得「突然變直再變軟，非常不合理」，改由 NE-276 重做成「從頭到尾都是同一條軟的繩子」並已進 main。併入 main 時捨棄本票的實作與檢查，不和 NE-276 並存兩套鞭身；需求與驗收由 NE-276 承接。
