# [NE-255] 整理立繪到遊戲的角色製作 Skill

> 狀態：進行中

## 內文

### 需求
主角骨架與立繪（特別是 NE-222）累積了很多經驗，但散在票、交接文件與多份 Skill 裡。要整理成一套完整的 Skill，涵蓋從生成立繪一路到放進 Godot 的全部流程，之後要生成任何新角色或新姿勢都能照同一套做法，不再重新摸索。這套流程必須能解決三類反覆出現的問題：破圖、零件組合後邊緣稜稜角角、立繪上出現奇怪的東西。

### 來源
使用者 2026-10-11：「目前在設計主角的骨架跟立繪的部分，特別是 NE-222，我希望最後可以整理一套 Skill，包含完整的從立繪一路到放進 godot 的流程……務必要解決像是破圖、元件組合起來之後稜稜角角的，或是模型立繪會有一些奇怪的東西」。

### 驗收條件
- [x] Skill 涵蓋完整流程：來源與姿勢規劃、生成、透明與人體檢查、取骨架、分件與補底層、解析度與重組、綁定、全動作檢查、操作手感、原生畫面與效能、交付
- [x] 破圖、組合後稜角、立繪怪東西三類問題各有：成因、怎麼提早發現、怎麼修、不能用的掩蓋做法，並附 NE-222 等票的實際前後例子
- [x] 每一關有明確的通過與退回條件，退回時回到哪一關寫清楚
- [x] 內容以實際做成功的做法為準；試過失敗的做法列為反例，不寫成建議
- [ ] 用這份 Skill 從頭做一個新的角色或新姿勢，全程不需要回頭查舊票，成品通過同一套驗收
- [x] 舊的重複內容整併或改為連結，三處共用 Skill 副本內容一致

### 測試流程
1. 開新對話，只說「幫我做一個新角色放進遊戲」
2. 預期自動讀到這份 Skill，並照流程做到通過驗收

# Commit-1

## 內文

角色從立繪到進遊戲的做法散在很多張票、交接文件與兩份 Skill 裡，每次做新角色都要回頭翻。

現在有一份入口 Skill「從立繪到放進 Godot」：九關照順序走（決定做什麼、畫立繪、產生規格、建置、看底層圖與零件、引擎內近拍、逐格接點稽核、接到遊戲、測試與交付），每一關寫了要看什麼、沒過回到哪一關；最前面是破圖、組合後稜角、立繪怪東西三類問題的總表；最後一節是四足與其他非人形的做法。逐項案例（成因、怎麼提早發現、修法、不能用的掩蓋做法）放在累積筆記裡，Skill 連過去。內容都來自這次實際做過的角色：凜的遊戲內外觀、鷺、阿梨、燈、清掃兵、兩種收帳人與看門狗；試過不行的做法（走姿當來源、手寫規格、太多裝飾的提示詞）寫成反例。

還沒做的：

- 「用這份 Skill 從頭做一個新角色、全程不查舊票」還沒有用新對話實測。
- 三類問題的案例在累積筆記裡有成因與修法，但前後對照圖分散在 NE-222、NE-218 的票上，還沒有整理進同一份。
- 舊的兩份角色 Skill 還有重複的段落沒有整併。

### 測試結果

| 項目 | 結果 |
|---|---|
| 文件檢查 | 兩處 Skill 副本內容相同；Skill 裡提到的工具與檔案路徑都存在 |
| 遊戲測試 | 只有文件，沒有受影響的遊戲測試 |

# Commit-2

## 內文

上一次交付留下三件事：沒有用新對話實測、三類問題的前後圖分散在各票、舊的兩份角色 Skill 有重複段落。

**新讀者實測。** 請一個完全沒有背景的代理人，假設要做一個新的 NPC，照 Skill 一關一關走，逐一對照工具實際的參數與檔案。結果：沒有斷掉的路徑，但缺了十處新手一定會卡住的地方，都補上了——選定種子後要再跑一次才會換掉來源圖、規格工具要跑兩次、匯入的實際指令、眨眼圖要自己跑而且頭一改就要重做、動作檔的測試到底擋什麼（12 個欄位至少 4 個不同）、精修選項的寫法、規格改了之後哪些會自動重算、走路與近拍的預覽參數、裝甲角色要先跑破損步驟、NPC 姿勢資料在哪裡。

**這一輪又學到的也寫進去了**：走路時髖部缺一塊的三個成因與修法、裝甲全掉後頭浮起來、袖窿補色、兩腿同色時遠側腿切不出來、長下襬、接點數字很大時怎麼分辨。每一項都有成因、怎麼提早發現、修法與不能用的做法。

**前後圖集中。** 教訓紀錄最後加了一節，把三類問題的實際前後圖各自列出，並指到對應的說明。

**重複段落整併。** 七個在兩三份 Skill 重複講的主題，細節留在專門的那一份，入口 Skill 只留一行並指過去。兩處副本（`.claude/skills`、`.agents/skills`）逐位元相同；守則裡寫的第三處 `.agent/skills` 在專案裡不存在。

還沒做到的一項，不勾：「用這份 Skill 從頭做一個新角色、全程不查舊票、成品通過同一套驗收」。這次的實測是照著走一遍並核對每一步，沒有真的讓新對話從頭生成並做完一個角色。第二、三章的八個人是我自己照這套流程做的，但我帶著前面的背景，不能算。

### 測試結果

| 項目 | 結果 |
|---|---|
| 新讀者實測 | 路徑與檔案全部存在；補上十處缺漏；一處寫錯的（近拍模式的說明）已更正 |
| 副本一致 | 三份 Skill 的兩處副本逐位元相同 |
| 測試 | 這次只有文件與票，不需要跑 |

分支 `feature/character-art`。Skill：`.claude/skills/portrait-to-godot/SKILL.md`；教訓紀錄：`pm/Nest-Egg/attachments/NE-255-lessons.md`。

# Commit-3

## 內文

**找沒看過專案的人照 Skill 試做。** 一位全新的協作者只拿到 Skill，從頭做了一個新角色（售票員），站、坐、蹲、走都做出來，測試 26,255 項檢查、0 新失敗。他列了 11 處「文件不夠用」，其中最重要的一項是：走路與兩腿分開時髖部前面有一塊方塊，而自動檢查報 0。這就是使用者一直看到的「凸一塊」。

**所以這一條驗收還不能勾。** 成品有凸塊，不算通過同一套驗收。凸塊的成因已在 NE-218 修掉、檢查也補上了，但還沒有再找一位新的人重做一次來確認。

**Skill 補上的內容（11 項中的 10 項）。**
- 重新產生規格之後要從分件重跑到精修
- 自動檢查的例外要怎麼寫、有哪些鍵
- 檢查報 0 不等於沒問題，兩腿分開的近拍還是要放大看
- 零件「正常的樣子」附一張圖
- 頸後小洞怎麼分「真缺口」與「姿勢圍出的空隙」
- 動作資料抄哪一類角色
- 近拍的放大倍率、NPC 八格各是什麼姿勢
- 遠側的手單獨露出來算不算多一隻手
- 只做外觀時哪一關可以先不做
- 背景薄霧的判準、啟動腳本與一行無害訊息的說明
- 沒有補的一項：預覽輸出解析度的參數。改用較大的放大倍率就看得清楚，不需要另一個參數

教訓紀錄新增一節「凸一塊的第三次修正」，兩份 Skill 副本內容一致。

### 測試結果

| 項目 | 結果 |
|---|---|
| 試做 | 新角色做得出來；髖部凸塊一項沒過 |
| 兩份 Skill 副本 | 內容相同 |

Skill：`.claude/skills/portrait-to-godot/SKILL.md`；教訓紀錄：`pm/Nest-Egg/attachments/NE-255-lessons.md`。
