# [NE-197] 音訊建置只重做有更動的檔案

> 狀態：完成

## 內文

### 需求
套用音效到遊戲時，建置工具會把所有音效檔整批重新編碼，每次都有一兩百個沒改的 .ogg 在版本控制裡出現差異，要手動挑出真正更動的檔案還原，既慢又容易出錯，也讓提交內容難以檢查。要讓建置只重做有更動的項目，沒改的檔案位元組完全不變。

### 來源
2026-10-05，NE-189、NE-190 套用音效時發現每次都要手動還原不相關的檔案。

### 驗收條件
- [x] 只改某個位置的來源後套用，版本控制裡只有該位置的音效檔有差異
- [x] 沒有更動的輸出檔不會被重新編碼；來源、加工參數或工具版本改了才重做
- [x] 全部重建仍可用旗標強制執行
- [x] 套用工具與音訊測試通過

### 測試流程
1. 在實驗室套用一個位置，檢查版本控制的差異只含這個位置的檔案
2. 再套用一次相同內容，沒有任何檔案差異

# Commit-1

## 內文

套用音效時，建置工具每次把所有音效與曲目整批重新編碼，沒更動的 .ogg 也會在版本控制裡出現差異，得手動挑出來還原。
現在建置會記下每個輸出檔的來源內容、加工參數與工具版本，沒變的就略過、檔案位元組完全不動；只改一個位置時，版本控制只看到那個位置的檔案。需要全部重做時加 `--force`；`--only` 後面忘了給 id 會直接報錯，不再默默變成全部重做。快取檔 `build_cache.json` 要一起提交；換電腦或編碼器版本造成只差編碼雜訊時，加 `--adopt` 直接採用現有檔。
驗收：改一個變體的長度上限只重做 1 個、版本控制只多那一個 .ogg；馬上再建置一次重做 0 個、沒有檔案差異；還原設定後再建置一次，位元組回到原狀。套用工具 12 項、增量快取 11 項 Python 測試通過。遊戲內的音訊輸出檔沒有更動，所以不需要重跑遊戲測試，也沒有畫面變化，不附截圖。
備註：初次建立快取時，有 34 個既有輸出檔與重新建置的結果只差編碼雜訊（解碼後長度相同、最大取樣差約 0.03 以內），用 `--adopt` 採用，沒有改動音檔。

### 測試結果

| 項目 | 結果 |
|---|---|
| 增量快取的 Python 測試 | 11 項通過 |
| 套用工具的 Python 測試 | 12 項通過 |
| 套用一次後再套用一次 | 重做 0 個、無檔案差異 |
