# NE-218 打手腰部、頸部與落腳修正

此交付修正收帳人打手在彎腿時重複帶動腰帶與鑰匙、頸部接合，以及蹲入與起身時靴底穿過地面的問題。正式數值、碰撞、敵人招式與其他角色的外觀沒有改動。角色可選的腳部姿勢設定以空值保留既有行為，既有動作仍可指定自己的足部角度。

驗證基準為 `d7417bc8e28fae2637ef5db5456957bad8689bd7`，Godot 4.7.2、Windows、Forward+、HDR 2D、RX 9070 XT；原生驗證使用隔離設定目錄與 Dummy 音訊。這是本票的打手修正與回歸證據，整票其餘角色的完整驗收依票上未勾條件維持實際狀態。

## 重讀

Python 3.10+、僅標準函式庫。從任意目錄執行：

```text
python ne218_packet_reader.py <此附件資料夾> [遊戲工作目錄]
python reader_controls.py <全新的控制輸出資料夾>
```

第一個命令逐檔串流驗證 ZIP，不解壓所有圖片到記憶體或磁碟，並從原始 JSON／log 重算動作、接點與效能結果。給工作目錄時會再核對正式交付來源。第二個命令保留測試產物，輸出資料夾必須尚未存在。

`delivery-source.json` 記錄測試時與正式 LF 版本的 SHA；圖片逐位元相同，文字僅明確轉換 CRLF → LF。`canonical-source/` 是本次 28 份正式來源；ZIP 內 `tested-source/` 保留原測試 bytes。

ZIP 包含 C11 全部原始接點 PNG、遮罩、遊戲畫面、對照測試及先前失敗嘗試的原始文字紀錄。大量歷史診斷像素留在本機 D 槽，逐檔 SHA 見 `local-history-inventory.json`；不把它們當成本次可攜重算的輸入。執行設定目錄、產生式匯入快取及其他未交付角色工作均排除。

## 判讀限制

- 接點 checker 的自然退出碼仍為 1，362／40 是實際失敗數；人工逐類審查沒有把它們改成「工具零失敗」。詳見 [RootReview.md](RootReview.md)。
- 有其他專案的 Godot 工作並行，原生計時保留各輪工作負載。數字是中性光照場地的完整影格比較，不是 GPU-only、十個戰鬥 AI 或機器獨占測量。
- 原生效能 V1～V4 的錯誤取景／座標／過暗畫面均被拒收；採用實際看過十人可見的 V5。關閉故事自動播放未能解決 V4 過暗，最終用既有中性光照場地，兩版一致。
- 原測試與原生程式的 EOF 釋放警告原樣保留，不宣稱所有 log 沒有 ERROR。四死亡姿勢並排圖的外側頭部有裁切，沒有拿它宣稱四種死亡全身都完成驗收。
