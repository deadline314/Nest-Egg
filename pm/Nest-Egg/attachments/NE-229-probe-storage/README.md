# NE-229：手把探針持有自己的存檔與設定

2026-10-30，基準 7b8263336d0e7f7af7b0dcdaf32978a3a84757fc。Godot 4.7.2.stable.official.ed1daf0bf。合成 device 999、Forward+／llvmpipe、1280×720；不代稱真人或實體手把驗收。

## 原問題與修復

ST-9 未提交的整合回歸有兩項失敗：新遊戲初始焦點及難度確認。原始 67 組共 91,886 項、2 新失敗、551 秒；發現記錄與當時 ST-9 差異保留在 st9-discovery。暫存 ST-9 修改，在原版建立一份有效的普通存檔後，獨立重現同兩項：6 項、2 失敗。正常選單有繼續按鈕並保護覆寫，探針卻假設沒有存檔，並非產品的選單故障。

每次 ControllerFlowProbe 現在以原子建立的唯一目錄持有設定及 run/slot.json，Main 加入樹前就指定槽，其他累積版本搜尋也只看該私有根。還原設定、釋放 Main 後才刪自己建立的兩層目錄；不遞迴追隨意外巢狀內容，不刪外部檔案。

## 驗證與畫面

- 最終 `final-tap`：原始手把路由加既有普通存檔保留檢查，40 項、0 失敗，7 來源雜湊一致。fixture 只允許 runner 的專屬 user data，拒絕直接對普通使用者路徑建立樣本。
- 最終 `affected-tap-final`：原選取 InputFeelSuite，132 項、0 新／已知失敗、27 秒；既有斷言、長按秒數、設定取消門檻均未放寬。
- 最終 `native-tap-after`：41 項、0 失敗；包含一項原生圖片保存，普通存檔逐 bytes 不變，無 ERROR／SCRIPT ERROR／結束洩漏診斷。
- `native-before`：使用原版流程腳本（僅去掉全域 class_name 以便同專案獨立載入），7 項、2 原失敗。圖片擷取在探針以方向鍵移到開始任務之後，因此圖上焦點是開始任務；有繼續按鈕才是外部存檔影響入口的直接對照，不冒稱捕捉到初始焦點瞬間。

## 保留的原生時序失敗

`native-after` 最初還有長 B 失敗：探針在事件尚可能緩衝時就啟動 0.7 秒計時。改為先明確送達事件，`native-flushed-after` 的長 B 通過，卻抓到短 B 失敗：三個按住影格在慢速軟體渲染可超過 0.6 秒，會正確被產品視為取消。

最終短按先送達按下／放開，再等待原本六個 settling frames；長按先送達按下，再測原 0.7 秒。產品 0.6 秒門檻與原判斷完全保留。這是測試事件語義修正，沒有為通過回歸提高取消秒數、增加已知失敗或修改正式 UI。原始日誌與 leaf 完整保留，不宣稱已證實其他歷史硬體失敗的原因。

`public-final`／`affected-final` 是僅存檔隔離的迭代；`final-dispatch`／`affected-dispatch-final` 是只補長按送達的迭代；最終交付以 final-tap／affected-tap-final／native-tap-after 為準。圖片為真實原生未修圖擷取。
