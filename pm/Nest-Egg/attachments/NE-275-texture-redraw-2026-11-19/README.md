# 持有武器的貼圖重繪候選比較

前後使用同一份關卡、武器、骨架、輸入與顯示設定。應用程式正式程式碼只移動一個重繪呼叫。基底的 `CanvasItem.draw` 訊號由測試場景直接監聽，期間分別取待機 60 個、按下正式近戰鍵到收招 75 個物理影格。五把武器及切回長刀朝左的六組都從 60、75 次降到 0、0 次。缺圖線段維持 60、75 次，七組 147 筆位置與姿態相同，待機與攻擊共 14 對原生 PNG 校驗一致。貼圖採用與替換各自啟動引擎既有繪製。

RX 9070 XT／Vulkan Forward+，1280×720，高光影，解除垂直同步與畫面上限。成對計時先排除一輪預熱，接著六組交替，兩個版本各取每把武器每次 600 個實際待機畫面。各次取中位數，最後列出配對百分比的中位數、最小、最大。

五把武器的配對中位數都增加，個別跑次也出現反向變化。同一組內多把武器往相同方向變動，整幀包含場景的其他負載。依目前結果，這次只提交量測與停用候選的決定，整體效能條件仍待完成。
