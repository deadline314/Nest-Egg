# NE-241：普通格擋測試等待真窗口

原受影響回歸 72 組、93,793 項、1 新失敗、697 秒，失敗是「普通格擋消耗防禦值」。完整原輸出見 `affected-release`，不是忽略或新增已知失敗。

## 重現與修正

原測試用固定 15 個物理訊號代表完美格擋已結束。頭部局部頓幀會停掉玩家與彈體容器的處理，但樹的物理訊號仍走；低幀率補物理步會使這個前提失效。明示 5 FPS 的獨立重播，在第二發前真正防禦計時 0.10 秒、窗口 0.16 秒；第二發仍反彈，防禦值仍 100，因此原斷言正確失敗。其他 0／10／20 FPS 原流程通過，不宣稱所有低幀率都會觸發。

普通格擋先在最多 120 個訊號內等到真正窗口結束且玩家／彈體容器解凍，新增前置條件斷言。破防也先等該發子彈真正結算，再讀原硬直斷言。原戰鬥規則、所有舊斷言、選擇器、過濾器與已知失敗清單維持。

- 最後四程序 0／5／10／20 FPS 各 11 項，共 44 項、0 失敗；計時大於 0.16 秒，真正普通格擋後防禦值從 100 到 76。
- 第一輪只修窗口的 `after-5.log` 仍有破防等待失敗，保留原始輸出；最後 `final-*` 兩種等待都修正。`missing-fixture` 是重播副本尚未產生造成的工具錯誤，非產品失敗，原樣保留。
- Forward+／Vulkan llvmpipe 1280×720、5 FPS：原版 10 項 1 失敗（破防讀得太早），修後 11 項 0 失敗。原版射前窗口仍開著但碰撞較晚，第二發最終是普通格擋；不把它冒稱相同的反彈失敗。兩張原圖逐張檢視，圖片保留原先反彈子彈及通訊，不當作孤立的護盾外觀驗收。
- 原選擇器因測試入口變更要求全部：88 組、98,315 項、0 新／已知失敗、650 秒。此工作區同時驗到第一章機關保存變更；其正式來源與交付另屬 ST-9，不混成這一筆提交的遊戲功能。
