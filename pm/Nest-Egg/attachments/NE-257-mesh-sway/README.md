# 網格區域擺動與法線回歸

這次交付讓已設定的衣襬區域真正接到網格，並修正共用角色著色器的法線。不是主角胸口、袖口和全部動態驗收的結案。

## 對照與範圍

- 10種外觀、14個已設定區域，原本9個網格區域沒接上。Sprite保留24像素擴邊；多頂點網格使用0擴邊，不改既有拓樸。所有區域的實際綁定與移動輸入自動檢查5427項通過。
- 20張兩面向 MIN／ZERO／MAX 圖固定模擬1秒後停住。診斷控制套用同一修正法線、保留原Sprite-only綁定，**不是未修改main**。ZERO欄19/20完全相同，芷姐朝左僅1像素差1階；完整逐像素結果在raw。極值靜態圖只證明區域綁定、取樣和對照，不能取代自然起停或人體穿插驗收。
- `NORMAL_MAP`只在條件分支指定會改變整個shader的編譯輸出，未綁區域也受影響。依實際Godot4.7.2 canvas.glsl，先以原UV法線初始化，變形區域再取warped UV。舊控制暴露的亮度偏差與失敗圖完整保留。

## 測試與失敗原文

原選擇器以固定base223f936a選84組，凍結26個輸入，93673檢查、0腳本錯誤；首輪有1項爆炸效能失敗（+21.76ms，原門檻6ms）。第一次獨立重測仍+8.76ms而失敗，不能將首輪當綠色。之後對已合入的NE-154 main與本候選做相同隔離效能對照，原門檻不動，main為44檢查0失敗、增量0.33ms；候選同為44檢查0失敗、增量1.85ms。隔離對照保留，不能以這次通過抹除前兩次失敗或宣稱所有機器保證6ms。

26輸入的遊戲程式包含BG-46與NE-154，後兩票以各自提交交付。NE-154最終僅測試計時校正較凍結Feel測試更新，遊戲Sfx逐byte相同；rebase到10821後重跑FeelSuite（784檢查無失敗；同輪FX仍失敗，該輪828總檢查不能寫成全綠）。完整錯誤清單在raw：包含刻意壞資料的安全退回，另有body space為null與退出時資源／物理RID釋放訊息；不聲稱所有測試輸出零ERROR。原資料、負控制、舊法線回歸失敗、失敗效能、raw退出碼都保留。

## 來源與重跑

先讀User-guide並實際看過[五款同類遊戲參考圖](../../../../design/08-lighting/READABILITY_REFERENCES.md)：只借輪廓、局部光源與少量衣物延遲的比較，不推定其shader實作或玩家偏好。技術原理另看[Spine網格](https://en.esotericsoftware.com/spine-meshes)與[Godot4.7.2引擎shader原始碼](https://github.com/godotengine/godot/blob/4.7.2-stable/servers/rendering/renderer_rd/shaders/canvas.glsl)；來源HTTP失敗亦記在sources.json。

CI及本輪使用官方4.7.2，ZIP SHA在provenance.json，workflow先驗SHA再解壓。保留舊4.7 renderer錯誤，沒有以換版本假稱根因已證實，沒有在遊戲新增同步／等待或移除燈影。

解壓[raw.zip](raw.zip)；[逐檔manifest](manifest.json)、[候選來源](source.json)、[數值摘要](validation-summary.json)、[CPU原始數字](script-performance.json)。`GODOT=<官方4.7.2> SHARDS=4 tools/run_tests_changed.sh 223f936a`；靜態圖 `res://tools/rig_preview.tscn -- --chars=lin --sway-extremes --bright --zoom=3.4 --out=<png>`，加`--left`取另一面；perf `--headless res://tools/rig_perf_probe.tscn -- --skin=lin --count=10 --frames=600`。GPU工作用專案gpu_lock，整個Xvfb生命週期另有工作區互斥，不變更遊戲時序。
