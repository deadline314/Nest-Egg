# [NE-201] 統一開發規範與逐票交付流程

> 狀態：完成

## 內文

### 需求
不同開發工具都能讀取相同的專案規範與技能。每完成一張票，使用指定作者獨立提交並立即推送至最新 main，提交訊息不含工具或模型署名，推送後清理已合併的工作分支。

### 來源
2026-10-06，使用者要求把既有專案規範與技能複製到預設可讀取的位置，並要求逐票 commit、push、同步 main、指定作者 email 與清理舊分支。

### 驗收條件
- [x] 原本的專案規範與三份技能完整保留
- [x] 新的專案入口包含同等開發規範及三份技能索引
- [x] 共用規範一致記錄逐票提交、推送前同步與 rebase、指定作者及提交訊息限制
- [x] 舊分支只在確認合併後移除，保留未合併工作

### 測試流程
1. 比較兩組專案規範與三份技能內容，確認只有入口、引用位置及索引的預期差異。
2. 檢查 Git 流程包含逐票 commit 與 push、最新 main、指定作者與提交訊息限制。
3. 檢查文件格式與技能連結皆有效。
