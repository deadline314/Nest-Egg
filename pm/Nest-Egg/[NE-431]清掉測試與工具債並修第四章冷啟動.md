# [NE-431] 清掉測試與工具債並修第四章冷啟動

> 狀態：進行中

## 內文

### 需求
前一個玩法 session 與這幾天的多線作業留下一批測試與工具上的問題，其中一項可能是玩家會遇到的存檔問題。每一項都要有結論（修好、或查明不是問題並說明理由）：

1. 第四章的流程探針在「原帳」那一步失敗：從 Atropos 競技場的存檔冷啟動繼續時沒有回到安全臺。查出從什麼時候開始壞、根因是什麼，確認玩家實際會不會遇到（在競技場存檔、關掉遊戲、重開繼續，人出現在哪裡）；會遇到就修並補回歸。
2. 列出不在測試挑選規則與 CI 裡的流程探針，該進的放進去。
3. 測試挑選工具挑得準：改共用的敵人、玩家、關卡基礎程式不能漏挑（例如改 grunt.gd 只挑出 10 個、實際要 43 個），改一個道具或一個資料欄位也不能展開成幾乎全部。
4. 跑測試的腳本與探針不把整份輸出接進 grep、不把整個 log 讀進記憶體（輸出寫檔、每個套件的 log 有大小上限、結束時只印摘要），也不留下殘留的 Godot 或 grep 程序。這一項和 2026-11-28 一支 grep 吃掉 14.5 GB 記憶體的事故直接相關。
5. 攻擊權杖「同時預兆最多兩個」在高負載下出現過 3 個：查是不是真的競態。
6. run_controller_storage 探針在 Windows 上一定失敗：修成 Windows 與 Linux 都過。
7. bubble_source 探針多支同時跑時偶爾多一行「ObjectDB instance leaked」而判失敗：查是真的洩漏還是結束順序。
8. 章節文件數寫死在測試裡（第一章地圖測試的 5 份、收集品測試的 ch1_kasa 與 chapter_01、chapter_02）：改成讀各章的收集品資料。
9. 換區域途中死亡時跳出「進度尚未保存／重試保存／留在目前區域」：判斷這時候該不該問；可以安全地留在目前區域走正常死亡流程就不要問。

### 來源
2026-11-28，主 session 轉達前一個玩法 session 留下的已知問題、地圖線發現的第四章探針失敗、演出線遇到的死亡存檔提示，以及使用者因記憶體與硬碟被吃滿而定下的測試規則。

### 驗收條件
- [ ] 第四章冷啟動：寫明開始壞的 commit 與根因；玩家實際情境的結果；會遇到就修好並有回歸測試，第四章流程探針通過
- [ ] 不在挑選規則與 CI 裡的流程探針有一張清單，需要的已經加進挑選規則與 CI
- [ ] 挑選工具：改 game/props、game/enemies/enemy.gd、data/levels、ui 各一個檔時，修改前後各挑出幾個套件、有沒有漏掉該跑的，寫在票上；不漏挑也不過度展開
- [ ] 跑測試的腳本與探針的輸出都寫檔、log 有上限、結束只印摘要；跑完沒有殘留程序（有自動檢查或可重跑的驗證步驟）
- [ ] 攻擊權杖、controller_storage、bubble_source 三項各有結論，需要修的已修並有測試
- [ ] 文件數改成讀資料，故事線加一份文件不需要改測試
- [ ] 換區域途中死亡的存檔提示有結論；不該問的情況不再跳出，死亡流程照常
- [ ] 受影響範圍的測試全過

### 測試流程
1. 跑第四章流程探針，預期「冷啟動回到安全臺」通過
2. 在 Atropos 競技場存檔、關遊戲、重開繼續，預期出現在安全臺
3. 用挑選工具對票上列的幾個檔各挑一次，比對結果
4. 跑一輪受影響範圍的測試，結束後確認沒有殘留的 Godot 或 grep 程序
