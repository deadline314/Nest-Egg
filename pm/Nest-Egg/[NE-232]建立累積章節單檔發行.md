# [NE-232] 建立累積章節單檔發行

> 狀態：進行中

## 內文

### 需求
建立每完成一章即可保留「序章至該章」獨立Windows單檔版本的發行流程，讓玩家不需編輯器與專案即可體驗。

### 來源
2026-10-10，使用者要求逐章完成與累積發行、高清像素UI、全流程手把、豐富合理敘事與動畫、場景減雜，並追加武器差異、子彈、方向護盾、可選連段升級與打擊感總驗收；一般設計選擇由實作者決定，持續推進。

詳見[整體設計](../../design/20-campaign-experience/DESIGN.md)與[研究依據](../../design/20-campaign-experience/RESEARCH.md)。

### 驗收條件
- [x] 可選擇已完成的末章建立累積單檔，各自保存且不覆蓋舊版；第一、二、三章的實際正式包分別由NE-233／NE-234／NE-235驗收。
- [x] 版本所列章節與實際可玩內容一致，最後一章有收尾，不進入未完成章節。
- [ ] 乾淨目錄無編輯器／專案檔仍可啟動；正式必要資源完整，測試、來源大圖、字幕參考與票据圖片不入包。
- [x] 各包記錄版本、基準提交、可玩範圍、體積、校驗碼與驗收結果，單檔大小符合匯出限制。
- [ ] 存檔跨版可接續或有明确相容提示，正式鍵鼠／手把流程可用。
- [x] Linux建置與產物檢查、Windows實際單檔啟動分開記錄；實際各章發行由对应驗收票交付。

### 測試流程
1. 用已完成章節建立對應累積包，放在乾淨目錄啟動並操作。
2. 核對資源、版本、章末、存檔、體積與校驗碼，保留各包紀錄。

# Commit-6（三份累積候選包與乾淨目錄啟動，進行中）

## 內文

原本工具只能做來源稽核與小型探針，正式匯出一律拒絕，而且拒絕理由裡有一條永遠不會消失的「產出端未交接」，就算章節都驗收了也建不出包；遊戲端也無法說明「這個執行檔到底收錄了哪幾章」，乾淨目錄啟動只能證明程式開得起來。

現在可以選末章建出「序章至該章」的 Windows `.exe` 與 Linux 單檔。正式包只在收錄的每一章都驗收完成、版本契約正確、資源閉包零缺漏時放行；章節還沒驗收時，可以建明標「候選」的包給本機原生驗收用：版本號必須以 `-candidate` 結尾，主選單右下角會顯示這個版本號與收錄範圍，清單標明不是發行版並列出所有未驗收原因。每次輸出都放在含版本、末章與來源提交的新目錄，同一份來源已經匯出過就拒絕，舊版永遠不被覆蓋。包內每一項都必須是驗證過的來源或引擎對它的轉換，開發目錄、測試、票據與文件類檔案一律拒絕。

Linux 單檔會被放進只有它自己的空資料夾啟動，由遊戲自己讀包內資料回報收錄的章節、各章區域數、章末區域與版本號，工具逐項核對。用 main 上的同一個提交建了三份候選包：序章至第一章停在天亮的當舖、序章至第二章停在第二章屋頂、序章至第三章是最後一章停在完成卡；每份都只收錄自己範圍的區域。三份 Linux 單檔另以 Forward+（軟體 Vulkan）在乾淨資料夾開到主選單，版本號與收錄範圍顯示正確。

# 本機原生驗收（2026-10-12，Arc B580）

## 內文

在這台機器（Windows 11、Intel Arc B580、Godot 4.7.2）用 main 的 `feb9645d` 照[累積章節發行](../../design/20-campaign-experience/RELEASE_PIPELINE.md)的步驟試建「序章至第一章」的候選包。**沒有建出 `.exe`，Windows 原生驗收的 9 個步驟一步都還沒做**；下面是卡住的地方。這一段沒有改本票的工具，也沒有下載任何東西。

| 步驟 | 結果 |
|---|---|
| 準備來源（輸出放在很長的暫存路徑） | 失敗：複製到一半回報「找不到檔案」。實際原因是路徑超過 Windows 的 260 字元上限（這台機器沒有開長路徑支援），訊息沒有提到路徑長度 |
| 準備來源（輸出改放 `C:/Github/Nest-Egg-ne232` 這種短路徑） | 成功：8222 個檔案、約 210 MB，資源閉包 0 缺漏；工具列出序章與第一章還沒驗收的原因（章節是草稿、驗收票未完成、沒有提交的驗收證據等） |
| 匯入來源 | 失敗：模板資料夾缺 `provenance.json`（官方模板包的來源與雜湊紀錄） |
| 匯出候選包 | 沒有執行到：工具要求先完成匯入 |

這台機器的 4.7.2 模板資料夾只有 Windows 的四個模板與 `version.txt`，沒有來源紀錄，也沒有 Linux 模板（工具兩個平台的模板都要核對）。要繼續需要把官方 4.7.2 模板包（約 1.28 GB）照工具要求的方式放好；下載要使用者同意，這次沒有做。

發現（請本票負責的組處理）：
1. 準備來源時遇到路徑太長，只回報「找不到檔案」。建議開始複製前先算最長路徑，超過就直接說明並建議換短的輸出位置。
2. Windows 原生驗收步驟的說明可以補一句「輸出位置要夠短」，以及這台機器的模板要怎麼準備。
