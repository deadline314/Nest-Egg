# [NE-232] 建立累積章節單檔發行

> 狀態：進行中

## 內文

### 需求
建立每完成一章即可保留「序章至該章」獨立Windows單檔版本的發行流程，讓玩家不需編輯器與專案即可體驗。

### 來源
2026-10-10，使用者要求逐章完成與累積發行、高清像素UI、全流程手把、豐富合理敘事與動畫、場景減雜，並追加武器差異、子彈、方向護盾、可選連段升級與打擊感總驗收；一般設計選擇由實作者決定，持續推進。

詳見[整體設計](../../design/20-campaign-experience/DESIGN.md)與[研究依據](../../design/20-campaign-experience/RESEARCH.md)。

### 驗收條件
- [ ] 可選擇已完成的末章建立累積單檔，各自保存且不覆蓋舊版；第一、二、三章的實際正式包分別由NE-233／NE-234／NE-235驗收。
- [ ] 版本所列章節與實際可玩內容一致，最後一章有收尾，不進入未完成章節。
- [ ] 乾淨目錄無編輯器／專案檔仍可啟動；正式必要資源完整，測試、來源大圖、字幕參考與票据圖片不入包。
- [ ] 各包記錄版本、基準提交、可玩範圍、體積、校驗碼與驗收結果，單檔大小符合匯出限制。
- [ ] 存檔跨版可接續或有明确相容提示，正式鍵鼠／手把流程可用。
- [ ] Linux建置與產物檢查、Windows實際單檔啟動分開記錄；實際各章發行由对应驗收票交付。

### 測試流程
1. 用已完成章節建立對應累積包，放在乾淨目錄啟動並操作。
2. 核對資源、版本、章末、存檔、體積與校驗碼，保留各包紀錄。

# Commit-1

## 內文

原本沒有累積章節的來源清單與交付門檻。現在可以核對全部已載入故事、固定資源引用、動態路徑及章節驗收證據，並記錄來源提交、檔案大小與校驗碼。未驗收的章節保持草稿，不把稽核報告當作可玩包；報告已有同名檔時保留原件。

來源檢查確認目前載入五份故事、共93個場景，全部正式任務數為0。序章與第一章仍未滿足完整發行門檻，因此正式匯出就緒為false。資料校驗逐檔讀取，不把圖片解碼後常駐記憶體。

### 測試結果

| 項目 | 結果 |
|---|---|
| 工具局部測試 | 12項通過，涵蓋路徑越界、固定引用漏檔、多故事來源、草稿及缺驗收證據、損毀規格與保留既有報告 |
| 符號連結拒絕 | 以模擬的連結分支驗證；未宣稱本機建立真連結的驗收 |
| 來源稽核 | 基準589db650；6,951檔、187,043,301 bytes，逐檔校驗。四項開發輔助字面引用與九個動態路徑另列，未宣稱執行期可達性已驗 |
| 遊戲受影響範圍 | 選測工具確認沒有受影響的遊戲測試；沒有修改遊戲程式或渲染 |
| 正式匯出與乾淨目錄啟動 | 本階段是來源稽核，沒有匯出產物或啟動驗收 |

詳細邊界及引用稽核的限制見[累積章節發行](../../design/20-campaign-experience/RELEASE_PIPELINE.md)。

# Commit-2

## 內文

原本只有來源稽核，無法證明隔離來源經官方引擎匯入後仍完整，也無法辨識單檔匯出內的資料損毀。現在從指定提交建立獨立來源，保留仍會載入的全部故事與動態資料，逐檔校驗匯入前後內容；版本、累積末章、來源提交、排除原因和匯入生成內容都有完整紀錄，新輸出不覆蓋舊版。正式章節缺少驗收與公開接線時拒絕匯出並留下原因。

來源基準eadc5f8f共有6,957個輸入、189,678,150 bytes，隔離匯入與完整性檢查通過。五份故事共93場景、正式任務仍為0；草稿與候選內容沒有被列為通關完成。

另以明標工具樣本實際產生Linux單檔及Windows EXE，核對內嵌資料全部校驗碼，Linux在只有執行檔的乾淨目錄成功載入JSON與動態後章樣本。此樣本沒有章節驗收效力；Windows僅記錄跨平台匯出及完整性結果。正式產品就緒仍為false。

### 測試結果

| 項目 | 結果 |
|---|---|
| 工具局部測試 | 49/49通過；保留原12項，新增37項有效測試 |
| 隔離來源與匯入 | 6,957檔原始內容未變；5,702個生成檔另封存；引擎exit0、無ERROR |
| 資源邊界 | 0閉包缺漏，8個格式化動態路徑有覆蓋；32個開發及無執行期相依檔排除 |
| 正式產品門檻 | export exit1，保留阻擋理由，未產正式包 |
| 真單檔工具探針 | Linux 73,522,720 bytes、Windows 109,271,792 bytes；兩檔完整性通過 |
| 原生啟動 | Linux真程序exit0；Windows原生啟動未驗，不計為正式章節驗收 |
| 失敗辨識 | 首次探針引擎exit0但log有ERROR，工具拒絕成功；原始錯誤保留 |
| 影響選測與畫面 | 明確baseline核對無受影響遊戲套件；沒有遊戲畫面變更，使用log與manifest證據 |
