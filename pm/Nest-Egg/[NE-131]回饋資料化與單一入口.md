# [NE-131] 回饋資料化與單一入口

> 狀態：完成

## 內文

### 需求
目前打擊的停頓、震動、後座與縮放散落在約 19 個檔案、53 處呼叫，數值寫死，而且震動的持續時間根本沒有生效，小強度的震動實際不到 1 像素。要把回饋定義成資料事件（一串頓幀、震動、後座、縮放、閃光、粒子、光、聲音、壓低其他聲音），全部經過單一入口播放，並把現有呼叫遷移過去，行為維持不變。

### 來源
2026-10-04，使用者要求處理打擊感；研究與設計見 `design/15-game-feel/RESEARCH.md`（第 0 節、第 3 節），母票 NE-130。

### 驗收條件
- [x] 現有所有回饋呼叫改走事件資料，遷移前後的數值有逐項對照表（design/15-game-feel/MIGRATION-NE-131.md），行為不變（震動依第二項刻意變明顯）
- [x] 震動改為「峰值像素＋時間」，持續時間真的生效，小強度震動肉眼可見
- [x] 事件資料缺漏或損毀時記錄「檔案、事件、欄位」並退回安全預設，不崩潰
- [x] 事件資料有驗證，引用不存在的事件或音效時測試失敗
- [x] 各系統（頓幀、鏡頭、粒子、聲音）提供計數器註冊的介面，供實驗室診斷使用

### 測試流程
1. 比對遷移前後同一情境的震動與停頓數值
2. 刻意寫壞一筆事件資料，確認有具體錯誤訊息並退回預設
3. 執行相關測試套件

# Commit-1

## 內文

打擊的停頓與鏡頭震動散在十九個檔案、寫死數值，而且震動的持續時間根本沒有作用，小強度震動實際不到 1 像素、肉眼看不見。
現在所有頓幀與震動都從單一入口播放，數值集中在一份事件資料（每個事件可含鏡頭震動、全域頓幀、只凍結攻擊方與被打方的局部頓幀）；原有的二十幾處呼叫已全部改成播放事件，武器與特效資料決定強度的震動走同一個入口。鏡頭震動改成「峰值像素＋時間」，持續時間真的生效，強度隨時間平方衰減，多個震動可疊加並有上限，小強度震動現在看得見。事件資料缺漏、損毀或引用不存在的事件時記錄「檔案、事件、欄位」並略過，不崩潰；各系統可註冊自己的即時計數，供之後的實驗室讀取。
驗收：新的回饋套件檢查事件資料沒有錯誤、遊戲程式引用的事件都存在、沒有任何程式繞過入口直接呼叫頓幀與震動、小震動立即可見且依持續時間結束、壞資料與不存在的事件不崩潰、計數可讀。連同受擊、站姿、道具、敵人、頭目、死亡反應等套件通過，依指示沒有跑完整測試套件。道具套件原本因電話亭改版而失效的存檔測試一併修正為按互動鍵撥號。
