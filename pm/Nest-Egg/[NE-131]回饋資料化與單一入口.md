# [NE-131] 回饋資料化與單一入口

> 狀態：待辦

## 內文

### 需求
目前打擊的停頓、震動、後座與縮放散落在約 19 個檔案、53 處呼叫，數值寫死，而且震動的持續時間根本沒有生效，小強度的震動實際不到 1 像素。要把回饋定義成資料事件（一串頓幀、震動、後座、縮放、閃光、粒子、光、聲音、壓低其他聲音），全部經過單一入口播放，並把現有呼叫遷移過去，行為維持不變。

### 來源
2026-10-04，使用者要求處理打擊感；研究與設計見 `design/15-game-feel/RESEARCH.md`（第 0 節、第 3 節），母票 NE-130。

### 驗收條件
- [ ] 現有所有回饋呼叫改走事件資料，遷移前後的數值有逐項對照表，行為不變
- [ ] 震動改為「峰值像素＋時間」，持續時間真的生效，小強度震動肉眼可見
- [ ] 事件資料缺漏或損毀時記錄「檔案、事件、欄位」並退回安全預設，不崩潰
- [ ] 事件資料有驗證，引用不存在的事件或音效時測試失敗
- [ ] 各系統（頓幀、鏡頭、粒子、聲音）提供計數器註冊的介面，供實驗室診斷使用

### 測試流程
1. 比對遷移前後同一情境的震動與停頓數值
2. 刻意寫壞一筆事件資料，確認有具體錯誤訊息並退回預設
3. 執行相關測試套件
