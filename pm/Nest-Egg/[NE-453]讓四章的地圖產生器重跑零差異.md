# [NE-453] 讓四章的地圖產生器重跑零差異

> 狀態：完成

## 內文

### 需求
地圖由各章的產生器輸出，但其他線常直接改地圖 JSON（放人物、告示、機關），改完沒有寫回產生器；之後誰一重跑，這些東西就被洗掉。故事線回報第三章重跑時玻璃邊緣、夾層通道、樣品房仍有差異，也剛在第三章的廣場、泵室與兩個秘密空間、第一章麵攤的鐵皮棚放了東西。這張票把這些都寫回產生器，讓第一到四章的產生器重跑後地圖沒有內容差異，並加一支檢查：不改動工作樹地重跑四章產生器、逐檔比對，有人直接改了地圖沒寫回時指出是哪一區、哪一個檔。

順手處理兩件：第四章接線廊的劇情意圖是「下層一組看守、上層一組，玩家可以選正面通過或換層」，測試只數敵人數量，沒有確認兩組真的分在兩層、而且有換層的路；第二章北棟前室秘密空間的描述替劇情先命名了，改成只描述空間本身。

### 來源
2026-11-28，主 session 轉述故事線與使用者的要求（產生器由地圖線負責；之後任何一條線直接改 JSON 沒回報要能被抓到）。見[畫面與玩法的後續待辦](../../design/22-living-scenes/BACKLOG.md)的工具債。

### 驗收條件
- [x] 第一到四章的產生器重跑後，地圖、關卡、人物、主題與遭遇資料都沒有內容差異（只容許資源編號、鍵順序、換行這類不影響遊戲的差異）
- [x] 有一支檢查不改動工作樹就能重跑四章產生器並逐檔比對；有差異時指出區域與檔名，沒有差異時回報通過
- [x] 故事線在第三章廣場、泵室、診所備品間、辦公接待廊維修廊，第一章麵攤鐵皮棚、第四章（ST-63）放的東西，玩法線在第三章辦公接待廊示範的門閂門，都在產生器裡
- [x] 第四章接線廊的測試檢查地面與走道各有一組敵人、兩層之間有換層的路
- [x] 第四章舊廠清掃路線的文件寫的是目前的敵人配置
- [x] 第二章北棟前室秘密空間的描述只寫空間本身
- [x] 受影響範圍的測試 0 個新失敗

### 測試流程
1. 跑產生器重跑檢查，預期四章都通過
2. 故意在一張地圖上改一格，再跑一次，預期指出那一區那一個檔
3. 跑第四章故事測試

# Commit-1

## 內文

其他線常直接改地圖 JSON（放人物、告示、機關），沒寫回產生器；重跑就被洗掉，`git diff` 也因為資源編號、清單換行這類格式差異看起來到處都在變，分不出哪些是真的差異。

現在第一到四章的產生器重跑後，地圖、關卡、人物、主題與遭遇資料和提交的版本逐位元相同（兩次重跑 269 個檔的雜湊一致）。做法：故事線在第一章麵攤鐵皮棚放的貓碗寫回產生器（第三章的東西故事線已經寫回）；產生器輸出地圖時，近前景、地面剖面這類清單照畫面線手寫的格式放在同一行；再把四章重跑一次、提交成標準格式（內容和原本完全一樣，只有資源編號與排列順序）。故事線說的「第三章玻璃邊緣、夾層、樣品房重跑有差異」就是這類格式差異，不是內容。

同一張票裡又有兩批直接改地圖的東西進來：玩法線在第三章天穹辦公接待廊示範門閂門（第 32 欄一道 6 格高的門、門頂那格維修廊空出來、左端三格踏板），已寫回產生器，字元 `⊓` 記進共用字元表；故事線在第四章放的兩份收藏文件、可讀物件與人物（ST-63），故事線自己寫回了，重跑檢查通過。

新增一支檢查 `tools/level/check_generators.py`：不動工作樹，在暫存資料夾重跑四章的產生器，逐檔比對（地圖比內容、`.tres` 不看資源編號與順序）。有人直接改了地圖沒寫回時，指出區域、檔名與第幾列第幾欄；在市集地圖故意改一格試過，抓得到（第 0 列第 2 欄）。

第四章接線廊的測試原本只數敵人數量；現在另外檢查地面有一組（站在出入口那一列）、走道上或上空有一組，而且從地面走、跳得上狙擊手站的走道——也就是劇情要的「正面通過或換層」真的成立。舊廠清掃路線的文件改成目前的配置。

第二章北棟前室的暗櫃，地圖與票上的描述改成只寫空間本身，拿掉原本先放的錢袋擺設；裡面放什麼、和誰有關由故事線決定。

推送前合併時又進來兩筆：故事線在第二章北棟前室暗櫃放的未寄出公告（ST-64，第 59 欄）、畫面線把第四章當舖的天空換成依劇情時段的薄霧天（產生器那邊漏改），都寫回產生器；合併後四章重跑檢查仍然全部通過，任務地圖、第一章地圖、第二章敵人、場景合理性、第四章故事五個套件 3976 / 3976 通過。
