# [NE-372] 縮短自動存檔造成的卡頓

> 狀態：完成

## 內文

### 需求

改善移動、開始交談和取消對話時，自動存檔造成的長影格。存檔發生異常時保住已發布的進度。[設計](../../design/20-campaign-experience/LEVEL_ENTRY_PERFORMANCE.md#自動存檔的位元組驗證)

### 來源

2026-11-26 在原生當鋪重播玩家提出的卡頓。一次移動影格長達 35.2 ms，其中 29.7 ms 花在讀回並解碼自動存檔。開始交談及中止也各遇到兩次驗證成本。

### 驗收條件

- [x] 相同實機重播下，移動、開啟交談與取消對話的最長影格都低於 33.3 ms。
- [x] 中途換關、換驗證器或外部改動主檔時，日常存檔能檢查正確版本。
- [x] 暫存檔被改動、同步保存接手或發布失敗時，保留原存檔與可恢復備份。

### 測試流程

1. 以原生當鋪執行步行、射擊、格擋、走入互動提示、按 F 和取消，核對輸入與存檔耗時。
2. 在自動存檔待發布時替換暫存檔或主檔，確認正確拒絕並比對主檔及備份。
3. 重跑存檔、對話及劇情交易回歸測試。

# Commit-1

## 內文

角色走動和交談時會定期保存進度。日常保存現在分開完成整輪驗證和資料發布。暫存檔通過逐位元組核對才可發布，外部改動的現有存檔會重新驗證。

在 RX 9070 XT、Vulkan Forward+、1280×720、144 Hz 和相同的合成輸入下，比較相同的小幅背景 CPU 負載。自動存檔主檔檢查最長由 25.85 降到 0.46 ms，驗證和發布階段由 31.85 降到 7.99 ms。欄位驗證在自己的影格完成，最長 20.34 ms。

### 測試結果

| 事件 | 修前最長影格 | 修後最長影格 |
|---|---:|---:|
| 開始交談 | 31.52 ms | 22.43 ms |
| 取消對話 | 30.57 ms | 26.64 ms |
| 移動階段 | 35.66 ms | 32.07 ms |
| 走入互動範圍 | 45.27 ms | 21.68 ms |

修後一次格擋階段出現 50.58 ms 影格。同格的採樣沒有存檔工作或管線編譯，這組量測的改善範圍以存檔為準。

測試讓不同的有效資料替換未發布的暫存檔。舊版寫出了替換後的資料，修正後拒絕並保留原主檔和備份。28 項存檔界線檢查通過，包含換關、外部更新和驗證器替換。

首輪 11 組、8,112 項檢查。對話保存的 5 項斷言依賴固定六格，現改成等分幀寫入完成，首格與關閉當下的位元組檢查均保留。受影響存檔套件重跑 1,083 項檢查通過，0 新失敗、0 已知失敗及 0 未預期腳本錯誤。其他 10 組首輪通過。
