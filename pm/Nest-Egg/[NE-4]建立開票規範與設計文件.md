## 內文

### 需求
開發流程需要固定的開票規範：每項需求一張票、完成時在票上記錄交付內容與截圖、每張票各自 commit，並把設計決策集中在設計文件。

### 來源
2026-10-02，使用者於開發對話中提出：「最好是每一塊都開票作，每完成一個票都留言＋截圖，然後 commit 一次」，並提供開票規範 skill。

### 驗收條件
- [x] repo 內安裝開票規範，之後的開發對話可直接依規範開票
- [x] 開發守則列出常設品質要求與工作流程
- [x] 設計文件有索引，賽博龐克改版的決策與票的清單已寫入
- [x] 已完成的項目補開票並標為完成

### 測試流程
1. 瀏覽票券資料夾，確認每張票都有需求、來源、驗收條件、測試流程與相依關係
2. 確認已完成的票都有 Commit 段落與截圖
