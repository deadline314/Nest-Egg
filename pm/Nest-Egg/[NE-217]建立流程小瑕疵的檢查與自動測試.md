# [NE-217] 建立流程小瑕疵的檢查與自動測試

> 狀態：待辦

## 內文

### 需求
「死亡後沒有解釋就回電話亭」「該播的過場沒播」這類小瑕疵都算 Bug，要有系統地檢查。需要整理業界做法，寫成 skill 與自動檢查：旗標讀寫表（誰寫、誰讀、時機）、過場前置條件與寫入時機、孤兒場景與資源、不可達內容、死亡與復活矩陣測試、讀檔邊界、資源遺失容錯，並建立 Bug 分級。之後每張涉及流程的票都用清單驗收。

### 來源
2026-10-06，使用者試玩第一章後回報：「我覺得這種小瑕疵都算是 Bug，可以的話也要有一個 Skill 去檢查這種小瑕疵」。

### 驗收條件
- [ ] 整理業界做法與檢查清單，放進設計文件並寫成 skill `continuity-qa`（敘事連貫、旗標與狀態、過場觸發、死亡與重試、讀檔邊界、場景切換、文字與音效、提示與教學、可達性）
- [ ] 旗標引用檢查：掃描劇本、過場、關卡、觸發資料，建立「誰寫、誰讀」表，報告只寫不讀、只讀不寫、拼字相近的旗標；第一章與第二章通過
- [ ] 過場前置條件檢查：requires 的旗標至少有一處會設定；設定發生在過場結束
- [ ] 孤兒資源檢查：沒被引用的場景、過場、對話列為警告
- [ ] 死亡矩陣測試：枚舉死亡情境（第一次死亡是否完成、診間過場狀態、電話亭登記、死亡位置、讀檔情境），無頭模式走一遍並斷言結果
- [ ] 資源遺失容錯測試：缺一個過場或音效時記錄具體路徑並退回安全預設
- [ ] Bug 分級（S1–S4）寫進 skill 與票的驗收說明
- [ ] 自動檢查納入 `tools/run_tests_changed.sh` 的選測與 CI
- [ ] 本票統整出的檢查項目與自動檢查方法，寫進 skill `continuity-qa`（`.claude/skills/continuity-qa/`），參考業界做法並附出處；之後涉及流程與狀態的工作都必須先讀這份 skill

### 測試流程
1. 執行旗標引用檢查，看報告
2. 故意製造一個只寫不讀的旗標，確認被抓到
3. 執行死亡矩陣測試
