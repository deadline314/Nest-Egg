# pm 資料夾說明

角色製作及交接入口：[user_guide.md](user_guide.md) · [2026-10-11 停工交接](handoff/character-art-2026-10-11.md)。包含使用者品質要求、來源／部件SOP、業界參考、拒收圖與各票真實狀態。

票放在 `pm/<專案名稱>/`，每個專案各自編號。格式見 Skill `pm-ticket`。

| 專案資料夾 | 代號 | 內容 |
|---|---|---|
| `Nest-Egg/` | `NE` | 玩法、角色、敵人、劇情、介面等 |
| `Nest-Egg-BG/` | `BG` | 場景、物件、背景、光影、渲染控制：地形材質、建築立面、遠中景、天空、道具、樹木、過場舞台、燈光與後製，以及這些素材的生成與處理工具（含 ComfyUI 腳本） |
| `ST/` | `ST` | **故事**：劇本與對白、腳本資料、過場與演出、故事需要的對話選項與旗標功能、配樂與音效的需求、角色與世界觀落到遊戲裡的工作。設計見 `design/13-story-v2/` |

三個專案的票可以互相引用，跨專案的相依關係寫完整代號（例如 `NE-66`、`BG-2`、`ST-1`）。

## 為什麼有 `ST`

2026-10-05，使用者決定把故事獨立出來：劇本、角色、世界觀、過場與演出會有很多張票，和玩法、美術的票混在一起不好找，也容易撞號。**2026-10-05 起，故事相關的票一律開在 `pm/ST/`，用 `ST` 代號，從 `ST-1` 開始編號。**

- **過去的故事票不搬、不改號**，仍留在 `NE`（例如第一、二章的舊劇本票）。那批票對應的是已作廢的舊故事（04-story），新故事（`design/13-story-v2/`）的工作都從 `ST` 開始。
- 故事需要的程式功能（例如對話選項、旗標、死亡畫面序列）也開在 `ST`，因為它們的驗收是「故事能演出來」。純粹的玩法、戰鬥、介面功能仍開在 `NE`；美術素材開在 `BG`。
- 判斷不出來時：**驗收的是「故事讀起來、演起來對不對」就開 `ST`**。

## 為什麼有 `BG`

2026-10-03，兩個對話同時開票：環境美術這條線開了 NE-73～81，角色重畫那條線也開了 NE-73～90，合併後每個號碼有兩張不同的票。2026-10-04 起環境美術的票獨立成 `Nest-Egg-BG`，用 `BG` 代號，角色重畫的 NE-73～90 維持原號。
