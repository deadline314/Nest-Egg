# BG-51：無頭渲染器背景貼圖配置

NE-228 的原麵攤冷讀 `host_none_read` 七項功能檢查全過、程序退出 0，但嚴格檢查器發現一個 DummyTexture RID 洩漏，整批因此停止。原始主檔、輸出、來源及完整失敗收據保留，沒有加入忽略規則，也沒有以正常退出碼冒稱通過。

## 可獨立重現的原因

最小專案不載入遊戲或任何 autoload，也不使用預載、匯入素材及音訊。固定八批、每批 1,024 張 2×2 貼圖，共 8,192 次，建立後等工作完成及主線影格，再釋放全部唯一 RID。相同腳本只改工作數：原引擎單工作無錯誤，四工作可重現初始化錯誤及退出洩漏。

固定版本的 RenderingServer 先在呼叫執行緒配置貼圖 RID，再排入主渲染執行緒初始化。Dummy 的配置器原本未啟用執行緒保護，多個背景工作會競爭配置狀態。這次只啟用配置器既有的執行緒保護；正式 RD 原本就使用相同保護方式。背景預載、聲音、原生渲染器與輔助功能保留。

公開獨立探針還會回讀每張貼圖，核對每個工作自己的像素，並用既有嚴格程序檢查器檢查逾時、異常、引擎錯誤與退出洩漏。它有固定工作數、批次及資料量，不保留無界限歷史。

## 建置與驗證整合

原 NE-280 音訊修補逐 bytes 保持。新增貼圖修補分別固定完整修前／修後來源與 patch 雜湊，逐檔驗證完整來源包；來源被改、修補不符或快取收據缺少任何修補均拒絕。指定 venv 的 Python 保留原路徑與套件上下文，不解析 symlink 而跑到別的直譯器，也不改動指定環境的套件。

初次交付檢查另發現引擎配方變更會被測試選擇器漏掉，輸出「沒有受影響的測試」。已保留該次原輸出，新增引擎配方／固定 patch 的完整測試規則及端到端驗證；不把沒有跑當作通過。

CI 會在實際音訊負載及原遊戲測試之前，執行獨立單工作／四工作貼圖檢查，並保留原始日誌及結果。引擎快取包含全部 patch 與配方的身分。

## 直接依據與限制

使用已取得、SHA-256 固定的 Godot 原始碼：

- `servers/rendering/rendering_server_default.h`：配置與初始化的執行緒界線。
- `servers/rendering/dummy/storage/texture_storage.h`：修前及修後的配置器。
- `servers/rendering/renderer_rd/storage_rd/texture_storage.h`：原有執行緒安全配置。
- `core/templates/rid_owner.h`：配置器的實際鎖與回收行為。

[固定來源版本與完整收據](engine-receipt.json)、[完整驗證](validation.json)、[原始證據](evidence.zip)、[逐檔雜湊](manifest.json)。Godot MIT 授權及版權文件附在證據封包。

[官方 Thread-safe APIs 文件連結](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html) 本次回傳 403，沒有重試、繞過或聲稱已讀該頁。

原單一洩漏輸出沒有 RID／資源身分；獨立重現與背景載入路徑一致，不能因此宣稱已唯一定位較早週日那個物件。原週日故障與「六次對照未再現」紀錄原樣保留，修補後另跑原流程。Forward+ 是軟體 Vulkan，音訊是實際 Dummy driver 混音取樣，不代稱實體顯示卡、手把或耳機聽感驗收。
