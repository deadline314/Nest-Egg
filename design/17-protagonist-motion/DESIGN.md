# 主角動作重設計與以主角為主的鏡頭

> 來源：2026-10-05 使用者說「現在主角動起來很不合理、也不好看」，要求參考業界最佳做法重新設計主角的整套動作，音效已更新可直接使用，並且「遊戲的主軸要以主角為主，視角要拉近一點」。
> 範圍：主角凜的待機、移動、跳躍、落地、衝刺、蹲、受擊的動作與鏡頭取景。**不含**：近戰揮砍與撥號的專屬動作（`art/rigs/action_poses.json` 的 `rin.*`，另有票處理）、敵人與 NPC 的動畫（各自的動作資料不動）、零件圖（美術不改）。
> 資料品質說明：下面分兩種——【引】公開資料有的原則與做法；【建議】針對 Nest Egg 推算的初始數值，必須實機（截圖與跑起來）調整。公開資料幾乎不給毫秒級的數字，所以數值不假裝有出處。

## 1. 現況診斷（讀自 `game/rig/humanoid_animator.gd`、`art/motion/rin.json`）

主角用的是和敵人共用的程式動畫器：每影格算各骨頭目標角度，套用、FK、手臂 IK 握槍、彈簧骨做衣襬頭髮。引擎本身沒問題，**問題在於它只做了「腿的循環」，身體其他部分是死的**：

| 現象 | 原因 | 為什麼看起來不對 |
|---|---|---|
| 跑起來像踩高蹺 | 落腳 IK 的腿幾乎打直（`reach` 0.985 倍腿長），踩地比例 0.55（永遠有一腳在地，沒有騰空）、抬腳只有 5.5 px | 走路的鐘擺節奏，不是跑；身體在腿張最開時最低、併攏時最高，剛好和跑步相反 |
| 上半身像一塊板 | 手臂 IK 鎖在槍上，胸只有固定前傾角；沒有骨盆與胸的反向旋轉、沒有肩膀起伏 | 腿在動、軀幹不動，重心沒有移動的感覺 |
| 起步、停步、轉身沒有重量 | 前傾角只看「速度」，不看「加速度」；每根骨頭用同一個固定速度平滑 | 一按鍵就直接是跑姿，沒有慣性，煞車沒有前衝 |
| 待機是雕像 | 腿是固定角度，只有呼吸與微小的左右晃 | 沒有重心轉移，兩秒就看穿是一張圖 |
| 跳躍是兩張靜態圖互換 | 上升／下落各一組固定腿角，在 `vy = 0` 瞬間切換 | 沒有起跳蹬地的伸展、頂點的滯空、下落的伸腿找地 |
| 落地沒有緩衝 | 只有整個節點縮放（擠壓）一下，骨架本身沒有吸收衝擊 | 擠壓縮放會把貼圖一起變形；真正的落地是膝蓋彎、骨盆下沉再彈回 |
| 衝刺是一格姿勢 | 一組固定角度加殘影 | 沒有蹬出去的拉長、收尾的煞車 |
| 腳步聲和腳對不上 | 腳步聲按「走了多少像素」計，動畫按自己的相位 | 聽到的步點和看到的腳落地會漂移 |
| 看起來離角色太遠 | 鏡頭縮放 1.25，畫面 640×360，角色約佔畫面高度兩成 | 主角是主軸，但畫面裡主角很小，動作細節看不出來 |

## 2. 業界做法（可以直接拿來用的）

1. **跑步循環靠四個關鍵姿勢**：接觸（contact）、下沉（down）、過渡（passing）、上升（up），加上一個騰空姿勢；其中接觸與過渡是不能省的關鍵格，下沉與上升負責身體的上下起伏，頭、軀幹、手臂也跟著起伏。【引：2D 跑步循環教學整理；Mega Man 用極少格數靠的就是接觸與過渡的對比】跑和走的差別是**有騰空**：踩地比例低於一半。
2. **腳踩地不滑、骨盆跟著腳決定高度**：腳的位置由 IK 決定、骨盆高度由「腿能不能夠到地」算出，骨盆下沉、腳跟隨身體後移。【引：程序動畫的腳 IK 做法】本專案的 `_step_legs` 已經是這個結構，只缺參數與落腳的姿態。
3. **骨盆延遲、胸腔反向旋轉**：骨盆的擺動落後於腳，胸腔與肩膀反向、並且「胸領先」，頭保持穩定；身體隨重心傾斜（weight shift）。【引：程序跑步的上半身做法】側視 2D 沒有真正的扭轉，用「骨盆與胸的角度反相微擺、頭反向補償」模擬。
4. **預備、跟隨、重疊（anticipation、follow-through、overlapping action）**：主體停下時衣襬、頭髮還在動，各部位速度不同，沒有任何東西同時停下。【引：Disney 原則；本專案 `ENEMY_FEEL_RESEARCH.md` 第 2 節已有彈簧骨做法】
5. **跳躍的預備放在落地，不放在起跳**：平台動作遊戲為了操作反應，起跳前不加預備動作（Celeste 起跳只有極短的過渡，落地時才擠壓；頂點把重力減半讓滯空、方便調整落點）。【引：Celeste 動作設計整理】所以：起跳瞬間做**伸展**（蹬地、腿打直、拉長），落地做**吸收**（膝蓋彎、骨盆下沉再彈回），中間頂點滯空。
6. **擠壓與伸展克制**：沿運動方向 5～10% 的形變，位置在骨架上做比整張貼圖縮放自然。【引：`ENEMY_FEEL_RESEARCH.md` 1.5；既有結論】主角已有骨架，落地的吸收改用骨盆與膝蓋，節點縮放保留但大幅降低。
7. **骨骼動畫與 2D 立繪並存的路線有先例**：Dead Cells 用 3D 骨架驅動 2D 圖，換來快速迭代與流暢的動作。【引：Dead Cells 角色美術流程報導】本專案的程式骨架動畫器是同一種取捨：動作是資料與參數，不是逐格重畫。
8. **鏡頭**：平台遊戲鏡頭以前瞻、垂直死區、trauma 震動為標準（`level_camera.gd` 已有）。主角為主軸的遊戲把鏡頭拉近，讓角色動作與表情看得見，同時用前瞻與瞄準偏移補回前方視野。【引：Celeste 以固定取景強調精準；Dead Cells、Hollow Knight 類遊戲則以較近的跟隨鏡頭強調角色】

## 3. 設計

### 3.1 原則

- **資料驅動、只改主角**：所有新行為都是 `art/motion/<角色>.json` 的新欄位，`DEFAULT_MOTION` 預設值＝「完全不變」，所以敵人與 NPC 的動作一個像素都不會動；只有 `rin.json` 填入數值。這延續 `ANIMATION.md` 第 1b 節「動作資料各自獨立」。
- **動畫器只多一層**：在 `_body_pose` 算完目標姿勢之後加疊加層（慣性前傾、反向旋轉、落地吸收），不改 IK、彈簧骨、專屬動作的流程。
- **可稽核**：`AnimAudit` 已經量骨頭拉伸、關節反折、腳踩實地、角度跳動；新動作必須全部過。新增稽核情境（起跳、落地、衝刺）。
- **可預覽**：`rig_preview` 加 `--jump`、`--dash`、`--run` 條帶，所有票的截圖都由它產生。

### 3.2 跑步與待機（票 NE-191）

| 項目 | 做法 | 初始值【建議】 |
|---|---|---|
| 騰空 | 踩地比例 `duty` 降到 0.5 以下，兩腳同時離地的相位就是騰空 | 0.44 |
| 膝蓋 | 伸展腿 `reach` 改成可調（不再固定 0.985），踩地時膝蓋微彎 | 0.93 |
| 抬腳 | 後腳抬高、小腿折起（踢腿），抬腳高度與速度成正比 | 8～9 px |
| 腳掌滾動 | 著地：腳尖略翹；踩穩：放平；蹬地離地：腳尖下壓；擺動中腳尖下垂再翹起 | 角度見資料 |
| 骨盆與胸 | 隨相位反向微擺（骨盆 ±、胸反向），頭與頸補償讓頭保持穩定 | 骨盆 0.05 rad、胸 −0.6 倍 |
| 肩膀起伏 | 手臂 IK 的錨點（胸）隨步伐上下一點，槍跟著微晃 | 約 1 px |
| 慣性 | 胸前傾 = 速度項 + 加速度項（彈簧）：起步前傾、煞車後仰再回正、反向時過衝 | 加速度增益、彈簧頻率進資料 |
| 待機 | 重心轉移：緩慢的左右移動配合一腿微彎、胸反向；呼吸加大；偶爾（每 6～9 秒）換腳 | 週期 5.5 秒 |

### 3.3 跳躍、落地、衝刺（票 NE-192）

| 項目 | 做法 |
|---|---|
| 空中姿勢連續混合 | 依垂直速度在「上升、頂點、下落」三組姿勢間平滑混合，不再 `vy = 0` 瞬間切換 |
| 起跳伸展 | 起跳後極短時間（約 0.1 秒）腿打直蹬地、胸挺起，再收腿；沒有起跳前預備，維持操作反應 |
| 頂點 | 頂點附近四肢展開、衣襬與頭髮上飄（彈簧骨注入衝量） |
| 下落 | 腿伸向地面、手臂上抬保持平衡 |
| 落地吸收 | 落地衝量（0～1）驅動一個彈簧：骨盆下沉、膝蓋彎、胸前傾，彈回時有一點過衝；快跑中落地直接接回跑步 |
| 節點擠壓 | 保留但降到原本的三分之一以下，主要靠骨架吸收 |
| 衝刺 | 蹬出：身體低伏前傾、後腿拉長、前手向後；結束：煞車前衝一小段（慣性前傾彈簧處理） |
| 次級動態 | 起跳、落地、衝刺、受擊時對衣襬與頭髮的彈簧注入速度（衝量），免費得到餘震 |

### 3.4 腳步聲對齊落腳（票 NE-193）

動畫器在兩腳著地的相位發出「落腳」事件，玩家腳本改用事件播放腳步聲（音量仍依速度、地面種類），沒有事件來源時（骨架載入失敗）退回原本的距離計步。

### 3.5 鏡頭（票 NE-194）

- 縮放從 1.25 拉近到約 1.6（畫面 640×360，視野從 512×288 縮到 400×225 世界像素）；主角在畫面中約佔高度的 27%。【建議，要用截圖與實際關卡驗證】
- 補回前方視野：前瞻與瞄準偏移加大；瞄準遠處時（準星離角色遠）鏡頭可以略微往前。
- 縮放做成 `LevelCamera` 的資料（可由設定或區段覆寫），而不是散落的常數；脈衝縮放（`camera_zoom_pulse`）疊在基礎縮放上，行為不變。
- 驗收看「敵人出現在畫面邊緣之前玩家能不能反應」：用既有的關卡擺放，量敵人進入視野時與玩家的距離。

## 4. 票的順序

| 票 | 內容 | 依賴 |
|---|---|---|
| NE-191 | 重新設計主角的跑步、待機與慣性動作 | 無 |
| NE-192 | 重新設計主角的跳躍、落地與衝刺動作 | NE-191（共用疊加層與預覽工具） |
| NE-193 | 腳步聲對齊主角落腳時機 | NE-191 |
| NE-194 | 拉近鏡頭讓主角成為畫面主角 | 無（可獨立做，最後用新動作驗證畫面） |
