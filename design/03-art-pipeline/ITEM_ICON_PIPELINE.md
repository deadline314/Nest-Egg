# 第一章道具圖示流程（ST-8）

來源為 `tools/art/build_item_icons.py` 與 `item_icon_kit.py` 的向量座標、色票與描邊，可只指定受影響的素材名稱重跑。沿用既有超採樣工具，不把小 PNG 插值放大成高清圖。

| 用途 | 素材尺寸 | 顯示契約 |
|---|---|---|
| 背包卡片 | 32×32 | 保留卡片的邏輯佔位 |
| 高清詳情 | 384×384 | 長邊 96 邏輯像素；等比縮小，不撐大版面 |
| 場景拾取 | 24×24 與同尺寸 glow | 沿用原本漂浮、發光與拾取流程 |

384 像素由向量來源直接繪製，足以供詳情圖在 4 倍視窗縮放時一對一取樣。高清詳情用線性過濾；舊卡片與缺高清素材時的替代圖沿用最近鄰，不改 HUD 武器圖或場景武器外觀。

手槍依外觀 id、單分子匕首依既有近戰 profile 選圖，武器與改裝頁共用載入。缺高清圖則使用既有卡片圖。信用點及船錢硬幣提供可供審查的素材，圖示產生器不新增故事身份、道具資料、取得旗標或出場配置。

每次修改後：

1. 執行 `python tools/art/build_item_icons.py <素材名稱...>`。
2. 檢查透明畫布、非空輪廓、留白、描邊、色票與圖形意義；相同輸入重跑須產生相同 PNG。未更動的卡片與拾取圖须保持相同位元組。
3. 經共享 GPU 鎖匯入 Godot，以 `tools/screenshot.tscn -- --scenario=item_icons --out=<絕對資料夾>` 拍實際詳情底板，再拍背包、補給／典當、拾取與機關。
4. 確認 384×384 圖仍顯示於 96×96 邏輯範圍，切頁、武器選擇、道具使用、拾取及水位持久狀態不退化。船錢若尚未掛入故事資料，以素材審查圖記錄，不假稱已在地圖拾取。
5. 跑受影響測試；ST-8 原票要求完整套件，另跑完整測試。保存原生截圖及日誌後才記錄交付。
