# 角色骨架與動作製作方法研究（2026-10-09）

範圍：NE-222 的角色接合、人體姿勢、外套、清晰度與動畫製作方法；其他人形角色後續承接。使用者要求先實際搜尋、確定方法，再恢復實作。本輪沒有修改角色、動畫或玩法，也沒有載入生成模型。

## 結論與建議

採用 **先製作關鍵姿勢，配合角色專屬網格／權重及必要的姿勢替換圖，最後加接地、瞄準與衣物次級運動** 的混合流程。保留使用者同意的凜 s33 外觀；需要補畫的是被遮住的底層或明確的姿勢局部，不能重新生成整個角色來碰運氣。

這是根據下列官方工具工作流程與本專案程式提出的建議，不宣稱所有業界作品都使用同一工具。現有 RIG_QUALITY.md 已提出網格配合彎曲變體；這次要改變的是製作與驗證的順序，以及讓局部姿勢變體成為正常製作手段，不能繼續把通用網格調參當作完整美術製作。

製作方法可以先確定；整個渲染後端是否切換到 Spine 必須另以小樣確認授權與整合成本。**目前最小可行路線是沿用既有 Godot 骨架與玩法介面，先用凜的普通蹲姿、持槍單膝跪姿證明這套製作法。** Spine Professional 是可評估的專用製作工具；取得可用授權後，才用官方範例檢查本專案的 4.7.2、HDR、掛點與受損部件整合。不以購買或換工具代替姿勢品質。

## 與目前程式對照：為何一直局部改善，整體仍不對

核對正式基準 8ed20854，並與尚未交付的 terrain 試作比較；不能把試作當成 main 已有功能。

- `game/rig/rig_part_mesh.gd` 已使用 Polygon2D。正式版將貼圖鋪在三欄規則網格，關節區按縱向距離算權重，再補償寬度；試作改過欄列數、根部跟隨與局部來源輪廓，但仍是通用網格。**目前缺的不是「加一個骨架系統」；是讓網格、權重與姿勢素材承擔角色造型。** 換成原生蒙皮而沿用同一拓撲，不會自動解決臀部凸塊或肩膀折疊。
- `game/rig/humanoid_animator.gd` 的動作由資料、步態、姿勢混合、IK 與額外修正組成。現有功能可保留，但每層都改同一區域時，局部參數正確仍可能產生不合理全身剪影；要固定處理順序並檢查每層的結果。
- 部件補全／分割決定材質歸屬，骨架綁定決定變形。重複臀部、藏在衣物圖裡的手、錯誤靴口、站直陰影，被網格拉彎後都不會自動變合理。
- 接點距離、alpha 或骨長測試可發現破圖，卻不能判斷「是不是好看的蹲姿」。近期試作仍有輪廓失敗，部分逐格接縫檢查也未通過；不能稱為只剩使用者確認。
- 现有 `RIG_QUALITY.md` 的原因段落描述早期剛體狀態。它可解釋歷史，但對最新版本的判斷以上述程式為準，不再照舊描述重做已完成的蒙皮。

以上是程式觀察與專案推論，不是工具廠商對本專案的診斷。

## 每個問題的具體處理方法

| 使用者看到的問題 | 採用的製作方法 | 通過證據 |
|---|---|---|
| 腰髖及所有接點有洞、缺角、浮片 | 先校準原圖坐標、旋轉中心與材質歸屬；依外輪廓和彎曲區設計拓撲；共用接邊採一致位置／權重，補足真正被遮住的底層 | 兩面向、裝備／受損狀態、全部動作與過渡逐格；一像素洞也失敗，不放寬檢測區 |
| 普通蹲姿像鴕鳥、臀腿變成凸球 | 先畫清楚全身骨盆、髖膝踝、足底與重心；臀部只屬於一份骨盆。深彎曲超出站姿材質能力時，製作局部蹲姿臀腿變體／頂點修正 | 先看完整剪影，再看全彩與受光；符合造型後才跑大量接縫矩陣 |
| 持槍蹲姿 | 獨立單膝跪姿，前腳與後膝承重、腰背和肩位置先定；雙手握點最後校正 | 靜止持槍、抬槍、射擊、起身；移動、空手及其他動作不能被跪姿鎖住 |
| 倒地只是站姿轉平 | 仰躺與俯臥各自製作終止姿勢及過渡；必要時替換軀幹、頭、手或腳的視角，處理前後圖層；沿用致命一擊來源選擇要求 | 胸／背、頭、手與腿的位置可讀，身體實際接地；平台邊緣另測，不用一個 root 旋轉當驗收 |
| 外套像披肩 | 確認領口、袖窿、袖子、袖口與穿衣底層；固定邊隨軀幹／上臂，衣襬才加受控次級運動。袖子或版型缺失需補畫 | 側站、雙手持槍、舉臂、蹲跪、倒地；彈簧不能補救錯誤版型，固定邊不能離肩 |
| 過場走路怪、关卡走路較正常 | 沿用已修的演員實際位移／縮放與方向輸入；挑接觸、下沉、經過、抬升關鍵姿勢，讓步幅／周期對應實際位移 | 相同素材在關卡、過場兩個入口比較；起步、煞車、反向、慢走、鏡頭放大均錄影 |
| 女主角進遊戲模糊 | 保留高解析來源及足夠貼圖密度；按最大顯示尺寸核對切圖、旋轉重採樣、匯入、子 Viewport、取樣、法線與發光 | 同尺寸比較來源／發布PNG／無光照遊戲／正式Forward+；分別找出損失在哪一步，不靠截圖插值放大 |

清晰度的目前可核對事實：正式配方 `illustration_px_per_wp=23.78`、`tex_px_per_wp=20`，切圖比例約 0.841；試作使用 23.78／23.78。這是有限的縮圖差異，不能當成全部模糊原因。正式 `project.godot` 使用 `canvas_items`，640×360 是邏輯基準，**不能因此斷言整個遊戲只用 640×360 渲染**。先前 HD 交付保留；後續只處理實測仍存在的損失。

後續實作補記：NE-222從相同來源重切23.78／23.78，並同步重建法線、發光與支點；骨架和武器掛點資料相同。頭像來源覆蓋層與遊戲一致，凜280×280來源裁切輸出256。原生1920×1080比較及背包576×768實際子視窗留有紀錄；這些只驗證實際降採樣與載入流程，接合和新姿勢仍須獨立通過。

## 恢復實作前的限定驗證

這是待執行的製作門檻，本輪沒有宣稱小樣已做好。

1. **凍結基準**：s33 原圖、已發布玩法與走路、GPU／解析度／光照及目前拒收例。列出部件歸屬，普通蹲與持槍單膝跪各畫一張完整姿勢參考；每張需看得清髖、膝、踝、足底和衣物。
2. **只做兩個姿勢小樣**：先讓它們在目前最大過場倍率與關卡倍率下，全身剪影、全彩及接點都正確。依輪廓製作網格和權重；需要局部變體就明確列出並保留來源。不先重跑全部角色、不再換數百組 sag／半徑參數找碰巧成立的組合。
3. **短動畫證明**：站→蹲→站、站→跪→抬槍／射擊→站；檢查兩面向、所有過渡、普通腳底與跪姿承重。造型不對即停止該候選，回到素材／姿勢；不以增加遮片、放寬像素門檻或縮小角色隱藏問題。
4. **停止條件**：相同部位連續兩次仍無法達到姿勢参考，先判定是來源、拓撲、視角或工具能力不足，再換方法；記錄一份拒收比較，不繼續無上限調參。兩次是本案控制返工的建議，非業界標準。
5. **通過後才擴展**：舉臂、外套、仰躺／俯臥，再到八動作、過場與全部角色。角色專屬的是美術與權重；可共用的是命名、播放／控制介面、接點規則和驗證工具。
6. **正式交付門檻**：現有全部件 skill 的零容忍逐格檢查、AnimAudit、受影響測試、實際戰鬥與過場、相同 GPU 條件下效能對照。數值通過與人工畫面通過分開記錄。使用者同意不自行代勾。

動畫處理順序的建議基線：關鍵姿勢／狀態混合 → 骨盆與軀幹 → 接地和握點 IK → 姿勢局部輪廓修正／圖層 → 衣物與頭髮次級運動 → 蒙皮和材質。每一部位有明確的主控，避免多層同時反向修正；實際順序仍需用小樣確認。

## 操作手感：沿用已有功能，量測差異

Celeste 作者的案例支持「擴大輸入時間或位置容錯」這個原則，不提供本案應複製的固定毫秒值。本專案 `player.gd` 已有 coyote time、跳躍／衝刺／近戰緩衝與地面／空中加減速；先驗既有行為，不能當成新需求重做。

後續量測按鍵→玩法開始、按鍵→可見姿勢、開火→槍口／後座、起步／煞車、連招／取消，以及關卡和過場的步態一致性。視覺混合不得延後既有起跳、開火或移動；有明確設計的攻擊預備／有效／收尾段仍保留。測試包括正常播放和低幀率，門檻以目前玩法、武器節奏與實際試玩設定；不把生理步頻或別的遊戲碰撞容錯當成全案硬性標準。
