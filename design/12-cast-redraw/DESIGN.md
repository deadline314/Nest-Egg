# 敵人與 NPC 重畫：用凜的流程做出同等精細度的人形角色

> 來源：2026-10-03 使用者在凜（NE-17、NE-68～72）完成後要求「針對遊戲裡面的敵人跟其他 NPC 重新繪製，其他 NPC 也用一樣的精細度處理，敵人根據不同的骨骼分件，可以的話幫其他 NPC 加入合適的動畫」。確認內容：**先做人形的**（非人形敵人另開一批）；**每個敵人有自己的比例**，視覺上不同是合理的，不強求統一；**所有 NPC 都做**；**芽當成可操控角色來設計**。

## 2. 做法：沿用凜的流程

流程文件 `design/03-art-pipeline/CHARACTER_PIPELINE.md`：Qwen 畫透明背景側面圖 → SAM 3.1 分群 → 被擋住的部位補全 → 依關節切零件 → 清理 → 法線與發光 → 預覽。凜之外的角色需要的新東西：

- **配方與規格以範本產生**：每個角色一份配方（造型提示詞、種子）與一份規格（關節、分群、零件掛載）。關節由 SAM 3D Body 預測，只要填差異。
- **裝甲分件**：敵人受傷時裝甲逐片脫落（沿用既有機制，`armor_order`，每一步一片或一組）。裝甲是獨立零件：肩甲、胸甲、護肘／護臂、護膝、頭盔等，依角色而不同；底下的身體要畫完整。敵人不做破衣底層。
- **每個角色自己的骨架比例**：骨頭長度由立繪量出（流程本來就這樣做），所以不同比例的角色是同一種「人形骨架」的不同尺寸，不用改動畫程式。
- **持武器的角色**：武器掛點由骨架算出；瞄準起點會跟著量出的肩膀高度走（NE-71）。
- **大小以遊戲為準**：身高對照碰撞框 12×44（敵人現況身高 54～60，重裝 69，監管者 97）；縮放用整體倍率調，不改關卡。

## 3. 芽：可操控角色的規格

使用者希望芽可以當作可操控角色。這次**只做資產，不做切換角色的玩法**（要不要做、怎麼切換另外討論）。資產規格與凜同等級：

- 完整動作都要正常：待機、跑、跳、落下、蹲、衝刺、格擋、硬直、死亡、各瞄準角度；武器掛點與槍口位置正確。
- 身高與縮放與碰撞框相容（玩家的碰撞框 12×44，肩膀高度由骨架量出）。
- 眨眼設定、背包立繪（睜眼閉眼）、對話頭像、受傷時衣物逐片脫落（同凜的做法，底層為撕裂版），法線與發光層。
- 她的外觀要與設定一致：嘴很毒、心很軟的駭客，戴耳機，紫色頭髮（現有設定：髮色 #5f3d9c、外套深紫、洋紫線條）。

## 4. NPC 動畫

NPC 沒有戰鬥，需要的是「活著的感覺」與角色專屬的小動作，由程式用骨架驅動（不逐格畫）。新增一個 NPC 用的動畫器（與戰鬥用的人形動畫器並存），NPC 的動畫設定放在資料裡：

- **共通**：待機呼吸、說話時點頭與手勢（有對話時啟動）、聆聽、朝向玩家、揮手。
- **姿勢**：站、坐、靠牆、蹲。
- **專屬工作循環**（資料指定）：
  - 老 K：攪粥、擦手、說話手勢大
  - 航：坐在床上、咳嗽、拉被子
  - 芽：（過場裡）戴著耳機敲鍵盤、抬頭
  - 麵攤阿婆：攪麵鍋、加蛋
  - 夜班工人：靠著貨櫃、看交班紙條、打哈欠
  - 護理師：整理器材、看平板
  - 維修員老陳：蹲著修理，偶爾敲打、焊接火花
  - 夾層區住戶：不安地張望、抱著孩子
- 動畫的幅度與節奏放資料，沒設定的 NPC 至少有待機呼吸。
- 過場與場景裡的 NPC 共用同一套（過場演員 `CutsceneActor` 已經用骨架）。

## 5b. 骨架與動畫器：誰用哪一種

- 每個角色有自己的骨架檔（`art/rigs/<id>.json`，骨頭長度與比例由立繪量出），骨頭名稱與階層沿用「人形骨架家族」，所以監管者、凜、小兵、NPC 都能共用動畫程式，體型差異不是問題。
- 骨架檔或外觀定義（`character.json`）可以用 `animator` 指定動畫器，預設是人形動畫器（戰鬥用，`HumanoidAnimator`）；NPC 用 `NpcAnimator`（`animator: "npc"`，場景人物與過場演員自動使用），它在走、跑、跳、蹲、格擋、倒下或持武器時會退回人形動畫器。
- 特殊角色（例如手臂特別多的頭目、四足、飛行）可以有自己的骨架（骨頭名稱不同）加自己的動畫器：繼承 `HumanoidAnimator` 或獨立實作 `update(delta, input)`，在 `CharacterRig.setup` 的動畫器選擇登記一個名稱即可，不需要改其他角色。專屬攻擊動作由敵人腳本在需要時提供目標角度（NE-89）。
- **專屬骨頭**（NE-89）：人形家族以外的骨頭（砲口、刀尖、可掀開的胸甲、披風）直接寫進角色規格 `bones`，用 `"fixed": [x, y]`（離父骨頭的位置，單位同骨架）或 `"at": 關節` 定位；零件的 `uses` 可以把貼圖掛在專屬骨頭上，並用 `offset: [x, y]` 補償骨頭位移讓零件留在原位。規格檢查（`check_spec.py`）會擋下沒有定位的專屬骨頭與格式錯誤的 `fixed`／`offset`。人形動畫器對專屬骨頭只負責骨架運算，角度由專屬動作（`art/rigs/action_poses.json`）用骨頭名稱驅動。
- **範例：監管者的核心砲**（第二階段招式）：規格宣告 `core_plate`（胸甲鉸鏈，胸甲零件掛在它身上）與 `core_port`（核心砲口，沒有零件）。敵人腳本做三件事：① 資料的 `rig_actions` 把狀態 `core_windup`、`core_recover` 對到動作 `warden.core_open`、`warden.core_close`（胸甲掀開與收回，角度與時間都在資料）；② 預兆的瞄準線與發光環、發射點、核心部位判定（`hurt_parts` 的 `core`，綁在 `core_port`）全部取同一個骨頭位置；③ 發射後核心外露期間把核心判定倍率拉到 2、結束收回。新增別的專屬招式照這三步，不需要動動畫器。
- 非人形敵人（無人機、電擊犬、自爆蟲、砲台、偽裝箱）將使用這個機制，在下一批做。

## 6. 不在這次的

- 非人形敵人（無人機三種、自爆蟲、電擊犬、砲台、偽裝箱）：需要新的骨架家族與動畫器，另開一批。
- 切換成芽來操作的玩法。
- 敵人的破衣效果（只有裝甲脫落）。
