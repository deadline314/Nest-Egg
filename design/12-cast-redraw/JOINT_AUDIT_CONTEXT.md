# NPC 接點的範圍與鄰關節上下文（NE-267，待原生驗證）

原始 checker、alpha>=128、原生尺寸及一像素拒絕維持。完整首輪的
622/201600 與 40/26880 失敗、RGBA 原檔及來源封包保留，不改寫成通過。

固定八世界像素的方形取樣帶會跨過短肢體的相鄰關節。原生單因素顯示：
膝的 (51,47) 像素 alpha5，只有加入實際骨盆後即覆蓋；腕的 (61,66)
仍為 alpha127；肩的 (68,59) 在全身可見時仍是背景，源圖本來就是輪廓外。
同格真 head anchor (66.27,59.27) 比 shoulder (64,64) 接近後者。
不能為了滿足錯誤取樣範圍在領口或肢體之間長肉，也不能豁免所有 edge notch。

實驗方法另立 NPC 範圍診斷，不更改既有 combat/default 語義：

1. 每格由實際已動畫的骨頭輸出所有稽核點位置；不是姿態名稱或模型預測。
   同姿勢、面向、角色的多個隔離 rig 必須具有相同相對骨點，否則工具拒絕。
2. 只比較解剖鏈上的直接相鄰關節。腕只與同側肘比較，不能因抬手靠頭而
   把真袖口孔交給頸部。髖、膝、踝同側處理；不使用角色例外名單。
3. 目標接點擁有比相鄰關節更近的區域，額外擴一個**原生像素**作保守重疊。
   不縮像素、不改 alpha 門檻、不設定可接受孔洞面積。
4. 中心透明、斷開元件、任何8連通仍封閉的孔，一律保留失敗。
   只有4連通判成孔、8連通實際向外開口、且明確在上述目標區域外的像素，
   才能列為「需由已覆蓋鄰關節核對的外輪廓」。這不是原始 checker PASS。
5. 每個被歸到鄰關節的樣本，該角色／面向／姿勢／倍率／相同時間格的鄰關節
   必須也完整擷取並稽核；缺資料時拒絕，不能靠縮小 joints 清單取得通過。

採用前必須保存原生 A/A、單一部件與全可見組合，且同一 checker 仍拒絕：
真正袖口一像素缺料、原六個 enclosed 腕孔、中心缺料、斷肢與故意位移。
先以 CPU 對抗案例及原生骨點對照驗證。資料不足或實驗仍紅時保持進行中。
