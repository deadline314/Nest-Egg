# 打擊感（Game Feel / Juice）研究：玩家武器、近戰、鏡頭、聲音、視覺、輸入，以及「打擊感實驗室」

> 範圍：2D 橫向動作射擊（Nest Egg：Godot 4.7、賽博龐克、HDR 泛光、凜用槍與近戰、敵人有人形／觸手／機械／飛行）。
> 與 [`../12-cast-redraw/ENEMY_FEEL_RESEARCH.md`](../12-cast-redraw/ENEMY_FEEL_RESEARCH.md) 的分工：那份已經寫了「敵人被打到」的受擊三層、局部頓幀、受擊方向、部位弱點、損傷狀態、屍體與 gibs、閃白 shader 的基本原則與頓幀分級表，**本文不重複**，只在需要時引用。本文補的是：玩家這一側的回饋（槍、近戰、格擋）、鏡頭、聲音、畫面效果、輸入手感、預兆與擊殺獎勵，以及把這一切變成「資料＋可即時調參」的工具。
> 資料品質標記：【引】有出處（來源清單附網址）；【經驗】業界慣例，多個來源一致但沒有單一權威數字；【建議】我針對 Nest Egg 推算，必須在實機調整；【專案】讀自本專案程式。查不到官方數字的地方我會直說，不編造。
> 專案守則（`CLAUDE.md`）：以資料為主、資源遺失退回安全預設值並指出位置、避免每影格配置、tooltip 一句講重點、特效要克制（使用者明確要求：粒子少而精、不誇張、不過曝）。

### 0.2 我在讀程式時發現的問題與缺口（這些是票的來源）

1. **回饋參數散落在程式裡**：`Fx.shake / hitstop / freeze / kick` 在 19 個檔案出現 53 次，數字都寫死在呼叫處（例如 `Fx.shake(2.0, 0.08)`、`Fx.hitstop(0.08)`）。要調一個「命中手感」得改程式、重開遊戲。這是做實驗室之前必須先解決的事。
2. **`Fx.shake` 的 `duration` 參數沒有被使用**（`LevelCamera._on_screen_shake` 以 `_duration` 忽略它），衰減是固定常數；呼叫端以為自己能控制長度，其實不能。
3. **小強度震動實際上看不見**：位移峰值 = `9 px × 2 × trauma²`，而 `trauma = strength × 0.08`。換算（噪聲取到 ±1 的上限，單位是世界像素，畫面上再乘 1.25）：

   | `Fx.shake(strength)` | trauma | 位移峰值（世界 px） | 衰減到 0 的時間 |
   |---|---|---|---|
   | 1.0 | 0.08 | 0.12 | 0.04 秒 |
   | 2.0（近戰命中） | 0.16 | 0.46 | 0.09 秒 |
   | 3.0（完美格擋） | 0.24 | 1.04 | 0.13 秒 |
   | 5.0（終結技） | 0.40 | 2.9 | 0.22 秒 |
   | 8.0（大爆炸） | 0.64 | 7.4 | 0.36 秒 |

   也就是 strength 小於 3 的事件幾乎沒有震動。`strength` 這個抽象單位讓人無法直覺調參。建議改成「峰值像素＋持續時間」（見第 3 節）。
4. **鏡頭沒有縮放脈衝、沒有依距離衰減、沒有「衝擊方向」震動**（只有噪聲震動與單向 kick）；前瞻只看面向（左或右），沒有看瞄準方向。
5. **全域頓幀期間鏡頭的震動也被放慢到 5%**（鏡頭在 physics process 裡用 `delta`，`delta` 被 `Engine.time_scale` 縮小），結果是「凍結結束後才看到震動」。這個行為剛好是好的（見 3.4），但目前是意外的，應該明確寫成設計並可調。
6. **近戰是「按下即命中」**：`_try_melee` 在按鍵的那一幀就查詢判定，沒有前搖、出招、收招，沒有取消窗口，沒有位移（lunge），沒有揮砍軌跡，也沒有輸入緩衝（冷卻中按的近戰鍵直接丟掉）。ENEMY_FEEL_RESEARCH 對敵人的 windup/active/recover 已有規範，玩家這一側沒有。
7. **音效只有單一版本、沒有分層命中、沒有材質、沒有壓低其他聲音**：`hit` 是固定的兩層合成音，每個 id 只有一份串流；沒有輪播變體（連發會有機關槍效應）、沒有 ducking、沒有依命中物材質換聲音、沒有擊殺／弱點專屬層、沒有發聲數量的優先級（只有 24 槽輪流覆蓋）。
8. **命中點回饋只有「顏色不同的火花」**：沒有材質（金屬／肉／玻璃／能量盾）差異，沒有命中標記（hit marker），沒有準星回饋。
9. **沒有回放與診斷工具**：`tools/` 有 `screenshot`、`rig_preview`、`creature_preview`、`readability_check`，但沒有能「同一個戰鬥畫面重複看」或「顯示頓幀毫秒、震動強度、粒子數」的東西。

## 1. 玩家武器的回饋

### 1.1 業界怎麼做

**Vlambeer《Nuclear Throne》是教科書**。Jan Willem Nijman 在〈The Art of Screenshake〉與訪談中拆解一發手槍子彈（30 fps、320×240）：【引】
- 子彈每影格 16 px，射角偏移 0～4°（精準度故意不高，讓每槍不同）；子彈第一格是圓的、之後才是子彈形狀（第一格像槍口閃光的延伸）。
- 彈殼出膛速度每影格 2～4 px，方向 = 瞄準方向再偏 100～150°。
- 開槍：鏡頭後座 6 px（朝瞄準的反方向）、螢幕震動 +4 並快速衰減、槍的精靈後退再很快滑回（weapon kick = 2）。
- 命中：敵人第一格全白、接著兩格睜大眼，擊退每影格 3 px 沿子彈方向，遊戲暫停約 10～20 ms，播「槍聲」與「命中聲（依敵人材質）」。
- 〈Art of Screenshake〉的完整清單（依 recreation 專案整理）：動畫、降低擊殺所需時間、提高射速、加大子彈、槍口閃光、加快子彈、**降低精準度換取動態**、命中特效、受擊反應、敵人擊退、**持久性（permanence：彈殼、屍體留在場上）**、鏡頭 lerp、螢幕震動、玩家被後推、命中暫停、武器後座、隨機敵人爆炸。這份清單的重點是：**每一項都很小，疊起來才有感**，而且「讓武器更強」本身（大子彈、高射速）就是手感的一部分，難度用敵人去補償。【引】

**射擊循環**（strayspark）：輸入 → 開火動畫 → 槍口閃光＋聲音 → 後座 → 彈體 → 命中偵測 → 命中回饋（標記＋聲音＋特效）→ 後座回復 → 就緒；每一步都要「即時且彼此相連」，命中標記 50～100 ms；爆頭／擊殺要有不同的標記與聲音；混音優先序是「玩家武器 > 受到的傷害 > 敵人武器」。【引】

**後座（The Astronauts / Witchfire）**：垂直後座與水平後座分開，水平回得比垂直快（讓連發更好控制）；槍口煙比真實短（為了可讀性）；命中貼花與命中特效依表面或敵人不同；開槍時鏡頭輕震。【引】

**槍口閃光（2D）**：多數做法是只顯示 1 格閃光，之後接粒子（黃橙像素、少量煙）；做成 3～4 款大小風格相近的變體隨機挑一款，避免每槍一模一樣。【引：OpenGameArt／realtimevfx 討論】

**槍聲分層**（Lior Ortega、Violet Recording 等）：一發槍聲由 transient（瞬間脆響）、body（主體）、sub（低頻重量，約 80 Hz）、mech（機械聲）、tail（尾音，依環境換版本）組成；「快速連發的武器要用短尾音，長尾音會糊」。【引】
遊戲聲音的「連發疲勞」解法：多個變體輪播＋音高隨機化；隨機音高只在一個很小的範圍。【引】

**命中點特效依材質**：Witchfire 與多數 FPS 都依表面換貼花與特效；2D 同理（金屬冒火花、混凝土噴灰與碎屑、玻璃碎片、肉／有機物沒有火花只有暗色飛濺）。【引：Astronauts；材質對照表為【建議】】

### 1.2 Nest Egg 的對應與取捨

**射擊要分「每槍都有的輕量層」與「特別時刻才有的重層」**。賽博龐克 + HDR 泛光 + 使用者要求克制，所以連發武器不能每槍都放大特效。建議的分層：

| 層 | 單發／低射速（手槍、狙擊、軌道砲、榴彈、散彈） | 連發（衝鋒槍、步槍、雷射連射） |
|---|---|---|
| 槍口星芒／閃光 | 每槍（1 格 ≈ 16～50 ms，3～4 款變體） | 每槍，但尺寸 ×0.7、變體輪播 |
| 槍口點光 | 每槍（能量 1.0～1.5，0.06～0.1 秒） | 每 2 槍一次，或能量 ×0.6 |
| 彈殼 | 每槍 | 每槍（已有；上限由粒子容量控管） |
| 鏡頭後座 | 每槍，依武器 | 每槍，數值小，**不累加到上限以外** |
| 螢幕震動 | 重武器才有 | 無（用 kick 就夠）；每 8 發給一次極小脈衝可選 |
| 玩家後推 | 依武器（已有 `recoil`） | 同 |
| 準星 kick | 每槍 | 每槍（幅度小） |
| 音效 | 每槍完整層 | 每槍短版（transient＋body，無 tail）＋輪播變體 |

**每把武器的建議值**（【建議】，全部要在實驗室調。單位：camera kick 為世界像素（`MAX_KICK = 8`）；shake 以第 3 節建議的「峰值像素」表示，現行 strength 對照見 0.2 的表）：

| 武器類型 | 槍口光（半徑 / 能量 / 秒） | camera kick | 震動峰值 | 玩家後推 | 準星 kick | 目標命中頓幀 |
|---|---|---|---|---|---|---|
| 手槍 | 48 / 1.0 / 0.07 | 1.5 | 0 | 0 | +2 px | 0～16 ms |
| 衝鋒槍 | 40 / 0.8 / 0.05 | 0.8 | 0 | 0 | +1 px | 0 |
| 步槍 | 52 / 1.1 / 0.06 | 1.2 | 0 | 0 | +1.5 px | 0～16 ms |
| 散彈 | 72 / 1.6 / 0.09 | 4.0 | 1.5 px / 0.12 s | 空中 > 地面 | +4 px | 33 ms（見 ENEMY 表） |
| 榴彈 | 64 / 1.4 / 0.1 | 5.0 | 2.0 px / 0.15 s | 小 | +4 px | 爆炸另算 |
| 軌道砲 | 80 / 2.0 / 0.12 | 6.0 | 2.5 px / 0.18 s | 中 | +5 px | 33～50 ms |
| 能量／雷射 | 44 / 0.9（持續光）| 0.5（持續） | 0 | 0 | 0 | 0 |

**子彈軌跡（tracer）**：高速子彈給 1～2 格的拉長亮線（疊加層、峰值亮度 ≤ 1.2），顏色用武器色；過長的軌跡在 640×360 的畫面上會變成雷射筆。【建議】
**命中點（impact）**：以「命中物材質」查表而不是以子彈查表：材質標籤放在 hurtbox／地形／道具上（資料），查表得到 `{火花、碎屑、煙、貼花、命中音組、閃光色}`。

| 材質 | 視覺（克制版） | 聲音 |
|---|---|---|
| 金屬／裝甲 | 橘白火花錐 4～6 顆沿法線，小星芒 | 清脆 ping + 短 tail；跳彈時加高頻「叮」 |
| 混凝土／磚 | 灰塵團 2～3、碎屑 2～3 | 悶 thud + 沙礫 |
| 肉／有機（觸手、生物） | 暗色飛濺 2～3，不用火花 | 濕 thud，低頻 |
| 機械（無人機、機甲） | 火花 + 偶爾電弧 | 金屬撞擊 + 電子雜音 |
| 玻璃／廣告牌 | 碎片 4～6 | 清脆碎裂（已有 `glass_break`） |
| 能量盾 | 圓形漣漪（用現有 `shock` 環池，小半徑）＋青色 | 低頻嗡聲 + 高頻 shimmer |
| 木箱／軟質 | 木屑 3～4 | 悶響（已有 `crate_break`） |

**命中標記（hit marker）**：準星處 50～100 ms 的小十字閃一下；弱點／爆頭用不同形狀（例如空心 vs 實心）＋高頻 ping；擊殺用較大的 X；被裝甲擋掉（零傷害或減傷）用「暗色短橫線」並配悶聲。這是「命中確認」，不是特效，不吃粒子預算。【引：strayspark 的時長；形狀與色彩為【建議】】

**換彈與空槍回饋**（專案已有 `reload_start / reload_done / empty` 三個音效）：
- 空槍：`empty` 單聲「喀」＋準星輕輕搖（水平 ±2 px，60 ms）＋彈藥環短暫閃一下；連按時 250 ms 才再播一次，避免變成噪音。【建議】
- 低彈量提示：彈匣 ≤ 25% 時彈藥環變色（黃）、最後 3 發聲音音高逐發微降（−1 半音）；不要用文字。【建議】
- 換彈：三個節拍對齊動作（退匣、裝匣、上膛）＝三個音效事件；完成那一拍給 1～2 格的彈藥環亮閃。換彈可被衝刺／近戰取消（取消時不播完成聲）。【建議】
- 單發 vs 連發：單發武器強調「一槍一個事件」（完整音、完整後座、彈殼落地有聲）；連發武器強調「節奏與持續感」（短音輪播、小幅疊加的鏡頭後座、彈殼不要每顆都發聲）。

### Nest Egg 可採用做法（第 1 節）

- 每把武器的回饋寫成**資料**：`muzzle`（變體清單、尺寸、光）、`camera_kick`、`shake_px/shake_time`、`recoil`、`crosshair_kick`、`casing`、`fire_sfx_event`、`hit_feedback`（頓幀毫秒、命中標記樣式）；`WeaponData` 現有 `camera_kick / screen_shake / recoil / muzzle_light_energy / ejects_casing / fire_sound` 全部移到回饋資料，並以武器類型提供預設值，新增武器只填差異。
- 連發武器的「回饋預算」：每槍只做輕量層，重層用節流（例如每 100 ms 最多一次）；這個節流值是參數，在實驗室可調。
- 命中由「材質標籤 → 命中回饋組」查表；標籤缺失退回 `generic` 並記錄「物件名＋欄位」；新增材質＝加一筆資料。
- 槍口閃光做 3～4 款變體，輪播不連續重複；子彈第一格用「圓」或強閃，之後才是彈體（Nuclear Throne 做法）。
- 命中標記、準星 kick、空槍搖晃都是 HUD 層，不用粒子；弱點、擊殺、被擋各有一種形狀與一個聲音。
- 空槍、低彈量、換彈節拍用現有三個音效擴充（不新增素材即可先做）。

## 2. 近戰與衝擊

### 2.1 業界怎麼做

**三段式與取消窗口**：動作遊戲把一次攻擊拆成 startup（前搖）、active（判定生效）、recovery（收招）；多數動作遊戲的「脆、回應快」感來自取消系統：Eric Williams 在 God of War 的拆解裡把取消窗口分成 **命中前取消**（任何在第一個命中幀之前）與 **命中後取消**（最後一個命中幀之後），以及任意時間取消；輸入有兩種實作——**緩衝法**（存起來，窗口一合法就執行；好的實作允許在窗口合法之前就再取消這個緩衝指令）與**即時法**（只在合法的那一幀接受）。「一個好的取消系統通常決定了遊戲是遲鈍還是脆爽」；God of War 2 約有 4000 個取消分支；為了避免無限壓制，部分特殊技被限制不能命中前取消。【引：Game Developer〈Combat Canceled〉】

**揮砍軌跡與殘影**：Sakurai 把揮劍後留下的效果稱為「blade trail」，並談到製作與要注意的地方（影片內容我沒有逐字稿，不引數字）；像素動作遊戲的做法是在武器弧線上畫 1 格 smear（拖影格），蓄力攻擊最多 2 格，smear 若穿牆就退成 1 格預備格。【引：Sakurai 影片（無逐字稿）、gamineai】
**命中頓幀／震動／粒子**：輕擊 2～4 格全停、重擊 6～10 格；近戰震動 4～8 格、短而高頻；輕擊碎屑 3～8 顆；畫面很擠時近戰粒子減半；**避免所有攻擊用同樣的頓幀（會抹平輕重）**。【引：gamineai】（頓幀分級表敵人研究已有，這裡只談近戰如何套用）
**聲音時機**：輕擊 80～150 ms 長，transient 在 10 ms 內；重擊在撞擊前加 30～60 ms 的預備聲／低頻下沉；撞擊聲的 transient 對齊頓幀開始的那一格。【引：gamineai】

**格擋／彈反的時間窗**：Sekiro 的彈刀窗口約 0.2 秒（12 格 @60fps），舉盾立刻起算（沒有啟動延遲）；完美彈刀有清脆的金屬聲與明亮的橘色火花，並大量增加敵人架勢；失敗的彈刀會自然變成普通格擋（寬容）；連續亂按會讓窗口變短（社群說法有 7 格與 0.1～0.2 秒兩種，數字不一致，視為「有防亂按設計」的定性證據）。【引：Steam 討論、Fextralife、SuperJump；數字為社群量測，無官方】
音效與命中判定在動畫資料裡（不是程式另算），所以回饋與窗口永遠同步。【引：Steam 討論】

**聽覺比視覺快**：對聲音的平均反應時間約 170 ms，對視覺約 250 ms；所以攻擊預兆與完美格擋成功都應該有獨特的聲音。【引：critpoints】

### 2.2 Nest Egg 的對應與取捨

**把近戰從「按下即命中」改成三段式**（【建議】，60fps 的格數與毫秒；`melee_cooldown 0.3 s` 目前等於總長，改成由三段決定）：

| 招式 | 前搖 | 出招（判定） | 收招 | 取消窗口 | 位移（lunge） | 命中頓幀 | 鏡頭 |
|---|---|---|---|---|---|---|---|
| 輕斬（現行近戰） | 3～4 格（50～67 ms） | 3 格（50 ms） | 8～10 格（130～170 ms） | 命中後：收招第 2 格起可接衝刺／跳躍；收招後半（最後 6 格）可緩衝下一段 | 前進 8～12 px，ease-out | 3 格（50 ms） | 沿揮砍方向 kick 2 px |
| 第三段重斬 | 6 格（100 ms） | 4 格（67 ms） | 12 格（200 ms） | 同上，窗口略晚 | 12～16 px | 5 格（83 ms） | kick 3 px + 峰值 1.5 px 震動 0.1 s |
| 終結技（現有） | — | — | 0.25 s | 不可取消 | 瞬移（已有） | 0.09 s（已有）| 震動 + 縮放脈衝（見第 3 節） |

- **判定只在出招段生效，一次揮擊對同一目標只命中一次（hit-set）**——沿用 ENEMY_FEEL_RESEARCH 3.2 的規則。前搖的最後一格可以略提前 1 格（碰撞偵測會晚一個物理影格，見該文）。
- **命中確認取消（hit-confirm cancel）**：揮空時收招完整吃滿（風險），命中時收招可被衝刺／跳躍提早取消（獎勵）。這同時是手感與平衡。
- **輸入緩衝**：在收招的最後 6～9 格（100～150 ms）內按下近戰，下一段自動接上（緩衝法）；其他動作（衝刺、換彈、格擋）同理（見第 6 節）。
- **lunge 與命中後的位移**：出招時攻擊方往前滑 8～16 px（數值依武器重量，資料化）；命中後攻擊方不再往前（頓幀把他釘住），敵人依重量擊退（沿用敵人研究的擊退曲線）；重武器命中時攻擊方後退 2～4 px（「反作用力」，Nuclear Throne 的玩家被後推）。
- **揮砍軌跡**：用 `Line2D`／窄帶 mesh 做一條 4～6 段的弧形，疊加混合，壽命 80～120 ms，寬度曲線（中間粗兩端細），顏色取武器色；從出招前 1 格開始畫、收招開始時淡出；峰值亮度 ≤ 1.2（HDR 泛光下避免過曝）。另外在出招第 1～2 格疊 1～2 格 smear 圖（可由程式把武器剪影沿弧線拉伸產生，不一定要新美術）。同一時間最多 2 條軌跡。【建議】
- **命中**：沿用現有 `Fx.burst`，改成「命中點＋沿揮砍方向的火花錐」，粒子數不超過 6（`PARTICLE_SCALE` 已經 0.5）；聲音用第 4 節的分層命中。

**格擋與完美格擋**（現況：窗口 0.16 s、起算點是舉盾；`parry_stun = 1.4 s`）：
- 窗口 0.16 s（約 10 格）在 Sekiro 0.2 s 的合理範圍內偏緊；建議給實驗室一個 0.14～0.22 s 的範圍，預設 0.18 s。【建議】
- **讓玩家看得見窗口**：舉盾的前 0.16～0.18 s 盾的輪廓比之後亮一階（白青邊、亮度 ≤ 1.0），窗口結束時回到普通亮度；這是最便宜的「教學」。
- **防亂按**：放開格擋後 0.15 秒內再舉盾，窗口縮短到 50%（Sekiro 的類似設計）；不是懲罰，是讓完美格擋有意義。【建議，來源為社群描述】
- 三級回饋（克制）：

| 事件 | 頓幀 | 鏡頭 | 視覺 | 聲音 | 其他 |
|---|---|---|---|---|---|
| 普通格擋 | 0～33 ms | kick 1～2 px 朝受擊方向 | 盾點小火花 3～4 顆、盾輪廓閃一下；玩家被推 6～10 px（滑行） | `block`，音高隨傷害 | 守勢條抖一下 |
| 完美格擋（彈反） | 67～100 ms（可全域，因為雙方都該停） | kick 3 px + 縮放脈衝 +2% / 150 ms | 盾點白青火花錐 6 顆 + 一圈細環（用 `shock`，半徑小）、攻擊者閃白 2 格 | `parry`（高頻清脆）＋低頻 thump；音樂壓低 −6 dB / 250 ms（見第 4 節） | 敵人暈眩（已有）；投射物被彈回要有軌跡 |
| 守勢崩潰（guard break） | 100～133 ms | 震動 3 px / 0.2 s + kick | 盾碎裂（碎片 3～4 個脫離）、守勢條洋紅閃 2 格、玩家硬直 | 破裂聲（低頻 + 玻璃感）| 畫面邊緣短暫洋紅暗角（見第 5 節）|

  頓幀是否全域：完美格擋時玩家與攻擊者是兩個主角，其他敵人也應該「看著」這一刻，所以用全域頓幀合理（現況已是）；但投射物、粒子、UI 仍要動（已用 `Engine.time_scale = 0.05`，不是 0，粒子與 UI 以真實時間運行才正確，要在實驗室確認每個系統的行為）。

### Nest Egg 可採用做法（第 2 節）

- 近戰招式資料：`startup / active / recovery`（秒或格）、`cancel_into = [{to, from_t, requires_hit}]`、`buffer_window`、`lunge = {distance, curve}`、`hit_feedback`（頓幀、kick、震動、命中音事件、火花）、`trail = {width_curve, life, color, hdr_cap}`；近戰武器的資料欄位與 `design/14-combat-variety` 的 1.2 對齊，不重複造一份。
- 一揮一命中（hit-set）、命中確認取消、揮空吃滿收招。
- 輕斬 → 重斬的段數遞增：頓幀 3 → 5 格、kick 2 → 3 px，不靠新特效而靠數值階層（避免輕重一樣）。
- 格擋窗口視覺提示（盾輪廓亮一階）、放開後再舉盾的窗口縮短、三級回饋（普通／完美／崩潰）。
- 完美格擋用全域頓幀 67～100 ms；其餘近戰命中用局部凍結；兩者都走同一個 `HitStop` 管理器（第 9 節 F4）。
- 揮砍軌跡與 smear 先用程式產生，確定手感後再決定要不要美術。

## 3. 鏡頭

### 3.1 業界怎麼做

- **Trauma 模型**（Squirrel Eiserloh，GDC 2016「Juicing Your Cameras With Math」）：維護一個 0～1 的 trauma，震動量 = trauma 的 2 次或 3 次方，trauma 隨時間線性衰減，位移與旋轉用 Perlin／simplex 噪聲取樣（平滑連續，不是每格隨機）；事件只負責「加 trauma」。Godot 的 kidscancode 版：`amount = trauma^trauma_power`（2 或 3）、`max_offset`、`max_roll`（弧度，少用）、`decay`，噪聲沿 y 軸遞增，三個不同 x 取樣得到旋轉與 x/y。dev.to 的 Godot 4 版：decay 4.0/秒、最大位移 12 px。【引】（Game Developer 的文章頁沒有內文，公式來自這兩個實作；GDC 原講我沒有逐字稿）
- **Nuclear Throne**：開槍震動 +4（螢幕上下左右最大像素）並快速衰減、鏡頭後座 6 px；〈Art of Screenshake〉的「camera lerp」讓鏡頭追得不那麼緊，使後座與前瞻更明顯。【引】
- **Cinemachine Impulse**（Unity）：震動是「衝擊事件」，有 **訊號形狀**（曲線）、**方向模式**（固定方向，或朝向來源旋轉，給玩家「從哪來」的線索）、**傳播速度**、**衝擊半徑 + 衰減距離（線性／柔和／指數）**。重點：衝擊是有方向、有距離衰減的，不只是全域噪聲。【引：Unity 文件】
- **Unreal GameplayCue**：鏡頭震動被當作「一次性（burst）事件」的資料欄位，與粒子、聲音、力回饋放在同一個資料物件，設計師不寫程式就能配。【引：Unreal 文件】
- **無障礙**：指南建議能關閉或降低鏡頭震動、鏡頭晃動、動態模糊；Halo Infinite 提供徑向模糊、螢幕震動、全螢幕特效、速度線 0～100% 的滑桿；Jedi: Survivor 有「環境鏡頭晃動」0～150。閃光限制：每秒不超過 3 次明暗交替（WCAG 2.3.1），飽和紅色閃光更嚴。【引：Xbox Accessibility／Game Accessibility 整理】

### 3.2 Nest Egg 的對應與取捨

**(a) 事件以「峰值像素 + 時間」表達，內部再換算成 trauma。** 解決 0.2 節的第 2、3 點：設計師寫 `shake = {peak_px: 2.0, time: 0.12}`，系統換算 `trauma = sqrt(peak_px / (MAX_SHAKE_OFFSET × 2))`，並用 `time` 決定這次事件的衰減（目前只有全域常數 1.8/秒）。換算表（`MAX_SHAKE_OFFSET = 9`）：

| 想要的峰值 | trauma | 用途建議（【建議】） |
|---|---|---|
| 0.5 px | 0.17 | 輕近戰命中（現況約 0.46） |
| 1.5 px | 0.29 | 重斬、散彈、完美格擋 |
| 3 px | 0.41 | 終結技、精英擊殺、守勢崩潰 |
| 6 px | 0.58 | 大爆炸、頭目階段轉換 |
| 10 px | 0.75 | 劇情級事件（全遊戲上限） |

   現行 `Fx.shake(strength, duration)` 保留為舊介面（內部轉成峰值像素），遷移完成後移除。

**(b) 方向性衝擊（directional impulse）**：近戰與槍擊用「沿方向的阻尼彈簧」取代噪聲：初速朝衝擊方向，2～3 次往返，總長 120～180 ms；爆炸與崩塌才用噪聲 trauma。這比隨機噪聲更能說明「從哪裡被打」。現有 `camera_kick` 是單向衰減，可以升級成阻尼彈簧（有一點過衝）。【建議；原理引 Cinemachine 的方向模式】

**(c) 距離衰減**：事件帶來源位置，鏡頭依「與來源的距離」衰減（衝擊半徑 200 px 內全強，之後 300 px 內線性衰減到 0，數值【建議】）。畫面外的爆炸不該讓玩家整個畫面抖。

**(d) 縮放脈衝（zoom punch）**：目前 `ZOOM = 1.25`。事件以 +1.5～3% 的縮放（1.25 → 1.27～1.29）在 60～80 ms 內推進、150～250 ms 用彈簧回復。**只給**：完美格擋、終結技、精英／頭目擊殺、頭目階段轉換、清場最後一擊。**不給**：普通槍擊、一般近戰、一般擊殺。縮放脈衝是比震動更強烈的「事件標點」，濫用會讓所有事件都一樣重要。【建議；Sakurai 影片提到擊殺時推近＋放慢能增加戲劇張力，【引】僅定性】

**(e) 前瞻改成「瞄準加權」**：現況只依面向偏 48 px。建議前瞻向量 = `facing × 48 + aim_dir × 24`，上限 72 px，且前瞻在命中頓幀與格擋舉盾時鎖定不動（避免鏡頭在凍結瞬間漂移）；速度 2.5/秒不變。【建議】狙擊／長距離武器（軌道砲、雷射）可加大前瞻到 96 px（資料化在武器上）。

**(f) 命中推進（hit push-in）**：重要擊殺時，鏡頭往目標方向偏 3～6 px、ease-out 120 ms、再回；與縮放脈衝擇一，不同時疊。【建議】

**(g) 頓幀與震動的先後**：業界常見是**凍結的瞬間不震動，凍結結束的那一格才爆發**（命中先「卡住」讓眼睛看見，再「釋放」）。現況因為鏡頭用被縮放的 delta，剛好得到這個行為，但這是意外。建議明確：
- 事件帶 `shake_delay`（預設 = 頓幀長度），在頓幀的實時結束後才開始震；
- 頓幀期間，被凍結的角色可以做 ±1 px 高頻抖動，強度隨時間衰減（Sakurai 的說法已經寫在 ENEMY_FEEL_RESEARCH 1.1）。

**(h) 疊加規則**：多個事件同時發生時，**同一來源重複觸發取最大值，不同來源相加但整體上限 0.6（頭目與劇情事件可到 1.0）**；現況是相加到 1.0（`minf(1.0, _trauma + ...)`）。【建議】

**(i) 可關閉與縮放**：設定頁加「畫面震動 0～100%」（影響震動與縮放脈衝；kick 在 0% 時保留 50%，因為它是功能性回饋「槍有後座」）。與現有「減少閃光」分開。數值寫進 `Settings`，與 `flash_scale()` 同一個模式。

### Nest Egg 可採用做法（第 3 節）

- 鏡頭事件資料化為 `{peak_px, time, direction?, source_pos?, falloff_radius?, zoom_pulse?, delay}`，由 `Feel` 單一入口發送，`LevelCamera` 只負責執行。
- 保留 trauma + 噪聲（用於爆炸），新增方向性阻尼彈簧（用於槍擊與近戰）與縮放脈衝；縮放脈衝只准用在白名單事件（寫在資料裡、由測試檢查白名單）。
- 前瞻改為面向 + 瞄準加權，頓幀與舉盾時鎖定。
- 震動總量上限 0.6、同來源取最大；頓幀期間不震、結束才震。
- 設定頁新增「畫面震動」滑桿（附 tooltip），預設 100%；`Fx` 以外的系統不得自己改鏡頭 offset。

## 4. 聲音

### 4.1 業界怎麼做

- **命中聲的分層**：「高頻 click 負責定義、中頻 body 負責角色、低頻 thump 負責重量」；槍聲的 transient／body／sub／mech／tail 五層（見 1.1）。快速動作的 SFX「快速 attack、短 tail」。【引】
- **音高隨機化與輪播**：同一音效每次播放隨機移動音高一點點，並輪播多個錄音版本、避免連續兩次相同，再疊音量隨機，效果最自然；範圍「上下各約一兩個半音」可保持辨識度（那是通用上限，連發槍聲要小很多）。頻繁出現的效果（槍聲、腳步）最需要。【引：Violet Recording、Game Developer〈The Power of Pitch Shifting〉】
- **音高傳遞資訊**：撞擊越重音高越高；連鎖動作逐步升音（一個半音 = ×1.0595，第 N 次 = 1.06^N）可以強化連擊感。【引：Game Developer】
- **聲音與頓幀對齊**：輕擊 80～150 ms、transient < 10 ms，重擊多一段 30～60 ms 預備聲；撞擊聲對齊頓幀開始的那一格。【引：gamineai】
- **Ducking（壓低其他聲音）**：重要聲音（爆炸、對白、撞擊）出現時降低其他匯流排；兩種做法：Wwise 的自動 ducking 與 sidechain；典型匯流排結構是 Master → Music / SFX / Ambience / UI / Voice，並用規則決定「誰壓誰」。Godot 的 `AudioEffectCompressor` 有 sidechain 屬性，用另一條匯流排的音量作為閾值偵測，文件明說這在遊戲混音中常用來在語音時降低音樂與音效。【引：Audiokinetic 文章、Godot 文件】
- **反應速度**：聽覺 170 ms vs 視覺 250 ms，所以預兆與成功回饋要有聲音。【引：critpoints】
- **混音優先序**：玩家武器 > 受到的傷害 > 敵人武器。【引：strayspark】

### 4.2 Nest Egg 的對應與取捨

專案的 `Sfx` 已經是「多層合成」的雛形，所以不需要先有素材，也不用引進中介軟體；但需要補四件事：

1. **事件由多層組成（SfxEvent）**。一個命中事件 = 若干層，每層：`{sound_id, delay_ms, volume_db, pitch_range, probability, bus}`。範例（【建議】）：

   | 事件 | 層 |
   |---|---|
   | `hit.rifle.metal` | `hit_transient`（0 ms，−4 dB）＋ `metal_ping`（0 ms，−8 dB，音高 ±8%）＋ `hit_body_low`（0 ms，−10 dB，只在傷害 ≥ 閾值） |
   | `hit.melee.flesh` | `melee_thud`（0 ms）＋ `wet_hit`（0 ms，−6 dB）＋ （重斬）`sub_drop`（−30 ms 預備，即前置 30～60 ms 的低頻下沉） |
   | `hit.weakpoint`（疊加） | `ping_high`（3～4 kHz，60～90 ms，−8 dB） |
   | `kill`（疊加） | `sub_thump`（約 80 Hz，100～150 ms）＋ 向上滑音 `chirp`（80 ms）|
   | `parry.perfect` | `parry`（現有，音高不隨機，要讓玩家學會「這個聲音＝成功」）＋ `thump_low`＋ 短 tail |

2. **變體與輪播**：每個 id 預先合成 3 個變體（不同噪聲種子、微小頻率差），輪播且不連續重複（合成的 `_rng.seed = 7` 改為每個變體一個種子）。音高隨機範圍依類別：槍聲 ±3～5%、命中 ±6～10%、近戰 ±5%、UI 與 `parry`／`telegraph`／`block` 這類「資訊音」0～±2%（要能被學習）。連鎖命中（同一目標或 1.2 秒內連續擊中）每次 +1 半音，上限 +6，之後重置。【建議；數學引 Game Developer，範圍為建議值】

3. **Ducking**：新增匯流排結構（Master → Music / Ambience / SFX（含 Impact 子匯流排）/ UI）。先用「事件觸發的音量補間」（`Sfx.duck(bus, db, hold, release)`）而不是即時 sidechain 壓縮器，因為事件式 ducking 可預測、可測試、可在實驗室調：

   | 事件 | 壓低對象 | 深度 | 起音 | 保持 | 釋放 |
   |---|---|---|---|---|---|
   | 完美格擋 | Music、Ambience | −6 dB | 10 ms | 120 ms | 250 ms |
   | 精英／頭目擊殺 | Music、Ambience | −8 dB | 10 ms | 200 ms | 400 ms |
   | 大爆炸 | Music、Ambience、其他 SFX | −6 dB | 5 ms | 150 ms | 400 ms |
   | 玩家受傷 | Music | −4 dB（加 3 kHz 以上低通 200 ms，可選） | 10 ms | 100 ms | 300 ms |
   | 普通命中 | 無 | — | — | — | — |

   （【建議】全部。Godot 的 sidechain 壓縮器列為可選的第二階段，用在「長期持續」的壓低，例如對話。）

4. **發聲預算與優先序**：現況 24 槽輪流覆蓋、每個 id 25 ms 節流。加上優先級（`parry / kill / player_hurt` > 玩家槍聲 > 命中 > 敵人槍聲 > 環境）；同一影格超過 N 層（建議 8）時，丟掉優先級最低且音量最小的；實驗室顯示「這秒用了幾層、丟了幾層」。

**其他**：
- **擊殺與暴擊層**：只加疊加層（不替換基底音），所以調參時可單獨關閉。
- **環境回應**：給 SFX 匯流排一個混響效果（`AudioEffectReverb`），依關卡標籤切換濕度（街道 ≈ 0.12、室內 ≈ 0.25、升降井 ≈ 0.35，【建議】）；連發武器的 tail 要短，單發重武器才給長 tail。彈殼落地的「叮」延遲 250～400 ms，聲音依地面材質（提供「持久性」的聽覺版）。
- **素材**：第一階段全部用現有程式合成補足（變體靠種子、材質靠參數）；`OVERRIDES` 的機制保留給之後換正式音檔。若要請音效師，最值得先做的是 `hit_transient` 與 `sub_thump` 兩個素材（影響最大、檔案最小）。
- 每個 SfxEvent 在資料裡可指定 `ducks`，與鏡頭事件放在同一個回饋事件裡（第 9 節 F1），不要散落在兩處。

### Nest Egg 可採用做法（第 4 節）

- `SfxEvent` 資料：多層、延遲、音量、音高範圍、機率、匯流排、`ducks`；`Sfx.play(id)` 保持相容，新增 `Sfx.play_event(event_id, ctx)`。
- 每個合成音預先生成 3 個變體並輪播；音高範圍依類別；資訊音幾乎不隨機。
- 匯流排結構 + 事件式 ducking（先不用 sidechain 壓縮器），ducking 參數資料化；實驗室可即時調。
- 發聲優先級與每影格層數上限；超過就丟低優先級；診斷顯示層數與丟棄數。
- 擊殺／弱點／暴擊只加疊加層；連鎖命中升音（上限 +6 半音）。
- 關卡標籤決定混響濕度；連發武器短 tail。
- 資料缺漏（找不到 sound id）→ 記錄「事件 id + 層索引」，跳過該層，不崩潰；測試鎖定所有事件引用的 id 存在。

## 5. 視覺

（敵人側的閃白 shader、局部頓幀、損傷狀態、gibs 與屍體在 ENEMY_FEEL_RESEARCH 已寫；這裡只談全畫面、玩家側與預算。）

### 5.1 業界怎麼做

- **閃白／受擊色**：命中第一格全白或高亮、之後 1～2 格回到正常（Nuclear Throne、像素 FX 指南）；在 HDR 2D 下 `modulate > 1` 會發光，因此要克制（見 ENEMY_FEEL_RESEARCH 1.4 的結論：用 shader 混白，峰值 ≤ 1.0）。【引】
- **螢幕邊緣與色差**：Godot 有現成的全螢幕 post-process 做法：`CanvasLayer` + 全螢幕 `ColorRect` + `hint_screen_texture`，常見配方是暗角、色差、受傷閃光；社群 shader（Aberration Vignette、Chromatic Chaos Distortion）可參考。【引：uhiyama-lab、godotshaders】
- **慢動作**：研究建議最佳約 0.2～0.4 秒、時間縮放 0.3～0.5（敵人研究已引）；Sakurai 談到終結時推近與放慢可提高戲劇張力；Katana Zero 的慢動作是核心機制而非回饋（只給定性參考，沒有數字）。【引】
- **粒子預算與克制**：輕擊 3～8 顆、畫面擠時近戰粒子減半、避免連段每一格都噴粒子（會蓋住可取消的節奏）；閃光色調要配合環境（在雪地或亮 UI 上白閃會被吃掉）；畫面外投射物不要引起震動。【引：gamineai】
- **傷害數字**：字體用無襯線、白字加細描邊最易讀；大小約縮小 23～50%（避免洗版）；依傷害縮放；顏色依類型；暴擊更大且停在原地不漂；每個數字加隨機偏移避免疊在同一點；連擊時堆疊偏移幾個像素；用物件池。【引：wayline、sorceress 整理，來源品質普通】
- **持久性**：彈殼、屍體、火花留痕讓戰鬥「發生過」（Vlambeer，敵人研究已引）。

### 5.2 Nest Egg 的對應與取捨

- **一個共用的全螢幕效果層 `FeelScreen`**（單一 `CanvasLayer` + 一個 shader，uniform：色差像素、暗角強度與顏色、全螢幕混色量、去飽和量；由彈簧驅動，不是 tween 堆疊）。用途與上限（【建議】，解析度 640×360 基準）：

  | 事件 | 效果 | 峰值 | 時間 |
  |---|---|---|---|
  | 玩家受傷 | 洋紅暗角 + 色差 | 暗角 α ≤ 0.35、色差 ≤ 1.2 px | 120～200 ms |
  | 完美格擋 | 青白邊緣閃 | 全螢幕亮度變化 ≤ 0.12，只 2 格 | 40 ms |
  | 守勢崩潰 | 洋紅暗角 + 色差 | α ≤ 0.3、色差 ≤ 1.5 px | 200 ms |
  | 低血量 | 持續極淡暗角（呼吸） | α ≤ 0.15 | 持續 |
  | 頭目階段轉換 | 色差脈衝 + 縮放 | ≤ 2 px | 300 ms |

  全部乘以 `Settings.flash_scale()`；「減少閃光」時色差與全螢幕混色降為 0，只剩暗角。**全螢幕閃光頻率限制**：任何 1 秒內明暗交替超過 3 次要自動降階（診斷面板顯示此頻率）。
- **慢動作白名單**：只准用在 (1) 頭目最後一擊、(2) 一個區域「最後一隻敵人」的擊殺（清場）、(3) 劇情擊殺。時間縮放 0.35～0.5、時間 0.2～0.4 秒、冷卻 ≥ 8 秒、畫面上有 ≥ 3 個存活敵人時略過。一般擊殺、完美格擋用「頓幀 + 縮放脈衝」，不用慢動作。【建議】
- **HDR 亮度預算**：
  - 閃白維持敵人研究的原則（shader 混白、峰值 ≤ 1.0）；槍口光、軌跡、爆炸的 HDR 值上限寫成常數（槍口星芒 ≤ 1.9 已是 `Fx` 現況的 `minf(1.9, ...)`，再依 `FLARE_SCALE` 縮放）。
  - 同一影格疊加層的總面積／總亮度做「發光預算」：實驗室每 0.25 秒對縮小的畫面取樣，顯示最大與平均亮度，超過門檻（【建議】峰值亮度 > 1.0 的像素比例 > 3%）時警示。
- **粒子預算**：每個事件有粒子數上限（寫進資料）、全域活躍粒子數有上限（`ParticleField` 已固定容量）；畫面擠（≥ N 個敵人或 ≥ M 發子彈）時事件粒子減半（`particle_density` 由 `Feel` 即時計算）。
- **傷害數字**：預設關閉（Nest Egg 不是數值遊戲）。如開啟，用池（24 個 `Label`）、白字 1 px 描邊、暴擊／弱點變大並停在原地、同一目標 150 ms 內合併累加、隨機偏移 ±6 px。**只有「帶資訊」的情況才顯示**：弱點、暴擊、被裝甲吃掉（顯示 0 或暗色）。命中標記（第 1 節）才是主要確認。
- **受傷閃爍**：現有 `hurt_invulnerability = 1.0 s`。建議用半透明閃爍（α 0.5↔1.0，約 8 Hz），不要全亮全暗（符合每秒 ≤ 3 次明暗交替的原則：α 變化小於全黑全白）。

### Nest Egg 可採用做法（第 5 節）

- 單一 `FeelScreen` 全螢幕層：色差、暗角、混色、去飽和；彈簧驅動；乘 `flash_scale()`；峰值上限寫在資料。
- 慢動作白名單 + 冷卻 + 敵人數量條件；一般事件只用頓幀與縮放脈衝。
- HDR 發光預算、粒子密度自動減半、全螢幕閃光頻率限制（每秒 ≤ 3 次明暗交替）三項都要在實驗室診斷中可見。
- 傷害數字預設關、池化、只顯示帶資訊的情況；命中標記為主。
- 受傷閃爍用半透明低頻。

## 6. 輸入手感

### 6.1 業界怎麼做

- **土狼時間與輸入緩衝**：Celeste 的作者 Maddy Thorson 公開了她的「寬容」設計：離開平台後仍可跳、落地前先按跳會在著地那幀起跳；以及牆跳可離牆 2 px（在 320×180 的遊戲裡約四分之一格）、超級牆跳 5 px 等；**她沒有公開幀數**。【引：Celeste & Forgiveness】
- 一般建議：土狼時間 60～120 ms、輸入緩衝 100～200 ms，「小到看不見、大到吸收人類的時間誤差」；緩衝不只用於跳躍，也用於戰鬥（排隊下一次揮砍）、閃避（在硬直中按下、恢復時觸發）與選單；測試時把值加倍與減半找甜蜜點，找陌生人測試，因為設計師會適應自己的遊戲；難度或無障礙設定可放寬。【引：bugnet】
- **取消窗口與緩衝**：見 2.1（God of War）。**「回應快或遲鈍，主要取決於取消系統」**。【引】
- **瞄準輔助**：常見技術是子彈磁性（bullet magnetism）、面積游標（area cursor）、黏性目標（sticky targets）、目標引力；磁性把準星拉向目標、摩擦在目標附近降低準星速度；**玩家輸入永遠要能蓋過輔助，輔助是偏置不是鎖定**；依距離與目標大小縮放（遠、小的目標給更多）。Insomniac 在 Resistance 3 用磁性、置中與摩擦（GDC，內容需會員，只知道名稱）。【引：bugnet、GDC Vault 摘要】
- **延遲**：舊文獻常用 100 ms 為舒適上限，較新研究顯示簡單滑鼠互動的可感延遲約 60 ms；Godot 文件建議降低輸入延遲的做法：提高物理頻率（120／180／240）、4.3 起把 V-Sync swapchain 影像數降到 2、需要時 `Input.set_use_accumulated_input(false)`；物理插值會增加延遲。【引：Wikipedia／學術論文、Godot 文件】
- **準星回饋**：命中標記 50～100 ms（見 1.1）；準星依後座張開（bloom，專案已有 `aim_bloom`）。

### 6.2 Nest Egg 的對應與取捨

專案已有土狼 0.1 s、跳躍緩衝 0.12 s、牆角修正 5 px，值都在建議範圍內，所以重點是**把緩衝擴到戰鬥動作並做成資料**：

| 動作 | 緩衝窗口（建議） | 取消規則 |
|---|---|---|
| 近戰 | 收招最後 6～9 格（100～150 ms） | 命中後可被衝刺／跳躍取消 |
| 衝刺 | 100 ms | 可取消近戰收招與換彈（不可取消硬直） |
| 換彈 | 不緩衝 | 可被衝刺／近戰取消 |
| 跳躍 | 現有 0.12 s | — |
| 格擋 | 不緩衝（按住即時） | 放開後 0.15 s 內再舉盾，窗口縮短 |
| 射擊 | 半自動武器：冷卻最後 80 ms 內按下則排隊 | — |

- **瞄準輔助（只給手把，預設開；滑鼠預設關）**【建議】：
  - 子彈磁性：子彈發射時，若在 ±6° 錐內、距離 ≤ 400 px 有可打的 hurtbox，把射角朝目標轉過誤差的 40%，不超過 3°；
  - 摩擦：準星距離目標 24 px 內，搖桿瞄準的旋轉速度降 25～30%；
  - 兩者都在設定頁可調 0～100%，玩家推搖桿的輸入永遠優先。
- **輸入延遲量測**：在實驗室（第 8 節）顯示「按鍵事件 → 槍口閃光產生」的毫秒數；目標 ≤ 1 個物理 tick（60 Hz 時 16.7 ms）。評估把 `physics_ticks_per_second` 提到 120（Godot 文件建議值）與 swapchain 2 的效益與 CPU 成本；**這是效能取捨，需要在最低規格機器上實測才決定**。
- **準星回饋**：每槍準星張開 `crosshair_kick`（第 1 節表）、命中標記、空槍搖晃、對準敵人時準星微變色（青 → 洋紅，亮度 ≤ 1.0）。

### Nest Egg 可採用做法（第 6 節）

- 輸入緩衝與取消窗口做成資料（動作 → 窗口、可取消的動作清單、是否需命中確認），土狼與跳躍緩衝的現有 `player_tuning` 值保留並納入實驗室。
- 手把瞄準輔助（磁性 + 摩擦）可調、預設只給手把；玩家輸入永遠優先。
- 實驗室顯示輸入延遲量測；120 Hz 物理與 swapchain 2 先在實驗室 A/B，再決定是否改專案設定。
- 緩衝窗口要「看不見」：實驗室提供「緩衝視覺化」除錯（按鍵時在動作時間軸上畫一條線）。

## 7. 敵人側的補充（不重複 ENEMY_FEEL_RESEARCH）

### 7.1 預兆與命中的可讀性

- **聽覺預兆**：聽覺反應比視覺快（170 vs 250 ms），預兆必須有聲音。做法有三種：每種攻擊獨立的提示音（Devil May Cry）、同類攻擊共用一個提示音以訓練一致反應（Furi：近戰一種、遠程一種）、用聲音區分長得像的攻擊（Street Fighter 3）。【引：critpoints】
  Nest Egg 建議：**按「攻擊類別」共用提示音**（近戰、投射、範圍、抓取、不可格擋），每類一個音高與音色；這和「每章敵人名單不重複」「動畫各自獨立」不衝突（動畫獨立，提示音按類別）。現有 `telegraph / beep / laser_flash / spin / vent / growl` 先歸類。【建議】
- **預兆時間**：格鬥遊戲社群的量測是前搖 ≤ 20 格幾乎不可能「看到後反應」、21～25 格只能對有明顯動作特徵的招式反應（來源為討論串，非官方，僅供參考）；ENEMY_FEEL_RESEARCH 3.3 的【經驗】值（小兵 12～24 格、重擊 24～48 格）要補一個限制：**會造成實質傷害的普通攻擊，前搖 ≥ 24 格（400 ms），並且要有聲音；前搖短於這個值的只能是「不致命的輕擊」**。【建議】
- **可格擋 / 可彈反的視覺語言**：可彈反的攻擊在命中前最後 0.18 s 給統一的標記（例如武器邊緣青白亮點，亮度 ≤ 1.0）＋提示音；不可格擋的攻擊用洋紅標記＋不同提示音。這與第 2 節的「盾輪廓亮窗口」搭配，形成完整的「攻擊—應對」語言。【建議】
- **命中玩家**的可讀性：受傷方向用邊緣短箭頭（80～120 ms），不用全螢幕閃。

### 7.2 擊殺獎勵感

- **擊殺階梯**：普通擊殺 = 局部頓幀 67～100 ms（敵人研究已有）＋ 擊殺音（第 4 節 `kill` 疊加層）＋ 1～2 個脫離零件；精英 = 加縮放脈衝與 −8 dB ducking；頭目 = 加慢動作（白名單）。
- **連殺（chain）**：2 秒內連續擊殺，擊殺音每次 +1 半音（上限 +5），HUD 只出一個小跳動（不出大字橫幅）；斷鏈就重置。重點是「聽得到」，不是「看得到」。【建議；升音數學引 Game Developer】
- **掉落與拾取**：掉落物以小弧線彈出（不是直接出現）、帶 0.3 秒短拖尾、0.4 秒後開始被吸向玩家，拾取聲依連續拾取升音（現有 `pickup`）。【建議】
- **屍體持久性**：沿用敵人研究（上限 8～12、烤成貼圖）。
- **清場時刻**：一個區域的最後一隻敵人被擊殺，給一次標點：慢動作 0.4× / 0.25 秒＋縮放脈衝 2%＋音樂 ducking；這是全遊戲少數允許慢動作的地方（見第 5 節白名單）。
- **過度擊殺（overkill）**：傷害 ≥ 生命 2 倍時多 1 個脫離零件與較長頓幀（+17 ms）；資料化。

### Nest Egg 可採用做法（第 7 節）

- 預兆提示音按攻擊類別共用（近戰／投射／範圍／抓取／不可格擋），可彈反與不可格擋有固定視覺語言；寫進敵人招式資料（`telegraph_class`），測試鎖定每個有傷害的招式都有 telegraph 類別與 ≥ 24 格前搖（輕擊例外需標註）。
- 擊殺階梯、連殺升音、掉落弧線、清場標點全部是資料事件，沿用第 4、5 節的音效與縮放；沒有新的特效種類。

## 8. 打擊感實驗室

### 8.1 為什麼需要、其他人怎麼做

**問題**：調手感是「改數字 → 重開 → 打一下 → 覺得不對 → 再改」，每輪幾十秒，且「同一個畫面」很難重現。現況連數字都散在程式裡（0.2 節第 1 點）。

**借鏡對照**：

| 來源 | 做法 | 我們借什麼 |
|---|---|---|
| Vlambeer〈The Art of Screenshake〉（及社群重做版） | 同一個遊戲 demo，**把每一項效果逐項打開／關閉**，讓觀眾看見每一項貢獻的差別；清單：動畫、射速、子彈大小、槍口閃光、命中特效、擊退、持久性、鏡頭 lerp、震動、命中暫停、武器後座等 | 實驗室的「效果清單開關」與逐項 A/B；每一項回饋都是一個可以單獨關掉的項目 |
| MoreMountains **Feel**（Unity，MMFeedbacks／MMF_Player，150+ 種回饋） | 回饋是「原子化的資料項」，組成一個播放器（PlayFeedbacks / StopFeedbacks），每項有時間設定、方向、**強度倍率**、**頻道**；編輯器內有測試按鈕、play mode 即時修改；Demo 有 Bounce「有／沒有回饋」對照 | 事件 = 一串回饋項；每項有 delay／duration／intensity；全域強度倍率；有／沒有回饋的對照模式 |
| **Unreal GameplayCue**（Lyra） | 一次性（burst）與持續（looping）兩類事件，欄位含粒子、聲音、鏡頭震動、力回饋，設計師不寫程式 | 回饋事件分「一次性」與「持續」（如持續光束、低血量暗角）兩類，同一份資料描述全部通道 |
| **Cinemachine Impulse** | 震動是帶訊號形狀、方向模式、傳播速度、衝擊半徑與距離衰減的「事件」 | 鏡頭事件的參數模型（第 3 節） |
| Godot 社群：**Sparkle**（疊在 inspector、預覽、複製貼上整段序列，Lite 免費、含完整 GDScript 原始碼）、**Juicee**（33 種效果、視覺化 graph editor、JuiceePlayer 節點、無障礙開關、MIT）、**Game Feel Flow — Expanded**（77 種效果、24 個組合含 `recipe_hit`／`recipe_death`／`recipe_camera_hit`、彈簧家族、逐項預覽按鈕、`intensity` 參數）、**saltmire-juice**（trauma 震動、命中暫停、閃白、池化傷害數字，MIT） | 現成的 Godot 外掛都是「節點／資源 + inspector 預覽」；沒有一個把「A/B、錄製回放、診斷數字、寫回資料檔」做在一起；而且都假設用它們的類別 | 概念借用（組合、強度、彈簧、預覽按鈕）；**不直接採用外掛**（我們已經有 `Fx`、`Sfx`、`LevelCamera`，引進第二套會變成兩套回饋系統，且第三方外掛的維護風險大）；原始碼可當實作參考 |
| **Figgy**（GameMaker）、**Hot Tuner**（Unity／Unreal） | Figgy：定義一次參數，**自動產生**即時編輯介面，**調整結果寫進專案資料檔、可放進版本控制**；Hot Tuner：在裝置上調滑桿，值回傳編輯器，**不會因停止遊戲而遺失** | 參數面板由 schema 自動產生；存檔回寫到資料檔；不因關掉遊戲而丟失 |
| 社群的確定性回放做法（Godot 無內建回放） | 在 `_physics_process` 記錄輸入並重送，搭配固定 RNG 種子；需要物理確定性，Godot 的完全確定性並不容易 | 回放分兩層：**事件回放**（預設）與**輸入回放**（進階），見 8.4 |

### 8.2 設計原則

1. **獨立工具場景，不是遊戲裡的作弊選單。** 與 `tools/screenshot.tscn`、`tools/rig_preview.tscn` 同一模式：`godot --path . res://tools/feel_lab.tscn`。理由：不污染遊戲、不進出貨包（確認 export 過濾排除 `tools/`）、可以用命令列參數載入情境（與 `--scenario=` 一致）。進階：遊戲內 F9 疊層可以之後再做，共用同一個面板。
2. **實驗室只改「資料」，不改程式。** 面板的每個參數都來自 `FeelParamSchema`（鍵、標籤、型別、最小、最大、步進、單位、預設、群組、tooltip），UI 由 schema 自動產生（Figgy 的做法）。新增一個回饋參數 = 在 schema 加一行，不寫 UI。
3. **實驗室使用真實的遊戲系統**（真的 `Player`、`Enemy`、`Fx`、`Sfx`、`LevelCamera`），不是模擬。所以前提是 F1（回饋資料化）完成：所有回饋走 `Feel.play(event_id, ctx)`。
4. **存檔是人為動作**：不自動儲存；儲存前顯示差異；寫入有備份。
5. **無障礙設定在實驗室也生效**，並有「預覽無障礙模式」開關（震動 0%、減少閃光）以確認降階後仍然可讀。

### 8.3 沙盒場景

- **場地**：平坦地面 + 兩側牆 + 一段平台（測試空中與垂直鏡頭死區）；背景用最簡單的暗色（手感不該被場景分散）；可切換「亮／暗」背景（測試閃光對比）。
- **靶子**（可重生，血量無限或重置）：
  - 靜態靶（按材質分：金屬／裝甲板、肉／有機、玻璃、木箱、能量盾）——測試材質命中回饋；
  - 移動靶（左右巡邏、可調速度）——測試瞄準輔助與前瞻；
  - 真實敵人：從敵人資料清單選（人形、觸手、機械、飛行各一個預設），重生鍵 `R`，死亡後 2 秒自動重生；
  - 預兆靶（炮塔式）：可設定攻擊類別（近戰、投射、範圍、不可格擋）、間隔、前搖長度——測試格擋、彈反、預兆音；
  - 壓力模式：一次生成 N 個敵人（測試粒子預算、發聲預算、頓幀疊加）。
- **玩家**：真的玩家場景，數字鍵換武器，`Tab` 或面板按鈕換近戰武器；可「無限彈藥」「無敵」（隔離手感與生存）。
- **快速重置**：`R` 重生全部、`T` 回到出生點；情境存成 JSON（`data/feel/scenarios/*.json`），例如「散彈 vs 三個肉靶」「完美格擋訓練」。

### 8.4 功能設計（逐項）

**A. 參數面板與預設組合（presets）**
- 左側樹狀：武器、近戰、格擋、鏡頭、聲音、畫面、輸入、敵人受擊。每個參數＝滑桿 + 數字框 + 「回復為已存值」小圓點 + tooltip（一句講重點，符合專案守則）。
- **預設組合**：一份完整設定 = 一個 `FeelProfile`。建議內建：`標準`、`克制`（震動、粒子、頓幀 ×0.6）、`厚重`（頓幀、kick、ducking ×1.3）、`街機`（誇張，僅供對照）、`無障礙`（震動 0、閃光降階、縮放脈衝關）。Preset 是「覆蓋層」：`基底 + preset + 實驗室暫改`，所以可以只存差異、可以疊加。
- **「被哪些事件使用」**：選到一個參數，下方列出所有引用它的回饋事件（由 `FeelProfile` 載入時建立反向索引，不是人工維護），點事件就在沙盒觸發一次。這要求回饋事件裡的欄位明確引用 schema 鍵（或事件本身就是參數的擁有者；兩種設計在 F1 決定）。同時列出「未被任何事件使用」的參數，方便清理。
- **事件觸發按鈕**：每個回饋事件旁有 ▶ 按鈕，可用「模擬情境」直接播放（例如 `hit.melee.metal`、`parry.perfect`），不必真的去打。

**B. A/B 比較**
- 兩個槽 A、B，各存一份完整參數快照。`Q` 切換（瞬間切換，可在戰鬥中切）；「依序播放」按鈕：同一事件先用 A 播，1.2 秒後用 B 播，並在畫面角落標示 A／B。
- **盲測模式**：隨機決定當前是 A 或 B 而不顯示，連續 10 次，每次問「這個比較好嗎」並記錄選擇，最後顯示統計——用來對抗「我知道這是新的所以覺得比較好」。
- **為什麼不做左右分割畫面**：`Fx` 是單例、頓幀會改 `Engine.time_scale`（全域），兩份回饋同時在同一個引擎裡跑會互相干擾；做得出來但要為了這個工具重構成多實例，不值得。替代方案：**對照圖（contact sheet）**——在固定時間點（例如命中後 0、33、67、100、167、250 ms，用不受縮放的時間）擷取 A 與 B 各 6 格，拼成一張對照圖存到 `pm/Nest-Egg/images/`，直接符合專案「一張票完成要有截圖」的流程。這是延伸功能，排在最後。

**C. 錄製與回放**
- 兩層回放：
  1. **事件回放（預設，必做）**：錄下的是「回饋事件流」——`{t, event_id, position, normal, direction, intensity, material, killed, ...}`——與靶子配置。回放時用**另一份參數**重新播放同一串事件。因為回饋只改表現不改模擬，回放永遠一致；A/B 比較就是拿同一份錄影套兩組參數。限制：頓幀本身會影響模擬時間（延遲後續事件），事件回放用「錄下的時間軸」排程，因此與頓幀長度無關。
  2. **輸入回放（進階）**：錄輸入（在 `_physics_process` 記錄）＋ RNG 種子＋ 初始狀態，重新跑整場戰鬥；需要物理確定性（Godot 完全確定性不保證），而且頓幀、擊退、前搖等參數一改，模擬就分歧，所以只用於**回歸測試**（同參數同輸入 → 診斷數字不得超出預算），不用於調參比較。
- **種子化的亂數**：目前粒子、音高抖動都用全域 `randf()`。為了讓回放看起來一樣，`Feel` 提供可設種子的 `RandomNumberGenerator`，`Fx`／`Sfx` 的隨機改走它（遊戲中種子隨機，實驗室中固定）。
- 錄檔存 `user://feel_lab/records/*.json`；挑選的可匯出到 `data/feel/replays/`，供煙霧測試載入並檢查預算（例如峰值震動、同時發聲層數、活躍粒子）。

**D. 診斷數字（F3 切換，更新頻率 10 Hz，預先格式化字串，不每影格配置）**

| 類別 | 顯示 |
|---|---|
| 時間 | 目前時間縮放、全域頓幀剩餘 ms、局部凍結節點數、最近一次頓幀長度、近 5 秒最長頓幀 |
| 鏡頭 | trauma、當前位移像素（峰值與瞬時）、kick 向量、縮放脈衝值、前瞻偏移 |
| 粒子 | 兩個粒子場的活躍數／容量、光源池使用數／10、衝擊波環使用數／5、電弧數 |
| 聲音 | 活躍發聲槽／24、近 1 秒事件數與層數、被丟棄層數、各匯流排當前 ducking dB、輸出峰值 dB |
| 畫面 | 最大與平均亮度（每 0.25 秒對縮小畫面取樣）、峰值亮度像素比例、全螢幕閃光頻率（次／秒，> 3 變紅） |
| 輸入 | 輸入事件 → 槍口閃光延遲 ms（`Time.get_ticks_usec` 差）、緩衝命中次數 |
| 效能 | 影格時間 ms、物件數 |
| 事件日誌 | 滾動清單：時間、事件 id、強度、展開後各通道的數值；**時間軸視圖**（像 MMFeedbacks 的時間軸）：每個事件一排，每項回饋一條橫條（delay、duration），被預算丟棄的以灰色顯示 |

**E. 存檔與回寫**
- 實驗室編輯的是記憶體中的 `FeelProfile`；「儲存」按鈕寫回 `res://data/feel/<profile>.json`（只在編輯器環境或開發版允許，`OS.has_feature("editor")`；匯出版唯讀）。
- 寫入規則：先驗證（範圍、已知欄位、引用的 id 存在），失敗時列出「檔案 + 事件 id + 欄位」且不寫；寫入前顯示**差異預覽**（舊值 → 新值）；**原子寫入**（寫暫存檔再改名）並保留 `.bak`；鍵值順序固定（讓 git diff 乾淨）；只有被改過的 preset／事件才重寫。
- 附「複製變更為文字」按鈕，方便貼進票留言（「震動 0.46 → 1.0 px」）。
- 為什麼用 JSON 不用 `.tres`：專案的資料大多是 JSON／`.tres` 並存；回饋資料要被實驗室頻繁寫回與被人類讀 diff，JSON 最合適，而且載入端要做驗證與 fallback（專案守則）。`.tres` 保留給 `WeaponData`／`PlayerTuning` 這類編輯器資源，由 `FeelProfile` 以 id 引用，不複製。

**F. 容錯與測試**
- 載入失敗：記錄具體檔案與鍵，退回內建預設；實驗室的紅色警示列表顯示。
- 測試（供各票共用，進煙霧測試或 `tests/suite`）：每個 schema 鍵都有預設與範圍；每個回饋事件引用的 sound id、粒子類型、材質存在；縮放脈衝只出現在白名單事件；每個預設組合的所有值都在範圍內；回放檔載入後各預算不超標。

### 8.5 實驗室的建議開發順序

先做 F1（回饋資料化）→ **馬上做實驗室最小版（沙盒＋參數面板＋存檔回寫）**，之後每張手感票都用它調參並把截圖放進票；診斷、A/B、回放排在中後段。理由：手感票的驗收本質是「調到對」，沒有實驗室就是盲調。

### Nest Egg 可採用做法（第 8 節）

- 獨立場景 `tools/feel_lab.tscn`；使用真實 Player／Enemy／Fx／Sfx／LevelCamera；情境存成資料。
- 參數由 `FeelParamSchema` 自動產生面板；presets 為覆蓋層；反向索引「被哪些事件使用」由資料載入時建立。
- A/B = 兩槽快照＋瞬間切換＋依序重播＋盲測；不做同畫面分割（`Fx` 單例與全域頓幀）；對照圖作為延伸。
- 回放分事件回放（調參用）與輸入回放（回歸測試用）；亂數種子化。
- 診斷面板（時間／鏡頭／粒子／聲音／畫面亮度／輸入延遲／事件時間軸）10 Hz 更新、零配置。
- 存檔 = 驗證 + 差異預覽 + 原子寫入 + `.bak` + 固定鍵序；匯出版唯讀。
- 不採用第三方 juice 外掛，只借概念。

## 9. 票的拆分建議

### 9.1 母票

**【母票】打擊感（Game Feel）**
- 需求：玩家的槍、近戰、格擋、鏡頭、聲音、畫面、輸入與擊殺回饋達到「克制但有力、可資料調整、可無障礙關閉」，並有一個實驗室讓開發者即時調參。依據本文件。
- 共通驗收（每張子票都要滿足，不另寫進子票）：回饋參數以資料表達；缺漏或損毀時記錄「檔案＋事件 id＋欄位」並退回預設；每個新增參數有 tooltip；不引入每影格配置；粒子／聲音／光源有預算上限並進診斷；「減少閃光」與新的「畫面震動」設定都生效；該票範圍的測試通過且截圖放進票（依專案流程）。
- 與其他票：敵人受擊（ENEMY_FEEL_RESEARCH 已實作）不重做，只接入同一個 `Feel` 入口；近戰武器資料欄位與 `design/14-combat-variety` 對齊。

### 9.2 子票（建議編號 F1～F16 為暫定代號，開票時換成實際 NE 編號）

### 9.3 建議順序與理由

1. **第 0 階段（地基與工具）**：F1 → F2；緊接著 L1 → L2 → L6（實驗室最小版）。理由：之後所有手感票的驗收都是「調到對」，沒有資料化與實驗室就是盲調；F1 同時修掉 0.2 節的三個程式問題（`duration` 無效、數值散落、強度單位）。
2. **第 1 階段（全域骨幹）**：F4（頓幀管理）、F3（鏡頭）、F7（聲音）——三者是所有後續回饋的共同底座，F5～F11 都依賴它們。
3. **第 2 階段（玩家武器與近戰）**：F5、F6、F8（槍）；F9 → F10（近戰）；F11（格擋，依賴 F3、F4、F7、F9）。槍與近戰兩條線可平行。
4. **第 3 階段（輸入、畫面、敵人側）**：F12、F13、F15；F14 視需要。
5. **第 4 階段（實驗室補完）**：L3 → L4 → L5。**注意**：L3 的診斷計數器要求各 F 票「順手註冊」，所以 L3 的最小版（計數器註冊介面）應該在第 1 階段就先放進 F1 的範圍，完整面板最後再做。

### 9.4 開票前待使用者決定

1. 實驗室只做獨立場景，還是也要遊戲內 F9 疊層？（建議先獨立場景。）
2. 回饋資料格式：JSON（建議）還是 `.tres`？
3. 傷害數字（F14）要不要做、預設開還是關？
4. 「畫面震動」滑桿預設 100% 還是預設降低（例如 70%）？
5. 是否準備請音效師提供 `hit_transient`／`sub_thump` 等素材，還是先全部用程式合成？
6. 120 Hz 物理的 CPU 成本是否可接受（需要先知道最低規格機器）。
