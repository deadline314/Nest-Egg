# 存檔編碼耗時

撿起故事物品、確認區域結果與繼續遊戲都要檢查完整的存檔。地圖目錄原本會在同一次交易多次整理，NE-382 已共用一次作者資料。後續量測顯示，把已知由遊戲剛產生的 JSON 再當成外來檔解析，仍占用一部分主執行緒時間。較後章節的存檔包含更多區域、任務和狀態，這筆開銷會一起成長。

## 編碼與檔案邊界

遊戲剛擷取的資料依既有欄位與輸入範圍檢查，序列化後仍重新解析資料本體，讓數值和型別與實際讀檔一致。外層由同一處建立，使用包含跳脫字元的實際 UTF-8 位元組數檢查 4 MiB 上限。讀取磁碟、既有備份與恢復檔繼續檢查外層版本、檔案大小、JSON 深度、校驗碼及完整資料。字串內的引號、跳脫和括號由支援的掃描規則跳過。遇到殘留引號或掃描無法確認時走原有逐位元組檢查。

準備的候選仍要檢查當下的實際存檔、背包與物品。成功寫入後只交付一次。存檔輪替、失敗還原、可見提示及通知觸發保持同一個擁有者。對話前的進度仍由該對話自己的進入點管理。

## 驗收

以更新前後實際第一章與第六章存檔測量同樣的資料。逐位元組對照解析後的資料與型別。額外驗證 Unicode、跳脫、合法空容器、過深輸入、資料過大、格式未知及舊備份。無焦點畫面實際走到當舖文件上，檢查移動持續、擁有權、世界來源的消耗、額外通知造成的變動、暫存拒絕與檔案輪替失敗。原生幀時間與純編碼時間分開記錄。
