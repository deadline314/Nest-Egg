# 受影響測試的資源掃描範圍

2026-11-11，NE-283。

目前選擇器會掃描 Git 中的正式與未追蹤檔案，卻不理會 Godot 的忽略目錄。工作目錄內為交付保留的程式副本因此進入相依圖，膨脹使用者數量，觸發共用核心的搜尋截斷，反而漏選測試。副本增加不能成為縮小測試範圍的原因。

實際隔離：同一批六份近戰產品檔案、相同內容，只移除 `.gdignore` 目錄中的掃描候選，選組由 21 變成 35。MeleeModule 的圖上使用者由 74 回到 7，MeleeMove 67 回到 9，PlayerVisual 61 回到 15；補回十四組，包含流程、經濟、武器／角色舞台與補給。當時正式類別的最後提供者仍為正式來源，不能把本次具體漏選原因寫成已發生類別覆蓋。

決策：掃描範圍依祖先目錄的 `.gdignore` 決定，涵蓋已追蹤與新檔案；不硬寫工作目錄名字。Godot [4.7 專案組織說明](https://docs.godotengine.org/en/4.7/tutorials/best_practices/project_organization.html#ignoring-specific-folders)定義這個標記用於整個目錄，內容不是忽略模式清單。已忽略目錄內新增證據不改變相依圖；正式可見目錄的忽略邊界變更則保守跑完整測試。

可見來源若宣告相同類別，不能依檔案列舉順序靜默覆蓋，必須指出類別與衝突路徑並拒絕選擇。重複呼叫時只使用該次檔案集合，不沿用先前集合的成員快取。保留既有深度、核心截斷門檻、錯誤過濾及已知失敗規則。

驗證以臨時 Git 專案重現：真實的間接相依、三十一份忽略目錄副本、新增正式程式、忽略邊界增刪與重複類別。先保留舊工具紅燈，再以同一輸入重跑。正式完整回歸與同時進行的近戰、局部光影交付合併跑一次，保存產品來源前後雜湊並明列範圍。
