# 光影設計：沉重、壓抑的雨夜

> 來源：2026-10-02 使用者提出「整個遊戲可以有完整的光影設計，請參考業界最佳實例」「整體的渲染跟場景應該要陰沉一點，遊戲希望整體沉重一點」。確認：壓抑程度為**重度壓抑**；先做光影，再做內容（見 `design/09-content/DESIGN.md`）。

## 目標與調性

- 整個畫面**預設是暗的**：光是稀缺資源，一盞燈就是一個光池，光池之外的世界吞掉細節。
- 霓虹保留，但像是「黑暗裡殘存的東西」：飽和度與亮度壓低，只有發光體本身是亮的。
- 重度壓抑不能犧牲公平性：**敵人、子彈、危險物永遠看得見**（見「可讀性守則」），暗的是環境，不是資訊。
- 每個區段有各自的色彩與明暗，越深入越暗，頭目戰最壓抑，用光推進劇情情緒。

## 現況與問題

| 現況 | 問題 |
|---|---|
| 光源全是加法混合的點光源，沒有環境光，畫面整體偏亮 | 沒有「暗」的底，光源只是在亮的畫面上再加亮，沒有明暗對比 |
| 背景（天空、樓群）`light_mask = 0`，完全不受光 | 前景暗了背景還是亮的，空間感與壓抑感出不來 |
| 所有區段共用同一組色彩與霧 | 沒有色彩腳本，情緒沒有起伏 |
| 角色與地形是平面貼圖 | 受光沒有方向感與立體感 |
| 沒有後製調色、暗角、顆粒 | 畫面乾淨、數位感重，缺少「沉」的質感 |
| 光源無預算管理、無品質分級 | 加光源會直接拖累效能 |

## 架構

由下而上共六層，每層獨立、可單獨開關，由「區段光影設定」統一驅動。

### 1. 環境光與區段光影設定（`LightingProfile`）

- 以 `CanvasModulate` 設定環境光，所有不是自發光的東西（地形、角色、背景）都乘上這個顏色，光源再疊加在上面。
- 光影設定是資料檔（`data/lighting/*.tres`），欄位：環境光顏色與強度、霧顏色與濃度、調色（飽和度、對比、陰影／亮部色調）、暗角強度、顆粒強度、泛光門檻與強度、雨量、背景暗化比例。
- 關卡資料列出「區段」：從某個 x 座標開始套用哪個設定、過渡距離多長。玩家跨過邊界時所有數值平滑插值，不會跳變。
- 事件可以暫時覆蓋設定（停電、警報、閃電），結束後插值回區段設定。

### 2. 光源分級與預算

| 等級 | 用途 | 陰影 | 例 |
|---|---|---|---|
| 主光（key） | 決定場景方向與氣氛，一個區域只有 1～2 盞 | 有 | 路燈、大型霓虹、頭目機庫警示燈 |
| 輔光（practical） | 場景裡看得見的光源，做出光池 | 視距離 | 小招牌、窗光、機台指示燈 |
| 角色光 | 保證主角永遠可讀，範圍小、能量低 | 無 | 凜的柔光 |
| 戰鬥光 | 槍口、爆炸、命中、技能，壽命極短 | 無 | 光源池循環使用 |

- 預算：同時啟用的陰影光源上限（預設 4）、點光源上限（預設 24）；鏡頭外的光源停用；超過預算時優先保留離玩家近、能量高的。
- 壞掉的燈：部分場景燈會閃爍或整盞熄滅，用不亮來說故事（也順便省光源）。

### 3. 背景與景深

- 背景各層乘上「背景暗化」，越遠越接近霧色（大氣透視），不再 `light_mask = 0` 而完全不受光。
- 天空只留地平線的一抹洋紅，其餘壓成深藍黑；樓群窗光減半、更疏。
- 前景加上更暗的剪影層（管線、鋼樑、雨簾），壓住畫面邊緣、增加縱深。

### 4. 體積光、光錐與霧

- 場景燈、探照燈、無人機與砲台有光錐（加法混合的漸層多邊形），雨與霧在光錐裡更亮。
- 霧受附近光源染色：光源周圍的霧團變成光源的顏色（光暈），光池之外的霧偏冷灰。
- 地面反光：路燈與霓虹在地板頂面形成一條輕微晃動的亮帶；不畫進地面的剖面（BG-20）。

### 5. 法線貼圖

- 角色零件與地形帶法線貼圖（`CanvasTexture`），光從哪來邊緣就亮在哪，凜的盔甲、金屬地板會有立體感。
- 法線貼圖由工具從現有貼圖自動產生（亮度當高度、透明邊緣做斜角），可被手繪的法線貼圖用同名檔案取代。
- 缺法線貼圖時照常顯示平面貼圖，不報錯。

### 6. 後製與動態光影

- 單一全螢幕後製 pass：調色（去飽和、對比、陰影偏冷、亮部偏暖）、暗角、顆粒、邊緣色差，一次完成。
- 泛光門檻拉高，只有真正的發光體（霓虹、子彈、爆炸）會暈開，環境不會霧濛濛。
- 戰鬥動態光影：爆炸瞬間整個環境光被「閃」亮一下、命中與擊殺的點光、低血量時暗角收緊並帶紅色脈動、敵人攻擊預兆的紅光。
- 閃電：不定時的環境光閃爍，配合遠方雷聲；閃電瞬間畫面輪廓全部亮出來，是難得能看清整個場景的時刻。

## 暗場可讀性守則（重度壓抑下維持公平）

1. 敵人、敵方子彈、危險物（尖刺、雷射柵欄、爆炸範圍預警）本身是**自發光**或帶輪廓光，不依賴環境光。
2. 玩家角色永遠有最低亮度：角色光與輪廓光，不會被環境光壓到看不見。
3. 可站立的平台頂面一律有亮邊（`TERRAIN_TOP`），跳躍落點不會看不清。
4. 區段的環境光有下限（測試檢查：最暗的區段也要讓玩家輪廓與平台邊緣達到對比門檻）。
5. 設定裡有「亮度」滑桿與「光影品質」，讓對暗場不適應的玩家自行補償；預設值就是設計的重度壓抑。

## 效能預算

- 目標：Forward+ 與 Compatibility 都維持 60 FPS（Compatibility 沒有泛光，其餘效果優雅降級）。
- 陰影光源 ≤ 4、點光源 ≤ 24；光錐、霧、倒影用批次繪製，不新增節點；後製是單一 pass。
- 光影品質三檔（高／中／低）：高＝全部；中＝關閉顆粒與色差、陰影 PCF 降級；低＝關閉體積光與法線貼圖、陰影光源 ≤ 1。
- 所有光源參數不在每影格配置新物件；光源以池或場景內固定節點管理。

### NE-95 原生複驗（2026-10-08）

上列 Arc B580 數據與平面圓盤觀察保留為歷史，不能與本次 llvmpipe 同機量測直接互比。NE-95 的原生 Forward+ 複驗修正兩項退化：環池改用共用 2×2 ImageTexture，避免 Placeholder UV 將衝擊波畫成偏移四分之一圓弧；爆炸傷害節點不再疊畫舊圓盤，雙陣營傷害保留，既有 Fx 配方／flash／環境閃光／音效只播放一次。未重產圖集或改全局光影與角色設定。

性能使用 light_audit --no-capture、seed95、未縮放牆鐘差值、相同主機／解析度／敵人／武器／品質串行對照；單次結果有較慢配置，未驗收性能無退化。原生兩章、三檔、死亡／實際油桶連續圖與完整條件見 NE-95 票與 attachments。人工實玩、25 profile 泛光與實體 GPU 驗收仍待辦。

### 爆炸改成平塗分層的火球，並逐份光影設定巡檢（NE-95，2026-10-11）

參考 Leyla In Veil 官方截圖裡的爆炸（見[第一章場景光影與視覺優先序](../20-campaign-experience/SCENE_LIGHTING_REVIEW.md)）：大塊、邊緣分明的橘黃火球，中心近白，暖光照亮整個房間與地面。只借手法，不照抄像素風：Nest Egg 的美術是賽璐璐，所以火球用硬邊的平塗色塊。

原本的爆炸是幾團柔邊的光疊加：顏色相加後中心糊成一片白，沒有形狀；0.1 秒後只剩一小團橘色，0.3 秒後是一抹暗紅，還會沉到地板底下。白色面積隨光影設定的泛光強弱差很多（占畫面 0.19%～2.52%）。

現在的組成（由後到前）：

| 層 | 樣子 | 時間 |
|---|---|---|
| 濃煙 | 深灰的硬邊雲團，往上飄 | 火球退掉才露出來，約 1.1 秒 |
| 外圈 | 橘色雲團，撐開後停住，最後才轉暗退場 | 約 0.46 秒 |
| 中層 | 亮黃雲團 | 約 0.3 秒 |
| 白熱心 | 小小一團近白，加一圈短暫的光暈 | 0.1～0.16 秒 |
| 地面反光 | 貼地的爆炸在地上留一道壓扁的暖光 | 跟火球一樣久 |
| 火花、餘燼、碎片、衝擊波 | 沿用 | 沿用 |

- **層與層顏色不相加**（一般混合），所以中心不會因為疊了幾層就變白；三層的明度拉開（白熱心最亮、中層次之、外圈最暗），彩度被調色壓低的光影設定（白塔、轉運站、住宅、夾層）裡仍看得出層次。
- **貼地的爆炸只往上半邊炸開**（爆炸中心離地面不到半徑的 0.75 倍算貼地），火球與光暈不沉到地板底下；半空中的爆炸四面炸開。
- **照亮四周的光跟火球一樣久**：環境光被帶亮的幅度降低（半徑 64 的油桶從 0.5 降到 0.32），時間從 0.3 秒拉長到跟火球相同；另有一盞以爆炸為中心的暖光照近處的地面與角色。火球還亮著的時候四周不會先暗掉。
- 爆炸的顏色由呼叫端給（油桶與榴彈是暖黃、自爆兵的連鎖是青色），三層的顏色從它推出來；暖色的外圈往紅偏一點。
- 粒子多一個「變色前停留的比例」，圖集多兩格硬邊雲團；粒子數每次爆炸從約 23 顆變 27 顆，仍是固定容量、不建立節點。

巡檢工具 `tools/vfx_exposure_probe.tscn`（原生 Forward+）在每一份光影設定下各演一次：步槍槍口、敵人死亡、真的打破油桶後的爆炸（四個時刻）、半空中的小爆炸與青色爆炸；`tools/vfx_exposure_sheet.py` 算每張圖的全白比例並拼成一覽圖。`--level=<關卡>` 改在真實關卡演同一套，`--stress=<n>` 量連續爆炸時每影格的實際間隔。門檻：離特效 2 倍半徑以外的全白像素 ≤ 0.5%（整個畫面沒有被洗白）、主角與旁觀敵人身上 ≤ 5%、爆炸 0.33 秒後整張畫面 ≤ 0.5%。

結果（Arc B580，26 份光影設定 × 9 個時刻＝234 張）：沒有一張超過門檻；爆炸最亮那一格的全白面積從 0.19%～2.52% 收斂到 0.59%～1.27%；特效以外的全白最高 0.04%，主角身上最高 2.5%。光影品質「低」抽四份設定重跑也全過。連續 72 次爆炸（每 0.25 秒同時 6 個）時每影格間隔的中位數 6.63 → 6.73 毫秒。

新增一種爆炸或改火球之後，重跑這支工具並看一覽圖；新增光影設定也一樣。低彩度的光影設定會把火球的暖色壓成灰粉色（明暗層次還在），要不要讓發光的特效在這些場景保留顏色，屬於全域調色（NE-66）。

## 輪廓對比量測與光影預設的場景預覽（BG-13、BG-14，2026-10-04）

- 量測類別 `tools/contrast_probe.gd`：對比 = (內 − 外) / (外 + 0.02)，取「亮部（第 90 百分位）比周圍亮」與「身體比周圍暗（剪影）」較大者。背景平均亮度 ≥ 0.12 時剪影量身體暗部（第 25 百分位，角色瘦長只占量測框一部分），更暗時用中位數（避免黑對近黑被放大）。門檻：玩家 0.6、地面邊緣 1.0、敵人 0.45。
- 暗場可讀性量測：`godot --path . res://tools/readability_check.tscn`（兩章的每個區段）。
- 光影預設場景量測：`screenshot.tscn -- --out=<資料夾> --scenario=lighting_scenes [--lighting=<id>] [--scene=<id>]`，對應表 `data/lighting_preview/scenes.json`（預設 → 場景背景）。新增光影預設時在對應表加一行即可。

## 角色受光與過曝（NE-213，2026-10-07）

使用者回報主角「有時候」整顆頭變成一團白、光暈很大。在 Forward+（軟體 Vulkan）重現：**主角的頭靠近場景燈（跳起來、爬梯子貼著天花板燈）時，白色頭髮與臉的亮度達到數倍的 HDR 值，被泛光暈成一團**；用 `exposure_lamp` 量測，頭部範圍全白像素比例約 13%，峰值 15。

原因（逐項排除過的結果）：
- 玩家自己的光、環境光補光、閃光能量上限（NE-213 第一次修正）都有效，但不是主因：關掉玩家的光、關掉泛光、降低頭的 modulate，團白依舊。
- 主因是**預設的受光公式把單盞光的貢獻直接加在白色零件上**：場景燈能量 1.5（區段可到更高），貼近時白色零件的亮度遠超過泛光門檻；暗場景的補光倍率（最高 4 倍）還會讓角色的受光基底更高。
- 角色之前沒有任何機制限制「光對角色的總亮度」，預算估計（`character_exposure`）只算了環境光、玩家的光與固定預留，沒有算到實際的燈。

做法：角色（零件與武器）共用 `art/shaders/character_light.gdshader`：
- 單盞光對角色的貢獻用 tanh 壓在 `light_cap` 以內（亮度小時幾乎不變），上限依場景亮度由 `LightKit.character_light_cap_for` 決定（亮場景 0.2、暗場景 0.5）。
- 光的貢獻除回補光倍率：補光只用在環境光，不放大燈光。
- 預算模型：白色零件峰值 ≈ 環境光 × 補光 + min(玩家的光, 上限) + 一盞燈（上限）。每份光影設定由 `ExposureSuite` 檢查在預算＋容許範圍內。
- 發光層（霓虹）不受影響：它是加法混合、不受光的獨立層。
