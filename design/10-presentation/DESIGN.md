## 一、過場動畫

### 目標

讓劇情有「畫面」：每一章有一個開場、一個頭目登場、一個結尾，外加零星的小演出（記憶閃回、右臂雜訊、角色第一次現身）。畫面由程式繪製的多層場景＋骨架角色＋頭像構成，不依賴外部影片。

### 導演腳本

演出是資料檔（`data/cutscenes/*.json`），不是程式。每段演出是一串依序執行的「步驟」，步驟之間可以並行（`with`）。

| 步驟 | 作用 |
|---|---|
| `scene` | 換背景場景（見下表），可帶淡入 |
| `camera` | 鏡頭推、拉、搖、停（相對場景座標），可緩動 |
| `actor` | 放置、移動、轉向、播動作的角色（骨架或頭像剪影） |
| `reach` | 近／遠手到舞台點、人物相對點或具名道具來源點；可緩入、換點與收手，保持骨長 |
| `prop_move`／`prop_hold`／`prop_release` | 具名道具移動／轉動、真掌心接觸後握持、放下；鉸鏈子件只轉動 |
| `prop`／`prop_visible` | 有限材質狀態與可見性；隱藏局部效果即停止更新 |
| `say` | 一句台詞（講者、文字、說話風格：普通、低語、吼叫、雜訊） |
| `fx` | 雨量、閃電、震動、閃白、雜訊、暗角脈衝、泛光 |
| `sfx` | 音效 |
| `title` | 標題卡（章節名、頭目名、日期時間） |
| `wait` | 等待 |
| `letterbox` | 上下黑邊的大小 |
| `transition` | 轉場（見轉場一節） |

- 任何時候按「略過」鍵（ESC）可以跳到結尾；已看過的演出重來時不重播（沿用現有規則），也可從設定選擇「每次都略過」。
- 台詞沿用劇本資料的講者與頭像；演出檔只引用文字，不重複儲存。
- 道具指令只接受有限欄位及具名ID，沒有任意節點路徑／屬性執行。來源像素接點、圖集鉸鏈、scene初值、握持／放下順序與範例見[廚房接觸契約](../20-campaign-experience/KITCHEN_PROP_CONTACTS.md)；物件動作不發任務或經濟結果。
- 演出總台詞上限 16 句；每次畫面變化之間最多 3 句，避免變成長篇大論。

### 過場的操作鎖與生命週期

- 動畫、劇情對話、畫面轉場與阻擋式章節卡共用 `GameplayLock`，不各自保存與還原 `SceneTree.paused`。通訊與非阻擋的開場章節標題維持原本可操作的行為。
- 新增阻擋演出時，在 owner 加入場景樹後呼叫 `GameplayLock.acquire(owner, mouse_mode)` 保存 token；完成時先 `release(token)`，再發出完成訊號。owner 離開場景樹會自動釋放，重複釋放也安全。
- 重疊演出只在第一把鎖保存暫停與滑鼠狀態，最後一把鎖釋放才還原。換畫面用 `GameplayLock.set_base_paused(false)` 更新目的畫面狀態，保留還在播放的鎖；`UiKit.set_cursor_visible` 同樣會更新目的畫面的游標需求。
- 玩家與載具在讀取事件及輪詢操作前檢查鎖定；過場開始清除動作緩衝，結束清除過場按鍵狀態。Esc 跳過、點擊推進對話與轉場加速維持原有操作。
- 動畫內的 `Transition.cover` 傳入演出 owner；跳過或移除動畫時用 `abort_owned` 清掉它自己的轉場。轉場的代次檢查防止已中止的協程重新暫停遊戲或清掉新的轉場。

### 角色演出

- 凜、監管者與其他有骨架的角色，直接用骨架（同遊戲裡的外觀、同一套動畫）放大擺在場景裡。
- 沒有全身骨架的角色（遠景或只有聲音的人）用「剪影＋頭像框」呈現，頭像說話時輕微呼吸與切換表情。
- 頭像框的演出：切入時從側邊滑進、說話時輕輕上下浮動、換人說話時淡出再淡入、雜訊風格時加色散與抖動。

### 演出資料格式

演出寫在章節劇本（`data/story/chapter_XX.json`）的 `scenes`，`mode` 為 `animated`，內容是 `steps` 陣列，每一步有 `do`（動作）與該動作的欄位。場景（舞台）放在 `data/cutscene/stages/<id>.json`，由圖層組成。座標都是 640×360 的舞台座標。

| do | 欄位 | 說明 |
|---|---|---|
| `scene` | `id`、`fade`、`pos`、`zoom` | 換舞台；第一個場景自動從黑幕淡入 |
| `letterbox` | `on`、`time` | 上下黑邊 |
| `camera` | `pos`、`zoom`、`time`、`wait` | 推拉搖，`wait` 為 true 時等鏡頭到位 |
| `actor` | `id`、`kind`（骨架外觀）或 `portrait`（剪影）、`pos`、`facing`、`pose`、`weapon`、`scale` | 放置角色 |
| `pose` / `face` / `remove` | `id`… | 改動作、改面向、移除 |
| `move` | `id`、`to`、`time`、`pose`、`then`、`wait` | 走到某處 |
| `say` | `speaker`、`text`、`style`（normal／whisper／shout／noise）、`auto` | 台詞；`auto` 秒數後自動往下，否則等玩家推進 |
| `narrate` | `lines`（1 到 3 行）、`time` | 畫面中央的旁白（氣象預報、系統訊息） |
| `title` | `text`、`sub`、`time`、`color` | 標題卡 |
| `fx` | `kind`（shake、flash、lightning、noise、tint、rain）、`time`… | 特效；「減少閃光」時自動降級 |
| `sfx` | `id`、`volume` | 音效 |
| `wait` | `time` | 等待 |
| `fade` | `to`、`time`、`color` | 黑幕或白幕 |
| `transition` | `kind`、`mode`（cover／reveal） | 使用全域轉場 |
| `end` | | 提早結束 |

圖層種類：`gradient`、`skyline`、`rect`、`poly`、`glow`、`sprite`、`rain`、`grain`、`text`、`stripes`；共通欄位 `parallax`（視差，0 固定在畫面）、`depth`（back／front）、`alpha`、`additive`。

場景的整體欄位：

| 欄位 | 說明 |
|---|---|
| `mode` | 固定為 `animated` |
| `then` | 結束後立刻接著播的場景 id（只能接過場或動畫過場，不可形成迴圈）。玩家按 Esc 時整串一起略過；接續的場景若本輪已看過就不再播 |
| `overlay` | 為 true 時不放舞台、不蓋黑底，直接疊在遊戲畫面上（右臂雜訊、燈幕警報這類短演出） |

動畫過場放在 `data/story/cutscenes_ch1.json`、`cutscenes_ch2.json`：只有 `scenes`，以 `for_chapter` 標明所屬章節，不會覆蓋章節資訊。原本的靜態劇本（`prologue`、`boss_intro`、`epilogue`、`c2_*`）保留為文字稿，動畫版的每一句台詞都要涵蓋文字稿（系統旁白除外），由測試比對。收集品與關卡的觸發改綁動畫版的場景 id。

守則：整段最多 16 句台詞，連續台詞之間最多 3 句就要有演出或鏡頭；單句不超過 56 字。壞掉的步驟只會記錄「場景 id 第 n 步」並略過。

## 二、轉場

| 轉場 | 外觀 | 用在 |
|---|---|---|
| 淡入淡出 | 黑或白 | 一般切換、演出開頭結尾 |
| 光圈 | 圓形縮到主角身上或從主角身上展開 | 進入關卡、從檢查點重生 |
| 掃描線 | 一條亮線掃過，畫面被掃進來或掃出去 | 主選單與背包、開新遊戲 |
| 雜訊溶解 | 色散、橫向切片位移、數位方塊 | 死亡後重來（「回溯」） |
| 電梯門 | 左右兩扇門關上、打開，樓層數字跳動 | 第一章接第二章、章節切換 |
| 百葉 | 橫向百葉窗 | 結算畫面進出 |

- 轉場是獨立的全域服務：任何畫面都可以「蓋住」→ 換內容 → 「揭開」，期間遊戲暫停、輸入鎖定、略過鍵可縮短。
- 死亡轉場要快（約 0.8 秒），不能拖累重來；顯示一行小字「NEST 回溯紀錄 #n」（見 [FORESHADOWING.md](../04-story/FORESHADOWING.md) F19）。
- 設定裡有「減少閃光」時，雜訊與閃白降級成淡入淡出。

## 三、介面視覺語言

### 原則

1. **系統介面本身是角色**：它是凜眼裡的義體介面，有切角、有掃描線、有輕微的雜訊，劇情緊張時介面會破損。
2. **形狀簡單、顏色極少**：深藍黑面板、青色線條為主、洋紅為警示與強調、黃色只給金錢與提醒。
3. **資訊靠近事情發生的地方**：生命、護盾、彈匣靠近角色；任務與提示靠近物件；系統資訊（時間、信用點）退到角落。
4. **每一個動作都有反饋**：選取、確認、拒絕、購買、數值變動，都有動畫與聲音。
5. **閒置時退後**：戰鬥時不搶畫面（沿用 [動態介面](../05-dynamic-hud/DESIGN.md) 的淡出規則）。

### 字體與字級

- 字體：Cubic 11（開源像素字體，OFL 授權，隨專案附授權文件），與像素美術風格一致；缺字時退回系統字型。
- 字級只用整數倍：11（內文、標籤）、22（標題）、33（章節與大標）。原因：像素字體只有整數倍才不會糊。
- 數字使用等寬排列，避免跳動。

### 色彩

| 用途 | 顏色 |
|---|---|
| 面板底色 | 深藍黑，透明度 0.88，疊細微的掃描線 |
| 主線條、選取 | 青（`CYAN`） |
| 警示、危險、破損 | 洋紅與紅 |
| 金錢、提醒 | 黃（`NEON_YELLOW`） |
| 次要文字 | 灰藍 |
| 禁用 | 暗灰，線條變虛線 |

### 共用元件

| 元件 | 說明 |
|---|---|
| 面板 | 四角切角、1 像素青色邊線、角落小括號、頂端一條標題帶、可選的內部光暈 |
| 按鈕 | 切角、選取時邊線變亮並向右滑出一個小三角、確認時閃一下、禁用時虛線 |
| 標籤頁 | 斜切的頁籤，選取的頁籤下沿與面板相連 |
| 條 | 分段式（生命、護盾、電量），每段切角；受傷時掉落的段落有殘影 |
| 提示框 | 靠近物件的提示，有指向物件的小箭頭與出現動畫 |
| 橫幅 | 取得物品、檢查點、警告的橫幅，從側邊滑入、停留、滑出 |
| 分隔線 | 帶一個小菱形的細線 |
| 頭像框 | 見過場動畫 |
| 數字 | 增加時往上跳動、減少時閃紅 |

### 各畫面規格

| 畫面 | 內容 |
|---|---|
| 主選單 | 背景是循環的雨夜沉港（鏡頭緩慢搖動），左側是標題字樣與選單（繼續、新遊戲、圖鑑、設定、離開），右下角是版本與說明；選單項目依序滑入。 |
| 難度選擇 | 三張卡片，各有圖示、一句說明、受影響的數值。 |

### 通訊對話框（NE-274）

遊戲進行中、不暫停的那一種。原則是「小、一眼看得出誰在講、不多寫字」：

- **名牌只寫名字**。不寫「通訊／交談／閱讀」：種類由面板的樣子分辨，通訊用名牌旁的訊號格表示（講話時跳動，講完降到底）。
- **講者的顏色是他的身分**，同一個人在所有地方同一個顏色：左邊的直條、頭像框、面板四個角標、名牌的邊與訊號格都用它。內文一律用一般的文字色，不上色。不只靠顏色辨認：名字與頭像都在。
- **頭像是固定的方格**（40 像素），句子變兩行時不跟著拉長。沒有頭像的講者畫「只有聲音」的波形，不留空框。頭像上有很淡的掃描線。
- **底部一條細線是這一句還會停多久**：通訊會自己換下一句，玩家要知道還有多少時間讀。字還在出現時不顯示；要等玩家確認的重要通訊沒有倒數，也不顯示。
- **面板一出現就是這一句需要的高度**，逐字顯示時不中途長高；長句之後接短句會縮回去。
- 內文與底色的對比 16:1 以上（門檻 4.5:1）；文字放大到 1.5 倍時版面仍然成立。「減少介面動態」打開時不滑入、訊號格與掃描線不動。

查到的做法（只寫實際讀到的內容）：

| 來源 | 讀到什麼 | 用在哪裡 |
|---|---|---|
| [Dialogue UI Design（abratabia）](https://www.abratabia.com/game-ui-design/dialogue-ui.php) | 對話框有四個部分：名牌、頭像、內文、前進提示；名牌是連在框上的小標籤；頭像在內文左邊；一兩句的短對話用窄框（畫面高度的 15～20%）；每個角色一個固定顏色，和名字、頭像一起出現，不只靠顏色；內文不上色，顏色留給名字；對比至少 4.5:1 | 名牌做成小標籤、講者顏色的用法、內文不上色、對比門檻 |
| [Cyberpunk 2077 通話介面的玩家重製說明](https://sne1k.itch.io/cyberpunk-2077) | 來電是浮在畫面上的小視窗，有對方的頭像、名字與逐字稿，不打斷遊戲 | 維持「小視窗、不暫停」，不改成蓋住畫面的大對話框 |
| [Signalis 的收訊器（wiki）](https://signalis.wiki.gg/wiki/Receiver) | 調到有資料在傳的頻率時，左邊的指示格會亮 | 用會動的訊號格代替「通訊」兩個字 |

沒有查到的：對話框出現時的動畫時間、非暫停通訊的專門建議（上面第一個來源明說沒有涵蓋），所以滑入的時間沿用原本的 0.2 秒。

### 彈匣介面（主角旁的子彈圖示）

- 每把武器有自己的彈種圖示：手槍彈、步槍彈、霰彈、榴彈、電磁軌道彈、能量電池、雷射電池、機甲砲彈。圖示是高解析度的獨立美術（見場景美術的解析度規格），而不是色塊。
- 位置：主角身側，與準星相反的一邊（面向右就放在左邊），這樣不擋視線；跟著主角平滑移動，不抖動。
- 顯示：一排排子彈，每排最多 10 發，從下往上排；滿匣時每顆是完整的彩色，用掉的位置變成輪廓。超過 30 發的彈匣，每顆圖示代表多發，旁邊標示倍率。
- 動畫：
  - 開槍：最上面一發彈殼彈出並淡出、輪廓留下，音效有清脆的一聲。
  - 換彈：圖示依序一顆顆填回去，節奏與換彈時間一致，最後一顆「喀」一聲。
  - 彈量低（不到四分之一）：剩下的圖示變紅並輕微脈動。
  - 空匣：整排變輪廓、出現「換彈」按鍵提示。
  - 換武器：整排圖示換成新的彈種，帶短暫的翻轉。
- 備彈用小數字顯示在彈匣下方；無限備彈顯示符號。
- 閒置（沒射擊也沒換彈）一段時間後淡出，射擊、換彈、彈量變化、換武器時彈出；彈量低時常駐。
- 能量武器用電池格（分段的長條）而不是子彈。

## 五、場景美術

### 目標

把純色矩形換成有細節的元件：看得出是潮濕的柏油路、屋頂的碎石與女兒牆、貨櫃的波浪紋、設施的面板。畫面由「地形材質」「牆面」「道具」「背景層」四類元件組成，全部是資料驅動，新增一種不需要改程式。

### 解析度規格

- 所有環境元件以 **4 倍解析度**繪製（一格 16 像素的地形，貼圖是 64 像素），遊戲裡縮回原尺寸顯示；與角色骨架的規格相同（`texture_scale = 0.25`）。
- 有邊緣的元件都附 `_n` 法線貼圖（沿用法線工具）與 `_glow` 自發光層（窗戶、霓虹、指示燈）。
- 美術由程式繪製工具輸出成 PNG（暫代美術），同名 PNG 覆蓋即可換成手繪，不用改程式。
- 例外：背景視差層（遠景天際線、中景建築、近景前景）用 2 倍解析度，因為離鏡頭遠、又被霧與雨蓋住，4 倍會讓整條貼圖吃掉不必要的記憶體。

|---|---|
| 地形材質（body／top／side 三張）| `data/environment/materials/*.tres`、`art/environment/materials/` |
| 建築立面（一樓／標準樓層／女兒牆模組，附 `_glow` 與 `_n`）| `data/environment/facades/*.tres`、`art/environment/facades/` |

## 八、場景人物

> 對應票 NE-45。劇情與人物清單見 [../04-story/BIBLE.md](../04-story/BIBLE.md)，台詞怎麼寫見 [../04-story/WRITING.md](../04-story/WRITING.md)。

站在關卡裡的人：玩家靠近會出現一行提示，按互動鍵開始對話（遊戲暫停、用過場的對話框演出），說完可以拿到補給、信用點或收集品。牆上的刻痕這類「可調查物」用同一套資料，只是沒有人形，畫一個記號。

### 資料

新增一個人物只需要一份人物資料（`data/npcs/*.tres`）、章節劇本裡的對話場景，以及關卡資料 `legend` 的一個字元。

| 欄位 | 說明 |
|---|---|
| `kind` | 人物或可調查物 |
| `speaker` | 講者 id（章節劇本的 `speakers`）。沒有骨架外觀時，用這位講者的頭像做剪影 |
| `rig_id` | 骨架外觀 id（`art/characters/<id>/`）；找不到時自動退回頭像剪影，不報錯 |
| `pose`／`facing` | 站姿與原本面向；玩家靠近時轉向玩家 |
| `prompt` | 互動提示，一句重點，空白時用「{interact} 和<名字>說話」 |
| `talks` | 對話清單，每一段見下表 |

每一段對話（`NpcTalk`）：

| 欄位 | 說明 |
|---|---|
| `scene` | 台詞所在的劇情場景，`mode` 為 `dialogue`，每段最多 8 句 |
| `min_talks` | 至少已談過幾次才用這一段（0 = 第一次；1 = 之後再來） |
| `after_scene` | 某個劇情場景本輪播過之後才用這一段 |
| `credits`／`consumable`／`story_item` | 說完給的信用點、補給、收集品；`reward_text` 可改領取提示 |

- 挑選規則：清單中符合條件的**最後一段**勝出，所以越後面的越優先。
- 每一段的獎勵只領一次；補給帶滿時整份保留，騰出空間後再說話才補領。
- 談過幾次與已領的獎勵跟著檢查點存檔（與破壞物、開關同一套快照）：回溯後人物、信用點與補給一起回到檢查點的樣子，所以不會多領，也不會少領。新的一輪全部重置。
- 人物沒有受擊盒、不在敵人群組、沒有碰撞層：不受傷，也不會被敵人當成目標。地圖上人物周圍 8 格內不放敵人。

## 九、依死亡次數變化的劇情

> 對應票 NE-51。設計依據是 [../04-story/FORESHADOWING.md](../04-story/FORESHADOWING.md) 的 F19 與死亡次數反應表。

玩家的失敗是劇情的一部分：每次重來都有一筆「NEST 回溯紀錄」，累計到某些次數，通訊與廣播的措辭會有細微變化。**只改措辭，不改流程與難度**：場景一樣會在同一個位置觸發、一樣一輪只播一次，不多給也不少給任何東西。

### 死亡次數是本輪進度

- 累計死亡次數（`GameState.deaths`）屬於本輪進度，不存進檢查點：回溯、重開關卡、殘機用盡重來、換到下一章都不會歸零，只有開始新的一輪才歸零。
- 死亡畫面標題顯示「NEST 回溯紀錄 #n」；重來時的雜訊轉場也用同一個字樣。

### 劇本資料格式

都寫在章節劇本（`data/story/chapter_XX.json`），不用改程式。

| 位置 | 格式 | 說明 |
|---|---|---|
| 場景的 `variants` | `[{"min_deaths": 8, "lines": [...]}]` | 累計死亡達到 N 次時，這個場景改用這組台詞。有多組時取達到的最高一組；`lines` 與正常台詞一樣受句數上限限制，講者必須已定義 |
| 章節的 `death_notes` | `[{"min_deaths": 3, "text": "..."}]` | 死亡畫面標題下多一行小字，取達到的最高一則 |
| 章節的 `respawn_scenes` | `[{"scene": 場景 id, "min_deaths": 30, "repeat": true}]` | 死亡重生後（建立關卡時）播出的通訊；`repeat` 為 true 時每次重生都播，否則一輪只播一次 |
| 台詞的 `delay` | 秒數 | 這一句顯示前先把通訊框收起來沉默這麼久（上限 30 秒） |
| 台詞文字的 `{death_time}` | — | 換成最近一次死亡當下的世界時間，例如「11 點 40 分」 |

- 世界時鐘：一輪從晚上 21:00 開始，現實 1 秒是世界 10 秒，所以第一章結束時剛好是凌晨三點多。
- 壞資料（門檻不是數字、`lines` 空的、講者未定義…）啟動時記錄「場景 id 的第幾個死亡變化」的錯誤，執行時略過、退回正常台詞。
- 變化的台詞同樣受劇本品質檢查（見 [../04-story/WRITING.md](../04-story/WRITING.md)）。
