# 音效與音樂

2026-10-04，使用者要求：整個遊戲的音效（所有槍械、受擊）與場景 BGM 全部換成 CC0 素材，並做一個可以換角色、武器、BGM 的音效實驗室。母票 NE-154。

## 1. 現況

- `autoload/sfx.gd` 用程式合成所有音效（約 100 個 id，疊波形與噪音），`OVERRIDES` 是空的，專案裡沒有任何音訊檔。
- 聲音事件（`data/feel/sound_events.json`）已有多層、變體輪播、連鎖升音、壓低、優先級（NE-138），要保留。
- 匯流排只有 Master 與 SFX；沒有背景音樂、沒有環境音、沒有腳步聲。
- 呼叫端約 120 處 `Sfx.play(...)`／`Sfx.play_event(...)`，其中槍的換彈／空槍、敵人的受擊／死亡／開火目前全部共用同一組 id，聽起來每把槍、每種敵人都一樣。
- 打擊感實驗室（`tools/feel_lab/`）可以重生敵人、換武器、單獨播放聲音事件，但沒有 BGM、沒有混音與素材檢視。

## 2. 原則

1. **只收 CC0**。授權不明、CC-BY、CC-NC 一律不放進專案（與 `.claude/skills/free-asset-pipeline` 同一條規則）。每個素材包登記作者、授權、網址。
2. **檔案優先、合成音退路**。有檔案就播檔案；檔案遺失或壞掉時記錄具體位置，退回原本的合成音，遊戲不崩潰也不無聲。
3. **新增內容以資料為主**。新增武器、敵人、曲目、場景配樂只改 `data/audio/*.json` 與素材，不改程式。
4. **原始檔不進版控，成品進版控**。下載的原檔放 `assets_src/raw/audio/`（git-ignored，可重抓）；進版控的是轉檔後的 `audio/**`、清單與授權登記。
5. **低記憶體**。音效單聲道 OGG；音樂串流播放不整首解碼；長音檔不預載。

## 3. 匯流排

| 匯流排 | 內容 | 設定選單 |
|---|---|---|
| Master | 全部 | 主音量 |
| SFX | 槍械、命中、角色、機關、介面 | 音效 |
| Music | 背景音樂 | 音樂 |
| Ambience | 雨、風、機械嗡鳴等環境底噪 | 環境音 |

暫停與背包開啟時，Music 與 Ambience 匯流排掛低通濾波並降低音量，關閉後平滑還原。

## 4. 資料

全部放在 `data/audio/`，格式與錯誤處理比照 `data/feel/*.json`（缺檔、壞格式記錄一次錯誤、退回安全預設）。

| 檔案 | 內容 |
|---|---|
| `sound_bank.json` | 音效 id → 檔案清單（變體）、音量微調、音高範圍、授權包 id。沒有登記的 id 仍走合成音 |
| `weapon_sounds.json` | 武器 id → 換彈開始／中段／完成、空槍、換槍的音效 id；沒寫的退回 `default` |
| `character_sounds.json` | 角色 id（玩家、每種敵人、NPC）→ 受擊、死亡、攻擊、預兆、警戒、腳步的聲音事件；沒寫的退回 `default` |
| `footsteps.json` | 腳下地形材質 → 腳步聲事件 |
| `music.json` | 曲目（檔案、音量、迴圈點、授權）、cue（平靜／戰鬥／頭目的曲目組合與淡入淡出時間）、對應表 |
| `assets_src/audio/LICENSES.json` | 素材包授權登記（作者、授權、網址、取用的檔案數） |

### 4.1 槍械

射擊聲維持每把武器的 `fire_sound`（已經是資料）。換彈、空槍、換槍走 `weapon_sounds.json`，由武器 id 查表。近戰招式的出手聲與命中聲由 `data/feel/melee.json` 引用聲音事件。

### 4.2 受擊與角色

命中物的材質聲（`data/feel/materials.json`）、敵人受擊／死亡、玩家受傷維持用聲音事件，事件裡的層改引用新素材。敵人依自己的 id 查 `character_sounds.json`，所以「機械」與「生物」的受擊聲、死亡聲可以不同；新增敵人沒登記時用 `default`。

### 4.3 背景音樂

- 曲目一律串流播放，兩個播放器交叉淡化（同一個類別也用在環境音）。
- cue 有三種狀態：`calm`（平靜）、`combat`（戰鬥）、`boss`（頭目）。戰鬥狀態由「附近有警戒中的敵人」進入，離開有遲滯（幾秒內沒有敵人才退回平靜），避免來回跳。
- 對應表由具體到一般：關卡 id → 光影設定 id → 預設。新關卡只要有光影設定就自動有配樂。
- 頭目戰以 `boss_started`／`boss_defeated` 切換；死亡與通關各有短 sting；主選單、結算畫面各有曲目。
- 過場動畫播放時，BGM 壓低；對話與暫停選單不中斷音樂。

### 4.4 環境音

雨天關卡的雨聲、風、機械嗡鳴等 loop 掛在 Ambience 匯流排，依光影設定 id 對應（與 BGM 對應表同一種格式），淡入淡出。

## 5. 音效實驗室

`tools/sound_lab/sound_lab.tscn`，只能從命令列開（比照打擊感實驗室，匯出時排除 `tools/`）。分頁：

| 分頁 | 功能 |
|---|---|
| 角色 | 選玩家／敵人／NPC，播放受擊、死亡、攻擊、預兆、腳步，連按聽變體 |
| 武器 | 選武器，播放射擊（單發、連發）、換彈整段、空槍、換槍；近戰招式 |
| 受擊 | 選材質 × 力道（輕、重、弱點、跳彈、擊殺），一鍵播放整組回饋 |
| BGM | 曲目清單、cue 切換（平靜／戰鬥／頭目）、交叉淡化試聽、跳到迴圈尾端試接縫、調音量 |
| 環境 | 環境音 loop 試聽與疊加 |
| 全部音效 | 搜尋所有音效 id，列出檔案、時長、授權、是否缺檔／用合成音 |
| 混音 | 各匯流排音量與靜音、即時音量表、同時發聲數與被丟棄數 |

調出來的數值（音量、音高、cue 的淡化時間）可以回寫 `data/audio/*.json`，流程與打擊感實驗室相同：先預覽差異、驗證通過才寫入並備份。


## 5.1 編號體系與位置清單（2026-10-04 補充）

使用者要自己挑每個位置用哪個聲音，所以「位置」與「素材」分開編號，兩套體系的格式不同、不會混淆：

| 體系 | 格式 | 例 | 說明 |
|---|---|---|---|
| 位置（slot） | `P-<域>-<三位數>` | `P-WPN-001` | 遊戲裡會響的一個地方：手槍射擊、命中金屬、第一章屋頂的平靜曲。域：WPN 武器、HIT 命中與材質、CHR 角色、MOV 移動與腳步、ENV 機關與場景互動、UIS 介面、AMB 環境音、BGM 背景音樂 |
| 素材（asset） | `<類>-<四位數>` | `GUN-0042` | 一個候選音訊檔（已下載的 CC0 素材）。全專案不重複、不重編。類：GUN 槍聲、RLD 槍械操作、IMP 撞擊、EXP 爆炸、MLE 近戰、MOV 移動與衣物、VOX 人聲與生物、MEC 機械與機關、ELC 電子與能量、UIS 介面、AMB 環境循環、MUS 音樂 |

- **素材目錄** `assets_src/audio/catalog.json`：每個素材一筆（編號、素材包、檔案、時長、類、標籤），編號只增不改。
- **位置登記** `data/audio/slots.json`：每個位置一筆（編號、名稱、遊戲裡哪裡用到、對應的音效庫 id／音樂 cue、素材類、至少十個備選的素材編號）。
- **位置清單** `design/16-audio/PLACEMENTS.md`：給人讀與編輯的表格——位置、現在用哪些素材、「預計使用」（使用者填素材編號）、「手動放入」勾選。由工具產生，重產時保留使用者填的兩欄。
- 備選池：每個位置的備選先放同類別最相近的，並且不限制只能選備選——實驗室可以搜尋整個素材目錄，跨類別挑。
- 套用：使用者在清單填好預計使用的素材編號後，`tools/audio/apply_placements.py` 把它們寫進加工清單並重建；已勾「手動放入」的位置代表使用者自己放了檔案，工具不動它。
- 預聽用的小檔案（每個素材一個，統一響度與長度）由 `tools/audio/build_candidates.py` 產生，不進版控（新機器上直接跑 `tools/audio/setup_audition.py`：先下載約 3 GB 的原始素材，原始檔同樣不進版控，再產生預聽檔）；素材編號與目錄進版控，所以在任何機器上編號都一樣。

實驗室與 `PLACEMENTS.md` 雙向連動：實驗室改了「預計使用」或勾選，立刻寫回 md（只改那一格）；md 被外部編輯器改了，實驗室約一秒內偵測到並重新載入。

## 5.2 換彈聲音時間軸（2026-10-04 補充）

換彈聲原本固定分三段（開始、中段 55%、完成），段數與時間點寫死在程式裡。使用者要自己決定要不要分三段、分幾段、每段落在動畫的哪裡，所以改成資料：

- `data/audio/weapon_sounds.json` 的每個 profile 可以有 `reload_cues`：一串 cue，每個 cue 有 `at`（換彈進度 0 到 1）、聲音（`kind` 指到該武器的 reload_start／reload_mid／reload_done／empty／equip，或 `sound` 直接指一個音效名稱）、`volume_db`。
- 沒寫的 profile 沿用 `extends` 或 `default`；`default` 就是原本的三段，所以沒有改資料的武器行為完全不變。武器自己寫了 `reload_cues` 就整份取代（不逐筆合併，避免看不出實際有幾段）。
- 段數不限（上限 12）。一段：只在開始播一個長音；兩段；霰彈槍一發一發裝填時可以重複同一個 cue；空陣列代表換彈不發聲。
- 播放依換彈進度而不是秒數，所以義體加速換彈時聲音自動跟著動畫；換彈完成時補播還沒播的 cue；中途取消換彈不補播。
- 驗證：`at` 在 0 到 1、音量在範圍內、`kind` 必須是已知動作、`sound` 必須存在、段數上限，錯誤訊息指出是哪個 profile 的第幾個 cue。

## 5.3 實驗室的畫面舞台與情境（2026-10-04 補充）

只聽聲音看不出聲音和動畫配不配，也看不出一個聲音在遊戲裡會以什麼形式出現。所以實驗室加一個畫面舞台，並把「每個聲音位置會在什麼情境下響」做成資料：

- **舞台**：實驗室右側常駐（可收合）的遊戲真實畫面——真正的關卡、玩家、敵人、HUD、特效，聲音由遊戲自己的程式路徑播出，不是模擬。滑鼠移到舞台上可以瞄準，鍵盤照遊戲操作，可以直接玩。
- **情境**（`data/audio/stage_scenes.json`）：一個情境 = 一個動作加參數，例如「手槍射擊三發」「步槍換彈」「對肉靶開槍」「保全受擊」「走在金屬地面」。動作種類是程式裡登記的小函式（射擊、換彈、空槍、換槍、近戰、命中靶、敵人受擊、死亡、行為、走路、落地、拾取、開機關…），新增情境只改資料；新增動作種類才需要寫一個函式。
- **位置對應情境**：同一份資料把每個聲音位置（P-XXX-NNN）對應到一個或多個情境；暫時做不出畫面的位置明確標示原因，實驗室只播聲音。資料檢查保證每個位置都有對應或有原因，情境引用的動作都存在。
- **實際響了什麼**：情境執行時記錄遊戲實際播出的音效，顯示在舞台下方；自動測試用同一份記錄驗證「這個情境真的會響出對應位置的聲音」，所以對應不會悄悄過期。
- **在畫面裡試備選**：選一個位置和一個備選素材，按「用這個素材在畫面中試」，舞台執行該位置的情境，但那個位置的聲音暫時換成備選素材的預聽檔（只在記憶體，不寫檔、不動資料），看到的動畫配上的就是候選聲音。
- **整段動畫的聲音**：動畫相關的聲音（目前是換彈，見 5.2）用時間軸；時間軸編輯器在舞台下方，顯示動畫長度、每個聲音的位置與長度、目前進度的游標。可以分三段、分更多段、或整段只用一個聲音，並在真實動畫上立刻重試，確認串起來合理。
- **慢動作**：0.1 到 1 倍的滑桿，動畫與聲音事件一起放慢，方便看聲音落在動畫的哪一格。離開實驗室時還原。
- **舞台與音樂**：舞台關卡預設不播背景音樂與環境音，避免蓋過正在調的聲音；環境音與音樂的情境才會打開它們。
- **入口**：編輯器或除錯版的遊戲中按 F5 開發工具選單即可進入（NE-168），不用打命令列。

情境分三批做：武器（NE-166）、受擊／角色／移動（NE-167）、機關／介面／環境音／音樂（NE-169）。

## 5.4 音訊片段擷取（2026-10-05 補充）

有些素材一個檔案裡包含多段聲音：連發槍聲、一整組撞擊、長錄音。加工清單的 `start`／`end` 雖然能指定範圍，但要靠手算時間、看不到波形，而且一個加工輸出只能取一段。所以實驗室加一個擷取介面，把「某個素材的某一段」變成一個獨立的新素材。

- **流程**：在實驗室選一個素材開啟擷取介面 → 看原始完整檔的波形與依靜音自動標出的各段 → 選一段（或手動框選、拖動、輸入秒數微調）並試聽 → 按「擷取成新素材」→ 確認視窗列出來源、起訖、時長與新名稱 → 使用者確認後才真的輸出；取消不寫任何檔案、不改任何清單。
- **看原始完整檔**：預聽檔只有前 4 秒（音樂前 60 秒）且已去掉頭尾靜音，時間和原檔對不上，後面的段落看不到。所以介面看的是原始完整檔：準備編輯時由工具解出一份可聽的完整長預聽（單聲道、不去靜音，長度有上限）、波形資料與自動分段，再交給實驗室；輸出時直接從原檔切，不經預聽檔。
- **輸出是新素材 + 範圍紀錄**：輸出無損音訊檔，保留原檔的取樣率與位元深度，不調音量、不重新取樣；取得新的素材編號（類別與原檔相同、接在該類最大編號後面、不重用），和原檔並列在素材目錄與搜尋。同時把「原檔編號、起訖秒數」寫進一份進版控的片段清單；輸出檔放在本機產生的素材包（不進版控），原始下載檔被清掉重抓後，照清單重跑就能重做出同樣的片段與同樣的編號。
- **授權**：片段沿用原檔的 CC0，來源目錄記錄「衍生自」哪個素材包；下載工具略過這種本機產生的素材包，不當成下載失敗。
- **預聽與挑選**：新片段自動產生預聽檔，立刻能在實驗室試聽、挑成預計使用；擷取本身不改任何位置的預計使用。
- **自動分段**：依靜音門檻與最短間隔把音訊分成幾段，標在波形上，一鍵選用；分段只是建議，起訖仍以使用者調整為準。
- **容錯**：起訖超出檔案、起點不小於終點、原檔缺失、寫入失敗時，錯誤訊息指出是哪個素材與原因，不留下半成品檔案或半寫入的清單；同一個原檔幾乎相同的範圍重複擷取時提示已存在。
- **測試**：用合成的短音訊測試，不依賴下載的素材；沒有 Python 與 ffmpeg 的環境（CI）也要通過。

分兩張票做：工具與片段清單（NE-179）、實驗室介面（NE-180，依賴 NE-179）。

## 5.5 射速加快時音效跟著加快、音高不變（2026-10-05 補充）

射擊間隔比音效短時（例如霰彈槍每 0.55 秒一發，音效 0.84 秒），上一發的尾音會被下一發蓋掉；射速提高（超頻、未來的射速升級）時更明顯。做法是兩件事：

- **預先做幾級加速的音效變體（音高不變）**：加工時用時間伸縮（ffmpeg 的 rubberband 濾鏡，打擊音模式，保留起音）為每個射擊音效產生幾級速度（預設 1.25、1.5、2.0 倍，資料可調）的變體，響度與原速對齊，原速的檔案不變。音效庫的每個音效除了 `files`（原速）多一個 `speed_files`（速度 → 檔案清單）。不即時變調：遊戲內的 pitch_scale 會連音高一起變，要保持音高只能離線做，音質也比即時變調好。
- **依射速選用變體**：播放射擊音效時帶「射速倍率」（目前射擊間隔與基準間隔的比，超頻時大於 1），音效庫選最接近的一級；沒有該級變體就退回原速，不報錯。倍率從玩家目前的有效射速算出，所以超頻、之後的射速升級與武器改裝都自動生效，不必各自處理音效。
- **收掉上一發的尾音**：同一個音效在上一發還沒播完時又響起，上一發的聲音在很短的時間內淡出（`choke_ms`，資料可調，預設只給射擊音效），不再互相蓋住。
- 實驗室的即時試玩可以選射速倍率聽每一級；加工驗收用數據：變體長度約等於原長除以倍率、頻譜重心與原速相近（音高沒變）、響度對齊。
- 因為是時間伸縮，倍率太高會失真；上限預設 2 倍，由使用者聽過再調整。
