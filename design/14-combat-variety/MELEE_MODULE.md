## 二、鞭子：從頭到尾都是軟的（NE-276）

戰鬥組在雲端分支上的做法（NE-270，未併入 main）是兩種模式切換：平常用 Verlet 模擬下垂；出招時改成「每一節的角度跟著導引」，並且在出招開始的那一格把整條鞭身一口氣排成直線。這就是使用者看到的「突然變直再變軟」。main 上則是一條永遠筆直的線。

我們的做法（來源 1、3 的結合）：

- **只有一種狀態：一條一直在模擬的繩子**。握把那一端釘在掌心；出招時不改變模擬方式，只多一個「鞭梢的目標點」沿著這一招的路徑走，鞭梢與靠近鞭梢的幾節被它用有限的力拉過去，其餘的節點由繩子自己帶動。沒有任何一格是用排的。
- **繩子比要打的距離長一點**（留 6～8% 的鬆弛）：鞭梢到達最遠點時，中段仍然有弧度，不會變成一把尺。
- **單分子鞭的線是從握把放出來的**：平常只放出短短一段垂著（不拖地一大截），出招時放長、收招時收回——長度是連續變化的，不是換一條。
- 命中判定仍然照招式資料；鞭梢在出招那一刻要已經在最遠點附近（看得到是它打到的）。
- 自己的特點（來源 2 給的想法，列為後續）：按住近戰鍵把鞭子留在外面、跟著準星甩；軟的鞭身碰到小型飛行物可以擋掉。來源 1 的纏與拉也列為後續。

驗收的量法寫在票上：整招逐格量「握把到鞭梢的直線距離 ÷ 鞭身長度」（1.0 就是一把尺），不能有哪一格等於 1、相鄰兩格也不能跳變。

## 三、完整且獨立的近戰攻擊模組（NE-277）

現況：一招＝一段手臂的姿勢內插，武器跟著前臂；身體幾乎不動；另一隻手不參與；五把武器的招式長得很像，只有軌跡的顏色與形狀不同。

要做成的樣子（來源 4、5、6、7）：

1. **一招是一個完整的、自己帶齊所有東西的單位**（資料）：預兆、出手、跟隨、收招四段的關鍵姿勢；身體怎麼動（踏步、轉身、壓低、躍起）；武器走的路徑；另一隻手在哪；軌跡與特效；判定（可以多段：持續＋間隔）；命中回饋（停頓幾格、敵人怎麼反應、聲音哪幾層）；可取消點。不再是「共用的揮砍姿勢＋不同的顏色」。
2. **武器帶著手，不是手帶著武器**：這一招先決定武器的路徑，兩隻手用 IK 去握（NE-275 已經有握點與另一隻手的握法）。雙手武器出招時兩隻手都在桿上。
3. **姿勢少而強**（來源 4）：每招 4～6 個關鍵姿勢，補間不加在關鍵姿勢中間；時間是資料，改一個數字就能調手感。
4. **每把武器有自己的一套**，不是同一套換皮：
   - 熱能長刀：三段斬（斜砍、反斬、踏步下劈），可以接衝刺斬。
   - 單分子匕首：近身連刺，按住是連續的快刺，最後一下往後跳開。
   - 離子戰戟：雙手，長距離的刺與橫掃；按住是把戟頭頂在前面的戒備姿勢（敵人撞上來會被電）。
   - 液壓錘：雙手，慢而重；按住蓄力，放開砸地（範圍震盪）；靠走位與時機。
   - 單分子鞭：遠距離的甩擊；按住把鞭子留在外面甩（來源 2）。
5. **獨立**：近戰模組自己管招式的播放、判定與回饋，不混在主角的槍械瞄準與手臂 IK 裡；輸入只有「按、按住、放開、方向」，模組回報「現在在哪一段、能不能取消」。這樣之後加新武器只加資料與少量的招式腳本。

做的順序（每一步都能單獨驗收）：
1. 招式資料的新格式與播放器（先讓現有的招式原樣跑在新的播放器上，行為不變）。
2. 武器路徑＋雙手 IK（先做液壓錘與離子戰戟，因為它們現在最假）。
3. 身體的動作（踏步、轉身、壓低）與多段判定。
4. 每把武器的「按住」招式。
5. 命中回饋分層（停頓、敵人反應、聲音）。

和戰鬥組分支的關係：`origin/feature/combat` 上有 29 個尚未併入 main 的提交（NE-237 的招式動作驗證、NE-270 的鞭身、NE-254 的投擲等），改了同樣幾個檔案。開始做之前要先決定：是把那個分支先併進 main，還是由這張票接手近戰、把那邊近戰相關的部分作廢。這件事要使用者決定。

## 四、實作後的樣子（2026-10-12，NE-277 第一輪）

和戰鬥組分支的關係：`origin/feature/combat` 和目前的 main 沒有共同的歷史（main 重寫過），而且 main 已經有 NE-260、NE-261、NE-275、NE-276 的成果；這一輪以 main 為準，不併那個分支。

## 原生逐格發現與連續握位（2026-11-11，NE-277）

戟的後手不能每格在整根桿上重新取最接近肩膀的等距解：前手兩側保留一個拳頭的間隔，因此兩側可握區不相連，貪婪取點會把後手瞬間換到另一側。`grip.shaft_side` 可選 -1（桿尾）或 1（前手前方），僅雙手招式可指定；缺值沿用原規則，壞型別、零、非整數與單手宣告拒絕。可達區間優先，其內沿上次真正接受的握位滑動；收招後保留這個握位，不撤掉最後一格的後手修正。換武器或翻向重設偏好。

戟的刺、上撩及戒備使用前側；交叉掃擊使用尾側，局部路徑保留後肩到桿線的距離，避免只能折肘到過窄或完全搆不到。上述數字屬本作資料調整，並非通用業界門檻。

長刀原本的踏步 14、真正前衝、判定距離、傷害與全部時間保持。蓄力轉前衝時的膝部跳動來自共用待機／走跑腳部 IK 交接：低權重走跑直接取代待機接地，混合的基底卻是未接地腿角。現在待機固定腳與走跑腳的目標先連續混合，再做一次腿 IK；身體高度與雙腳使用同一組可達目標。空中、格擋及未啟用待機固定腳的姿勢保留原有走跑淡入；滿權重走跑與 NPC 姿勢入口保持。腿角混合使用重用緩衝，不再每條腿每格建立臨時陣列。回歸涵蓋正反向走跑／待機脈衝與原強度近戰踏步，以腳部位置及實際單格角度判定；故意丟失待機接地目標的負控制必須被同一檢查拒絕。

驗證使用 `tools/ne277_delivery_probe.tscn`／`tools/ne277_feedback_probe.tscn`，由 `tools/run_ne277_delivery.py` 串行隔離設定與存檔、封存來源及原始 ZIP。個別招式明示安排起手與指定招式；按住段另用公開 `action_press/release` 從第一招自然進入，不能把直接指定按住招式當成輸入驗收。每個物理步含回到待機的 15 格都保存實際骨角與握點，原生圖只裁切、不縮放；舊八張固定進度表仍只是摘要。接點幾何、全彩接合、真人辨識與試聽分別判斷。全引擎耗時監視器不作模組成本結論。

減少介面動態只控制介面，不能代稱世界震動已停用。命中矩陣分別設定減閃光、世界震動倍率及鏡頭脈衝，保存實際設定讀回與世界震動事件；正常組應有震動，世界震動倍率為零的組不應發出震動事件。錄音保存真正主匯流排原始 PCM，包括環境音與配樂；按接觸時間切片不改增益，不能拿混音的峰值或 RMS 宣稱獨立聲層響度或真人試聽通過。

舊接點工具在無起手／零影格、缺指標或超標時仍成功，且 angle_pop 重複放寬 ACTION_POP_SCALE；現在一律拒絕，倍率只套一次。故意不出招與反折手肘的負控制須失敗，不能放寬原門檻。無頭安排的敵人需停用畫面可見性啟用器以留在物理世界；聲音事件驗解析後的實際 leaf，不能把未 emit 的事件包名當成缺音。程序結束沿用 AudioRelease 等混音端真正釋放，原 Ogg 洩漏日誌保留。

命中矩陣另重現匕首第一刺的 LIGHT 受傷：impact=3 未造成敵人 flinch／stagger，既有受傷分層不會給敵人停頓，而近戰回饋只暫停主角。第一個真正造成傷害的接觸現在把受傷 health 的實際擁有節點加入同一次局部停頓，不提升受傷分級、不加傷害。仍每招僅一次；後續判定窗／晚到目標保留各自反應，不再凍攻擊者，與 NE-268 的接觸契約一致。

本輪原生首傷格仍發現錘頭、鞭梢遠離目標時已出傷害，屬同票的產品時序缺口。第一個傷害事件的 phase 不能證明呈現已更新：需一起記錄物理步內的招式推進／命中、玩家可見姿勢更新、延後雙方停頓及 frame_post_draw 次序，並量可見攻擊部位與真正受傷區的世界幾何。資料的活動窗或延後停頓過早凍住上一格姿勢都是待證的可能，不先指定唯一原因。後續修正保持相同場地、方向與原始影格紅綠對照，不任意改傷害、射程、連段及既有時序，另跑新版本真正受影響範圍。


## 當格可見接觸與持續招式收招（2026-11-11，NE-277）

順序紀錄證實兩個獨立原因：玩家先推進招式／命中，再由子節點更新可見姿勢，敵人的同步受傷停頓可能先停掉子樹；即使僅延後停頓，原粗判定也會在錘頭、鞭身尚未到目標時造成傷害。現在保留原判定窗、射程、死角、傷害及連段規則，將待判定區間交到 `PlayerVisual` 完成本格骨架、武器、軟鞭及後手後處理；最後一個有效區間處理完才轉收招，不能額外延長一格命中。揮空聲在原有效窗觀測完仍未命中時才選播，避免先播揮空再補命中聲。

粗判定只提名候選目標。剛性武器以正式 PNG 的 alpha（大於 0.1）建立可重用的局部三角形，保留透明孔；軟鞭使用實際節點與繪製粗細。正式繪製與接觸共用 `MeleeArt.draw_transform`／`texture_rect`，包含翻向、非零握點及實例縮放，不另寫一套近似掌心座標。每格重用前後世界頂點緩衝，檢查兩格輪廓及每條邊掃過的面，並裁到該格真正仍開著的原判定區間，避免快速刃尖一格穿過目標時漏擊。

招式組可選 `contact_span: [from, to]`，限制武器局部 x 軸相對握點的有效部位；單位與外觀的 `size`／`grip` 相同，實例縮放由同一繪製矩陣套用。缺值保留整個可見輪廓；壞型別、非有限值、逆序或超出 ±512 拒絕。長刀、匕首只取刃段，戟取刃部，錘只取錘頭，不能以柄／桿相交冒充命中；鞭取真正繩身。先驗真接觸再選部位：未碰到的高優先弱點不能吃掉身體接點，實際碰到的盾／關閉部位仍須阻擋後方傷害。

局部姿勢修正保留原數值契約：戰戟戒備收回握點，讓原 0.25 秒持續間隔能由真刃接觸；長刀兩招局部縮短伸手以回到原可見射程門檻；匕首第二刺微調握點方向並反補武器傾角，保持刀刃角度，避免首傷只靠呼吸高度下不到一像素的擦邊。持續循環可在任意位置放開，收招從剛發布的實際進度接續到終點，使用原收招秒數，不能跳到固定 0.7 的姿勢。

`tools/ne277_contact_probe.tscn` 在原 42 列雙向／真按住逐格稽核上記錄正式敵人的每次傷害、前後輪廓、原窗口、繪製與受傷區矩陣、首傷原圖及真正混音 WAV。獨立 reader 以來源 alpha／繩節點重建輪廓、SAT 重算掃掠與接觸點，拒絕空矩陣、舊可見進度、缺輸入、未接觸及改動傷害資料。早粗判定、單純延後粗判定、錯誤繪製 y 軸及舊循環收招各保留負控制。只進粗矩形卻未碰到刃的原平台位置保留為負例，另用原瞄準／射程／窗口下真刃相交的位置驗雙向上身接點；聲音實驗室也將戟靶放到真刃區。

### 接觸幾何的有限值與效能驗證邊界（2026-11-12，NE-277）

碰撞 API 在反矩陣與 SAT 前拒絕非有限的世界頂點、矩陣、行列式、反矩陣、轉換後局部頂點與矩形半尺寸。只有行列式恰為零才拒絕；合法的反射、極小非零縮放及零尺寸矩形保持原語義，不能加 epsilon 把細小但可逆的武器變換當壞資料。實測原 API 的 NaN／INF 頂點可回傳有限假接點、奇異矩陣可輸出引擎錯誤，而引擎接受的 INF 矩形尺寸能讓遠處三角形誤中；這些原始反例與 setter 診斷分開保留。窄守門不改 SAT、原接觸門檻或正常命中規則。

原生連續格、接點與錄音各自證明可見接觸、實際停頓與混音事件，不代替效能。效能先以完整歷史基底的真實 Player 物理／PlayerVisual 動畫／MeleeHeld 繪製呼叫，與最終候選同場、同招、同實體敵人數交替比較；新增模組在主角物理呼叫內，不重複相加，也不把歷史不存在的模組或按住招式填零。c78 的增量對照另涵蓋按住招式，不能單獨代稱整票修前比較。

## 裝置輸入比對的時鐘界線（2026-11-02，NE-237）
