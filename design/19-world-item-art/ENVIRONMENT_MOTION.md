# 場景動態：有來源、有接觸、有層次（BG-25）

2026-10-10，使用者希望場景不只有靜態立繪，例如水管出水應有水流；優先以 Godot 製作合理動畫，真正需要影片模型時另開待辦票。既有特效先盤點，避免同一水管、雨或蒸汽重複生成。靜止的牆、海報與家具仍保持穩定。

## 研究依據

Motion Twin 場景美術 Gwenaël Massé 在《Dead Cells》開發分享中，說明以視差、粒子、水、霧等建立空間層次，同時以視覺優先序維持可走地形、互動與危險的辨識；装飾也按區域與用途安排。採用這個原則，不套用其色盤，也不宣稱所有玩家偏好一致。[開發者原文](https://www.gamedeveloper.com/production/art-design-deep-dive-giving-back-colors-to-cryptic-worlds-in-i-dead-cells-i-)

Godot 可用逐格精靈、AnimationPlayer 與 CanvasItem shader 製作局部循環；粒子的 amount、lifetime 與可見區域可明確限定。官方特別指出，減少 amount_ratio 並不減少已配置粒子容量，且 GPU 2D 粒子不與 PhysicsBody2D 直接碰撞。因此不以半透明或降低發射比例冒稱降低容量，也不假設水會自動撞到平台。[精靈動畫](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html)、[2D shader](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html)、[粒子容量與碰撞限制](https://docs.godotengine.org/en/stable/classes/class_gpuparticles2d.html)

## 專案決策

| 用途 | 動態與接觸 | 辨識限制 |
|---|---|---|
| 排水管、漏水、滴水 | 明確出水口；向重力方向；遇第一個實際承接面才有小水花／漣漪 | 不穿過牆地板，不用發光彈道模仿水；已有流水先保留並改善 |
| 通風口、蒸汽 | 固定噴口、低對比少量漂散；依機械運作或壓力循環 | 裝飾蒸汽與可傷人的蒸汽使用不同訊號；危險預警保持清楚 |
| 風扇、布條、雨傘邊緣 | 只動可活動部件，固定支架／掛點；同區風向一致 | 不讓整張立繪或牆面漂移、抖動；海報保持貼牆 |
| 霓虹、窗光、電器 | 有電源與場景理由才短暫變化，頻率與幅度克制 | 不讓整片背景網格闪烁，不與可拾取物提示或戰鬥閃光混淆 |
| 水面 | 流向、局部漣漪、腳步濺水與反光分開 | 反光不取代地面接觸，不掩蓋落點或敵人 |

每個動態元件記錄來源、世界尺寸、固定點、運動範圍、承接面、圖層、循環／事件與品質檔。背景動態低於角色、危險與互動提示的視覺優先序；每個視角挑少量主要動態，不使所有物件一起動。

沿用共享貼圖、固定容量与視野分塊；不在每格創建圖像或節點，不同場景重用小圖集，不將長影片或大量逐格圖片常駐 RAM／VRAM。低檔優先保留辨識所需的動態。暫停、過場、切區、讀檔與重進場景須有明確恢復／清理，不累積發射器或粒子。

Godot 已能處理流水等首批需求，暫不載入影片生成模型。若某個複雜演出確實超出引擎動態／小圖集可表達的範圍，先列具體場景、無法達到的效果、影片循環接縫、分層、透明度、解析度、容量與模型資源，再另開待辦票；不把等待影片模型當成首批流水的依賴。

## 驗證

先逐件盤點已有與靜態的場景，再選第一章電話亭巷、街道與適合的室內元件完成首批。實際 Forward+ 相同視角至少記錄 0、0.5、1 秒，檢查出水口／固定點、落水接觸、循環接縫、戰鬥與拾取辨識。品質檔、暫停恢復、切區與連續往返另驗；用同機同場景測試有／無新增動態的幀時間與 RAM／VRAM，記錄方法及原始值。靜態截圖不能代稱動畫順暢或效能通過。

BG-19 保持支撐規則；BG-20 管用途與密度；NE-95 管既有共用特效。BG-25 管物件動態的接點、循環及逐區實際採用，三者不重複改同一特效來源。

## 首批局部水流（2026-10-10）

電話亭巷既有落水管成品為 148×672 左右的長條：硬管、下端管口、水柱及底部承接水花已在同一張透明貼圖中。水柱不是獨立水面，不能套整張 puddle ripple。首階段以資料中的正規化局部矩形界定水柱（管口下方至水花上方）與承接面，僅在原 alpha 內向下流動高光；管口、支架與硬管像素固定，水花以局部橢圓漣漪循環。base 與 glow 同一時鐘，Sprite2D 鏡像已提供來源 UV，不再次鏡像選區，世界縮放不改來源錨點。

時鐘由繼承暫停的局部元件累計 delta，不使用 shader TIME；材質每個實體最多兩份、無新貼圖與粒子，離開視野停止時鐘，切區隨 PropNode 釋放。低檔保留低對比水流與接觸，避免畫質切換另建效果。資料非法時記錄物件 id 與範圍並保持靜態原圖。首階段不動地圖、海報、故事、角色、共用 Fx；風扇必須先分離葉片與固定網罩，不能旋轉整張換氣扇。

## 第二階段：廚房水壺的蒸汽接點

沿用既有 Godot 蒸汽與固定容量 ParticleField，不新增發射器、不改 shared Fx / NE-95 的大小或強度。先校正既有水壺：原 steam_offset (14,6) 在木柴側，實際左側壺嘴為來源圖約 (12,60) / (149,228)，對應目前世界尺寸 (18.6,28.5) 的 (1.5,7.5)。壺嘴散布限制為左右 0.25 世界像素，不讓初始蒸汽跨到硬管或木柴；其他物件沿用原 ±2 預設。局部散布資料不合法則記錄物件並退回原安全預設。固定點仍由 PropNode 的 flip 與 to_global 處理。

驗證在既有 ch1_pawnshop 廚房原擺位，不改 maps、Story 或構圖；同視角保存原接點與校正後 0/0.5/1 秒，確認壺嘴、小團蒸汽、硬爐與壺身穩定。暫停驗證 emission timer 與已有 ParticleField 粒子壽命，恢復與十次切區觀察釋放。BG-25 票由主 session 同時追加本機水流證據，此階段不改該票；交付原始證據與範圍供主 session 合併紀錄。

### 滴水的做法

水滴由擺設資料指定兩個點：出水口與承接的水面（貼圖的 0～1 座標），加上幾秒一滴。水滴越落越快，落到水面濺開兩個小點再消失，等下一滴。沒有粒子、沒有每格配置；自己累計時間，暫停時停住、離開畫面不更新。資料不對（出水口在水面下方、超出貼圖、間隔比一滴的時間短）就記錄擺設並保留靜態圖。

搖晃的擺設（吊鏈、紙罩燈、燈籠、盆栽、天線、電線）各連拍四個時刻：掛點、花盆、底座與桿身都不動，只有下垂或上端的部分擺動。搖晃與閃爍是著色器依時間計算的，沒有接縫；它們不隨暫停停住，會在暫停畫面後面繼續動，滴水、水流與蒸汽則會停。
