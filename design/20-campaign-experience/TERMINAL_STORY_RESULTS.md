# 第一章獨立段落的保存邊界

2026-10-21。承接 ST-9：先將晚飯與交接櫃三次明確操作接上真正整輪保存，不宣稱所有故事結果已完成。政策 `main_terminal_results_v1` 由正式 compiler 指定，限定有真 Main／當前 persistent Level、無選項、無 then、無待定交物的獨立段落。回家保留原旗標政策；世界拾取、診間托盤與含續段的餐費本批不借用此政策。

保存前以既有純 StoryResultPlan 計算完整旗標、錢包／正式收據、物品持有／交付與完成史，所有 owner 先準備，再寫完整現況快照。交盤的目的地必須來自正式交接櫃資料，其他紙物由已載入劇本的段落發放；不生成世界 pickup 或猜測座標。沒有改動區域狀態，因此保持 Level 的現有共享區域參照。

保存拒絕時保留真請求及全部原件，僅顯示可重試的事件提示。保存成功後無回呼地安裝錢包、物品、旗標與完成史，然後退休請求、發布通知。發布期間禁止新故事交易、交物、播放及路由；普通花費與閱讀 NEW 合法，完成後重抓現況補存，不重新安裝舊候選。跨程序以正式 reader 驗已提交結果不重發。

完整 runtime 的保持比較，兩側須經 writer 相同的 JSON 與第二次驗證邊界，避免方向向量少一次 float32 單位化造成誤拒絕；不放寬數值門檻或省略欄位。主檔替換及回滾同時失敗時，既有提示改為載入完整原備份，真 Main 重建 Level 並只釋放本模組自己的鎖；本次結果仍未提交，不宣稱已保存。

另修現有 legacy 預檢：整段交易必須在獨立帳本與累計餘額中依序模擬，不能每筆都拿原餘額驗。重複、互斥與後筆缺錢均在第一筆 live 寫入前拒絕。

驗證在第一次真正的轉交／取得通知內，直接解碼原主檔及其checksum，尚未經讀取修復、NPC等待者或後續自動保存；保留當下完整主檔。修前同探針103項15失敗，三次live及主檔皆落後一次；修後103／0且皆為1／2／3。真正拒寫／重試、普通通知花費與NEW已讀保持；另程序冷讀、原五個來源及翌日入口另外驗證。CI使用獨立write／read程序保存原始日誌、退出碼、來源雜湊與通知觀察，逾時只清理自己啟動的程序。

## 2026-10-26：週日自願追問的耐久接續

既有終點邊界延伸一個有限的正式選擇：屋頂原鷺的「問今晚與週日的事」。選擇的接受旗標、接續段落與原 NPC 來源／對話索引先經原整輪寫入器保存，再發布接受通知。此時原 NPC 仍在等待，交談次數與「已問週日」都不增加；只有接續對話真正結束才一併保存已讀、閱讀歷史及 NPC 交談次數。

選項拒寫保留同一個播放器、原選單和原等待者，使用現有事件保存的重試介面。未解決前不能換選項或略過繞出；外部取消釋放自己持有的介面和鎖，不發布接受或完成。已提交後需要恢復時讀真實已保存候選。通知期間沿用既有故事發布鎖阻擋新故事生產者、重入選項與路由；一般扣款及 NEW 已讀合法，通知返回後重新捕捉入口，不能安裝過期提案覆蓋它們。

只有此正式來源、原場景與獎勵為空的真 NPC 互動可進入此接續。來源的預設選項必須仍為無結果的「先去做差事」，目標必須是原週日段落、原明確旗標結果及既有終點政策；資料改成其他支付、交物、內嵌步驟或帶結果預設時拒絕沿用此權限。新通用 atomic_v1 能力仍不存在，不能把其他故事選擇或多段接續自動標成耐久完成。

共用測試程序管理收斂為一份標準函式，保留原交盤三項通知的強制檢查；新增週日六程序包括真拒寫／重試、完成冷讀、通知當下原主檔的途中冷讀、外部取消、主動返回與預設略過。途中存檔只複製原 bytes，不重編封套、不補旗標或對話次數。畫面用軟體 Forward+／HDR 與安排好的既有簡報前提，和真人完整通關、硬體驗收分開。

Ink 的 [Saving and loading](https://github.com/inkle/ink/blob/master/Documentation/RunningYourInk.md#saving-and-loading) 與 [Yarn Spinner Godot 變數儲存](https://yarnspinner.dev/docs/godot/gdscript/05-connecting-to-your-game/04-variables-and-storage/) 說明支撐故事狀態與遊戲保存的整合；不能只存變數卻丟掉接續位置。[本票證據與三款相近作品原圖](../../pm/ST/attachments/ST-9-sunday-choice/README.md)另外記錄可觀察的構圖／對話層級；沒有由商店圖推論其他遊戲的磁碟原子性或玩家偏好統計。

## 2026-11-02：載入政策遺失不能移除既有 owner

`StoryResultCompletion` 的有限來源登記必須先於載入的 `completion_policy` 決定管轄。已由原來源承接的段落，即使政策遺失、錯型或被換成另一個合法政策，仍由同一結果 owner 拒絕；不能落入 legacy 結果或另一個旗標 owner。`Sources.boundary` 繼續嚴格比較原資源、模式、條件、操作與接續，不根據目前載入內容自動補登記。未知且未宣告的舊段落仍保留原行為。

補齊既有晚飯、四張標籤、鷺簡報、交盤／收據／摘要九個既有終點的獨立契約；不擴張到只有 NPC 綁定、實際為選擇根的段落。現有 43 個結果政策段落都有有限來源。獨立 audit 逐一驗證宣告與原契約一致，後續新增作者政策若漏登記會失敗。

內容與有限契約不符時屬語義錯誤：提示恢復完整原存檔，而不是一直重試同一無效候選。正常磁碟拒寫仍保留同一互動重試。有限終點被改成未登記選擇時，在真正選擇 gate 拒絕並退出原呈現；選項不能因政策一起遺失而提前寫旗標。

真 Main 在開始電影型對話時會正常保存未完成的對話入口。測試先觀察這份真正入口主檔，再比對拒絕時的完整 bytes；不能把正常入口保存誤判成結果提交。修復測試明示還原被破壞的載入字典，再按現有「恢復原進度」，原 reader 會續播真正已保存的未讀對話；不假稱 reader 自行修復了作者資源。重新完成後，旗標、物品、歷史與三份 world 的原人物次數須一起先持久化，再通知。

`story_marker_completion` 使用原當舖標籤、第二章巡帳員與租契物件，分別驗政策遺失、換政策、錯型、遺失政策加未登記選項，以及正常 IO 拒寫控制，各另程序冷讀。位置／前置檢查卡是明示安排，不能代稱自然整章通關。CI 保留所有原始主檔、通知時主檔、來源雜湊、退出碼與完整日誌。

## 2026-11-02：返家結算的獨立原來源

第一章返家 `ch1_c14_home` 是 `main_flags_v1` 的有限章末 intro，不屬於 NPC 終點結果 owner。新增 `StoryFlagSources` 固定原劇本檔、原晨間當舖、原模式、三個前置條件與兩個原結章結果；限制深度且逐層檢查型別，不從當下載入的結果反推授權。正常資料與台詞、動作、音效、物件、交易及章節路由不改。

`StoryFlagCompletion.complete` 先按獨立 ID 判定所有權；缺失／錯型的政策仍須原旗標 owner 處理。另一個看似合法的結果政策不能把它轉給結果 owner。有限來源不符時拒絕提交並提供整輪原進度恢復。正常 IO 拒寫仍保留原 intro 及原結章等待者，從同一完成請求重試。

未知選項在真正的選擇門轉回原旗標 owner 拒絕，保留原呈現及恢復提示，不能先套用選項再等結章保存。該拒絕只適用有限返家 ID；既有 NPC 選擇、重要通訊及舊工具仍走原入場規則。這不是所有重要通訊的有限來源登記，也不宣告其他章節結算自動獲得新能力。

正式探針從真 Main 進原晨間當舖，僅安排已吃宵夜／交盤的明示前置旗標，不預設本次返家、結章或已讀。缺政策、換政策、錯型、換另一已宣告結果、插入選項、換劇本來源及刪前置條件均在可寫目的地拒絕。每次修復測試明示還原載入字典／來源後讀原主檔；原未讀 intro 重新完成才公開兩個結果。正常 IO 拒寫另外控制，同一請求可重試。

兩次原旗標通知內驗兩結果與完成史皆已在帶原 checksum 主檔，且對話位置清空；章末卡此時尚未結束，不把旗標通知誤稱已顯示勝利畫面。之後另外等真正原章末卡完成，驗主檔 `chapter_complete`，再以另一個程序繼續進真正原結算畫面。原生閱讀控制送真閱讀事件，完整執行原 65 步，不直接設完成結果，也不以略過代稱完整演出。

## 2026-11-02：原備份錄音的有限來源

`StoryFlagSources` 另登記原檢查點事件錄音 `ch1_t_booth_recording`：原第一章劇本檔、radio 模式、布林 freeze=true、原唯一 `ch1_recording_heard` 結果及原空條件／接續／物品範圍。保留原建檔與檢查點的既有播放入口，不限制成只有某張地圖才准播。`terminal()` 明確區分返家 intro 與重要通訊；正常錄音不必假裝是 cinematic，正常通訊取消／重試語義不改。

錄音的凍結欄位缺失、錯型、被插入另一合法結果政策、換旗標、換劇本來源、插入前置條件或改成選項時，不能移除原旗標 owner。終點 owner 在完整寫入前嚴格比對有限契約；損壞內容只提供原整輪恢復，原 IO 拒寫仍可由同一請求重試。實際選項門在選項生效前交回同一 owner 拒絕。未登記的重要通訊繼續維持原入場規則，這不是所有 radio 的來源遷移。

真實電話亭事件本來就會更新 checkpoint、彈藥／補血及地圖備份標記；它們與錄音的已聽結果分開。觀察基線先等完整事件及訂閱者更新，再由真 Main 保存；損壞 freeze 時仍可能有合法舊狀態自動保存。錄音的嚴格 byte 比較因此在真正完成 gate 呼叫前讀取當前主檔，原 gate 的參數、回傳、候選及 writer 不替換。注入選項則在實際 choose 前取同一觀察點。初始檢查點主檔、完成前主檔、拒絕主檔、通知時主檔與最終主檔分別保留，不把合法時鐘／瞄準或地圖更新誤稱錄音提交。

恢復測試明示修復載入字典／來源，再讀真正原主檔。保存了未讀呈現入口的情況由原 reader 續讀；其他情況須重新用真正互動鍵撥原亭子，不能直接設已聽。接受後另一程序冷讀，驗原備份亭仍啟用；再次真的撥號只完成原備份，不重播已聽錄音、不重發結果。每個通知內另驗真主檔已有原旗標、完成史、檢查點區域及原保存座標。

原生互動測試須等實際 booth.can_dial，而不是只假定八個物理幀之後來源已刷新。輸入按下跨過 process_frame 與實際物理處理再釋放，避免軟體 Vulkan 的補幀節奏讓一個物理幀的合成按鍵無人處理。此修正只在探針；未改遊戲的輸入、電話時序或來源選擇。閱讀畫面以真 ui_accept 揭示原對白，不改台詞、可見字數或進度。
