# 第一章正式劇本的執行期契約（ST-9／ST-2／ST-3）

2026-10-11。取代保存分支 `a5f2a1ba` 的「原子提交／來源授權」框架：那套框架讓 Story 長到兩千多行、126 項測試失敗，且沒有讓第一章真正能玩。本輪改用 main 既有的劇情執行期，只補作者來源需要、能被測試與畫面驗證的最小欄位；新內容一律寫資料，不改程式。

## 資料流

```
tools/story/ch1_closure.py（作者來源：段落、條件、選項、段尾結果、任務語義）
        │  tools/story/ch1_runtime_backend.py（轉譯；build_ch1_story.py 的預設輸出也走這裡）
        ▼
data/story/ch1_kasa.json  ──►  autoload/story.gd ＋ core/story_outcomes.gd（播放、條件、結果）
tools/level/build_ch1.py  ──►  data/levels/ch1_*.tres、data/npcs/*.tres（入口、出現條件、世界事件旗標）
```

## 場景欄位

| 欄位 | 意義 |
|---|---|
| `when` | 前置條件（StoryConditionTree 格式：all／any／not、flag+equals、item＝目前手上有原件、receipt、account）。不成立就不播。 |
| `results` | 段尾結果：flag、item_acquire、item_transfer、transaction。**整段播完才一起生效**；先全部預檢，任一不成立整段不生效。 |
| `on_failure` | 交易被拒絕時改接的場景（例如現金不足改接「保留欠條／留下」的選擇）。 |
| `transfer_items` | 交出原件（ST-3）；選項上的交付等場景播完才生效，取消、死亡、換區就丟棄。預設選項不得交付。 |
| 選項 `target`、`when`、`set_flags`、`explanation` | 選了才接下一段；`set_flags` 只放可逆的意圖；說明在選擇畫面一句講清後果。 |
| `mode: dispatch` + `routes` | 人物／物件入口：依劇本階段挑第一個成立的段落；完成過的節點自動不重播。 |
| `then` | 同類演出接續：過場／動畫／對話接成一段鎖操作的演出；通訊／氣泡各自排隊。 |
| `context_facts` | 只在這串演出裡成立的事實（例如真正的初次建檔，回放不算）。 |

## 章節欄位

| 欄位 | 意義 |
|---|---|
| `transactions` | 正式交易 id → 資源（金額與互斥條件只在資源裡）。 |
| `derived_flags` | 由條件推出、每段結果後重算的旗標（例如四張標籤都讀過、還能不能重選去留）。 |
| `runtime_facts` | 讀當下服務、不存檔的事實：deaths_zero、checkpoint_registered、always、context:<鍵>。 |
| `restoration_flag` | 真正的一般死亡（不是初次建檔）且有登記電話亭時寫入，給「剛從電話亭回來嗎」這類台詞用。 |
| `event_scenes` | 世界事件第一次發生時播放的場景（第一次在電話亭備份播錄音）。 |
| `death_sequences` | 一般死亡畫面的序列；第一次死亡走初次建檔，不經過死亡畫面。 |

世界事件的旗標寫在產生它的資料上：關卡 `channel_done_flags`／`channel_cleared_flags`（打倒看門狗、水閘、路障解除）、物品 `acquire_flag`（拿到資料盤）。連續性審核從地圖本身就看得到誰產生旗標。

## 存檔契約變動（NE-230 請跟進）

- 新旗標都存在既有的本輪旗標裡（`story/flags`），沒有新增存檔欄位；執行期事實不存檔、讀檔後重新計算。
- 正式交易收據沿用 NE-231 的帳本快照；物品沿用 ST-3 的 held／transferred。
- 新增可存的世界旗標：`ch1_street_route_open`、`watchdog_defeated`、`ch1_flood_gate_open`、`ledger_disk_obtained`、`ch1_recording_heard`、`ch1_booth_restoration_done`。舊存檔缺這些值時退回預設 false。
- 序章（ST-16）新增可存旗標：每項練習的完成（`ch1_prologue_bench_done`、`_jump_done`、`_range_reached`、`_shot_done`、`_high_shot_done`、`_trainer_reached`、`_melee_done`、`_guard_done`、`_dash_done`）、訓練器確實打停過（`ch1_prologue_fall_shown`，不是死亡）、聽過服務說明（`ch1_prologue_service_heard`）、完成（`ch1_prologue_done`）、整段略過（`ch1_prologue_skipped`）。出口 `ch1_prologue_exit` 是衍生旗標＝完成、略過或已吃過晚飯任一成立，所以已在第一章的舊存檔不會被倒塞回序章；讀檔（`RunSnapshot.apply`）後重算。
- 續玩序章時，已完成的練習保持完成，老 K 的站位與訓練站的啟用都由旗標重算，不另存位置或計時。

## 世界物件跟著旗標更新

`GameState.flag_changed(flag, value)` 只在值真的改變時發出。人物依自己的 `spawn_requires_flag`／`spawn_unless_flag` 當場淡入淡出（例如序章老 K 跟著練習換位），不必等某段劇情播完；其他物件要跟旗標連動時接這個訊號，不要每影格輪詢。

## 2026-10-30：序章訓練結果的保存邊界

真 Main 的訓練站完成與首次被訓練器打停，先準備完整本輪快照，成功寫入既有存檔槽後才安裝旗標、更新器材及通知後續。訓練站必須來自目前關卡正式生成清單、使用原地圖資料且前置條件成立；工具後加的同位置副本不具結果來源資格。獨立 Level 預覽仍沿用原本本地行為。

拒寫時沒有完成旗標、後續解說或通知；世界暫停並提供重試，不重做玩家已成功的動作。連續拒寫維持同一結果。若必須重新載入，沿用原存檔復原提示。外部回主選單取消保留原主檔；下一次從真正未完成的位置繼續，不假造訓練結果。成功寫入同時保留未讀對白，程序立即結束後仍可從原解說接續。

沒有新增存檔欄位，沒有改變射擊／近戰／格擋／衝刺的判定、訓練傷害、死亡或首次建檔。新練習仍由 TrainingData 供應。保存期間阻擋一般自動保存與發布中的路由；同一通知內的其他正常變動交還 Main 排程保存，不用提案覆蓋後來的服務狀態。

`python3 tools/run_training_completion.py --godot <4.7.2> --output <新的絕對目錄>` 使用真正 Main 入口及原輸入路線；每案獨立程序／使用者設定／存檔槽，冷讀逐 bytes 複製前一個程序真正寫出的主檔。此流程包含走、跳、實際射擊、近戰、被訓練器打停、格擋與衝刺，不補教學旗標；合成操作不代稱真人全流程或實體裝置驗收。世界機關頻道與序章略過仍有各自保存責任，不能把本次邊界當成 ST-9 整票結案。

## 2026-10-30：略過序章與目的地共同保存

正式 Main 的略過確認，先以原關卡、原略過出口、固定目標與原略過旗標建立來源證明；預覽 Level 保留本地行為。結果與目的地入口合併進同一份完整本輪提案，成功寫入後才一起安裝旗標與路由。立即關閉遊戲也會從原目的地接續，不留下「略過已生效卻還在序章」的保存空檔。已有練習紀錄保留，未練過的不補完成。

失敗時凍結原關卡，提供「重試保存／繼續練習」；重試維持原提案來源，重複確認不產生第二份請求。取消不公開旗標、不離場、不改寫原主檔。原出口或目標在等待時改變，原請求失去資格；復原分支沿用備份／已保存進度的區分與焦點規則。

完整布林結果準備與耐久寫入抽為 `core/run_flag_commit.gd`，訓練結果共用同一邊界；目的地準備抽為純 `core/run_destination.gd`，一般區域、死亡重試與跨章入口沿用相同整理規則。來源證明、完整正規化比對與發布期間的路由／普通保存阻擋維持，不以放寬比對解決路由差異。

`python3 tools/run_skip_completion.py --godot <4.7.2> --output <新絕對目錄>` 驗證原新遊戲與暫停確認、拒寫、再次拒寫、取消、過期來源、已有真練習及逐 bytes 的獨立冷讀；原先訓練矩陣另驗共用邊界回歸。合成輸入／軟體 Vulkan 與真人、實體手把分開。世界機關頻道仍依自己的正式來源與保存責任驗收，ST-9 不以略過的局部交付結案。

## 2026-10-30：正式世界機關結果的保存邊界

關卡資料以 `durable_channel_results` 明確啟用已驗證來源契約，目前啟用第一章街道與倉庫；其他章的非致死制伏／拔插銷沿用既有結果責任，不把真正死亡當成它們的完成條件。正式 Main 接收原關卡生成清單中的踏板、機關、遭遇區或真正死亡頭目的頻道結果。來源須仍對應原地圖資源、腳本、頻道與原生成位置／敵人識別；後加副本與單獨頻道訊號不能授權完成旗標。同一輪訊號的世界變更先收齊，整份本輪快照成功寫入後才公開結果通知。頭目已完成自己的釋放不會遺失真正死亡時留下的來源證明。

保存失敗時維持原主檔與未接受旗標，凍結原世界並提供重試；第二次拒寫仍維持相同邊界。死亡、來源被改動或其他結果已要求復原時，只能重新載入完整已保存進度；不能先放行普通保存把半份世界寫回去。主選單退出保留原主檔。待處理結果與回呼各有 64 筆上限，超限走完整復原，不無限累積。

重要通訊與其他故事結果的完成回呼排在世界結果之後，避免依不同鎖的釋放順序寫出「世界已變、旗標未接受」。保存沿用原有單一未讀演出欄位；互斥的多份解說不猜順序，要求完整復原。已接受機關後的未讀重要通訊會在冷續玩時接續，關卡初始化完成即啟動通訊，取得閱讀凍結後才允許新的物理步。既有非凍結通訊維持原本時序。

同一輪已提出的原出口先等機關結果；之後目的地另依既有入口保存。來源區域不是章末，來源主檔不攜帶目的地出口。目的地拒寫後可重試原入口，或留在原區並恢復原暫停／背包允許狀態；不把已接受的機關結果回退。

公開重跑：`python3 tools/run_channel_completion.py --godot <4.7.2> --output <新絕對目錄>`。每案使用獨立真 Main、設定與存檔槽；倉庫／街道位置及致死事件是明示的原節點測試樣本，踏板使用實際物理接觸，並非自然整章戰鬥或真人驗收。冷讀使用先前程序實際保存的逐 bytes 主檔，不重建測試存檔。
