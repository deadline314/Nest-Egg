# 故事物品取得史與實物交付契約

ST-3，2026-10-10。依第一章收尾製作稿 F02／F03 與整輪存檔、中斷演出契約先補物品服務。本文與框架測試不表示 ST-9 正式交接櫃、場景、任務、回執、摘要或關卡已接入。

## 狀態與查詢

`owns`、`owned_items`、收集數與 NEW 標記都是本輪「曾取得」資料目錄。交出資料盤後歷史仍真，文件／錄音仍可回顧；NEW 只表示尚未讀過，不表示在手上。`holds(id)` 才表示目前實物持有；`was_transferred(id)` 表示本輪曾交出該原件。三個集合以物品目錄為上限；每個 owned 必須恰在 held 或 transferred 中，兩者不可交集，unseen 必須是 owned 子集。

`acquire(id, announce)` 只准首次取得目錄中真物品；先同步 owned、held、unseen，再請求保存和發取得訊號。已取得的物品（包含交出後）不會由場景完成、頭目或反覆呼叫再生。`transfer(id)` 只准目前 holds 的已知物品；先移除 held、加入 transferred，再請求保存與發 `transferred(item)`。未知／未拿／重交只回 false，沒有保存、訊號、提示或貨幣異動。此服務不發交付獎勵、不寫故事旗標、不判斷交易確認或場景重播來源；正式 backend 必須先驗實際確認與可用持有條件，並只在段尾完成路徑接入，不能用 owns 代替 holds。

新遊戲清空全部集合後才依既有 RUN_START 資料發放；普通死亡、檢查點、換區不重置物品。演出取消／讀入口快照沿現有 RunSnapshot 回撤全部集合，故未完成收盤段仍持盤；下段入口已包含交付則不能還盤。

## 存檔與相容

新 snapshot 保留 owned／unseen，新增 `custody_version: 1`、`held`、`transferred`（皆為目錄 id 陣列）。全部回傳副本；StringName 經 JSON 成 String、版本數字經 JSON 成精確 1.0 亦有效。轉 StringName 或複製前先用既有 RunSaveCodec 限制整個 raw tree（含額外欄位）的文字、節點、容器、深度、循環與引擎物件；診斷最多512字元。列表只接受 String／StringName，禁止未知、重複 id、超目錄數量及上述關係不一致。

舊格式必須完全缺少三個新增欄位，且 owned／unseen 為完整有效陣列；此時明確遷移為所有 owned 仍持有，transferred 空。不能從舊旗標猜已交盤；ST-9 的舊故事交接證據核對另行負責。任何新增欄位存在就視為新格式，缺值、null、壞型別、未知版本、部分集合均拒絕，不能降格 legacy 造回實物。

`prepare_snapshot(raw, where)` 純驗證、回傳 data 或帶欄位位置的 error。有效但不支援的版本另回 `unknown_version=true`，讓既有 RunSaveStore 禁止較新主檔降級備份或自動覆寫；缺漏／null／非整數版本是損毀。`restore` 先全驗證，失敗記警告且不修改任何集合、不發事件。這收緊了舊直接 restore 的「壞列表略過並清空」行為：合法 legacy 仍相容，損毀保留現況；現有壞故事檔旗標退預設的呼叫可繼續，不再順便吞掉物品。正式整輪 prepare 使用同一驗證器，失敗整份拒絕並讓 RunSaveStore 保留原檔／依既有完整備份恢復，沒有新增文件 IO。

既有 CollectiblesSuite 接入受控回歸：首次／重複交付、未知／未持有零異動、回呼與保存觀察同步狀態、歷史背包／收集不變、legacy／新 snapshot、真正 JSON 往返、無 alias、untrusted 拒絕且不半套用、整輪 prepare 原資料不變、磁碟 store 拒絕保留原件、普通檢查點／死亡／重建不復生、演出入口回撤與新輪重新發放。
