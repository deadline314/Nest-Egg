## 4. 劇本的機制怎麼用現有系統做

| 劇本 | 做法 |
|---|---|
| S02 修收音機 | 工作檯是一個物件；三個接點各一個選擇（電源、天線、音源），錯接只播一句雜訊說明再選一次；轉旋鈕兩段選擇；最後「儲存／關掉」。結果旗標分開寫（修好、聽到、儲存） |
| S06 付款或先問 | 選擇有真正的交易（代墊 40）與現金不足的改接場景，沿用第一章宵夜的交易流程 |
| S08 三份證據 | 每份證據是一個可讀的物件與劇情物品；取得即寫旗標與物品，順序任意 |
| S10 對帳 | 乾燥作業桌的三步選擇：先選本金欄、再選已付利息、最後選批號；選錯有劇本寫好的一句提示，可重選，不扣東西 |
| S12 斷連選擇 | 戰鬥中停下來的選擇說明（安全暫停）由頭目戰在血量門檻呼叫；隔離箱的操作是關卡機關。頭目本身由戰鬥 Session 製作 |
| S14 鷺的第 214 次 | B3 電話亭的短演出；次數存成章節旗標，同一事件只加一次 |
| S17～S21 客人簿 | 阿梨的視角：不讓玩家操作凜的身體走進阿梨的房間（那會變成凜在扮阿梨），改成從館外的客人簿入口開始的一串演出；客人名單可任意順序，每位客人的「問、聽、記、回答」是依序的選擇，錯的回答由客人說一句完整的話再選一次，可以隨時回到凜那邊 |
| S22 章末 | 屋頂演出、章末卡、存檔；港區交通線若還沒有實作，用劇本的「步行路線已接通」版本 |

## 5. 新旗標

依劇本第 6 節的狀態表命名；預設值由產生器從場景結果自動登記（第一章同一套）。存檔格式不變。

旗標檢查（ContinuityAudit）不允許拼字只差一兩個字的旗標，所以章末用 `ch2_heron_closed`（不和 `ch1_complete` 撞），三位客人用各自的物件命名：`guest_ticket_answered`（鄭先生）、`guest_band_answered`（陳女士）、`guest_letter_answered`（洪先生）。上屋頂的出入口要的旗標由早上結算的場景直接寫（`ch2_morning_settled`），不用推導旗標，地圖可達性檢查才看得到誰寫它。

## 6. 交付順序

1. 本文件、相依票（頭目、遭遇、新 NPC 外觀）。
2. 區域產生器與 11 個區域（可走完、出入口相通、電話亭站得穩、暗場可讀）。
3. 作者來源 S00～S22、回訪、任務與三語欄位；章節銜接。
4. 流程探針：從第一章結尾推到第二章章末，兩條阿勇路線與主要可選支線。
5. 舊第二章從正式流程移除。

頭目戰與遭遇交回前，阿勇戰以「戰鬥 Session 交付的頭目」為前置；本組的流程探針以真實的頭目事件入口（制伏旗標）銜接，並在票上寫明。

## 2026-10-30：原電池動作的持久結果

帳房明確啟用 `durable_channel_results`。阿勇以 `completed_channel()` 提供自己的非致命完成條件：已制伏且原 `BossHoldPoint` 電池的 `done` 為真；不以生命歸零或假死亡授權故事結果。共用 `ChannelCompletion` 仍核對原關卡、生成資料、追蹤鍵、節點身分與完成狀態，整份世界與旗標寫入後才通知。一般敵人及原死亡頭目保留自己的原死亡通道；第三章原插銷的獨立契約與交付另見 [CH03_IMPLEMENTATION](CH03_IMPLEMENTATION.md)。

拒絕時原場景凍結並提供重試；退出不接受結果，死亡或原來源被替換只允許讀回原整輪。真正電池互動由自動探針按住原互動鍵完成；末段位置、拆械與血量明示為測試樣本，不能代表完整自然戰鬥、張力或手把驗收。

關卡產生來源以每區 STORY 的 `durable=True` 明確宣告，同時保留第一章已遷移街道與倉庫；`check_channel_generation.py` 在獨立程序中用實際區域建構器產出暫存 LevelData，再比對已提交關卡的這項設定。只輸出到自有暫存目錄，不重寫正式地圖、人物與環境。這可避免下次產生關卡時把持久結果退回舊處理方式。未宣告區域維持原預設。

原生冷續玩另外揭露：已完成頭目 `queue_free()` 到這步結束才真正移除，仍可能先執行 dormant/wake 並重開血條。`PatternBoss._wake()` 現在拒絕等待刪除的節點，讓完成的原人物真正退場而不留下頭目血條；冷讀增加一項真 HUD 斷言，修前可重現。這不影響尚未完成、原本應醒來的頭目。

## 2026-11-02：原主隔離箱的成組旗標

原隔離箱完成時也由原阿勇提供 `ch2_yong_isolation` 收據，不能只呼叫完成回呼或發出頻道就授權。帳房的主旗標為 `yong_link_isolated`，`channel_done_extra_flags` 把 `yong_link_revoked` 列為同一動作的其他結果；解除類動作有對稱的 `channel_cleared_extra_flags`。主／其他旗標一次加入同一候選、同一整輪寫入、同一次靜默安裝，之後才逐一通知。每個通知當下必須已在磁碟與記憶體同時看到兩個結果。

這些映射納入來源契約簽章，等待重試時更換其他旗標映射也要回原整輪。完整旗標批次上限64，超量或空旗標拒絕安裝並要求原進度恢復，不以部分成功處理；原主檔bytes不變。已成立的主旗標不會掩蓋尚未成立的其他結果。

阿勇用祖先關卡的 `has_durable_channel_owner` 能力辨認正式Main，避免敵人反向預載Level。正式Main的原箱子／原地圖／原節點驗證仍必須成立；獨立演員工具沿用原本本地結果。故事作者來源的 `done_extra`／`cleared_extra` 產生對應欄位，三章29個原區域建構輸出現在同時核對擁有者與四組主／其他旗標宣告，不只核對durable布林值。

驗證明示前置斷連選擇、血量及位置為樣本；真正按住原箱子1.5秒完成。只有前置選擇由樣本安排，隔離／撤銷／制伏結果均不得直接設定。接受與取消的原整份主檔另開程序冷讀；隔離只恢復制伏階段，不等於已拔後續電池。原始退出音訊外洩由NE-282獨立提交0e146d39修正，原失敗保留。


## 巡帳員通行結果的持久化邊界（2026-11-02）

`ch2_t_s05_gate` 由作者 `ChapterSpec.completion_policies` 明示為
`main_terminal_results_v1`。共用編譯器只處理明示的段落，拒絕不存在的段落、
未知政策、分派入口與冒充終端結果的選擇／分支，不將第二、三章所有結果自動升級。

`story_result_ch2.gd` 獨立保存有限來源契約：第二章原 JSON、原巡帳員資源、
市集入口區域、對話模式、簡報已讀且尚未放行的完整條件，以及唯一放行結果。
共用來源查詢依契約取作者路徑；巢狀條件比較限16層，原載入樹大小限制仍保留。
Level 只登記原地圖建立的 NPC，結果要求原節點身分、原資源、格位、
進行中的原互動與既有資格。同資源同格位的事後複製品不能授權結果。已宣告保存政策的段落若被插入未登記選項，選取時直接拒絕，不退回舊的立即套用選項旗標路徑；原登記選項仍沿用其擁有者。

主檔保存成功後，放行旗標、已讀紀錄與 NPC 次數同時安裝，再發通知。

這是互動／存檔邊界樣本，不是從第二章開頭的自然完整通關。
