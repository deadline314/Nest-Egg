# 骨架與動畫 skill

目的：之後做任何骨架、動作、姿勢，都照業界與生物力學的規則來，不憑感覺調數字，也不重複踩過的坑。
每條規則標了性質：**出處**（有文獻或業界資料）、**建議**（我們的起點，要用量測與畫面調整）。完整資料與連結在參考文件，這裡只放做事要用的。

## 單位：用角色自己的尺

- **L = 站立時骨盆離地高度**（像素，`rig.rest(&"hip").y` 的絕對值；凜約 27 px）。所有長度規則都以 L 表示，不同身高的角色用同一組門檻。
- 步頻用「每秒幾步」（f_step，一個步伐週期 = 兩步）。

## 移動動作的規則（走、跑）

| 項目 | 規則 | 性質 |
|---|---|---|
| 步頻 | 走 1.4–2.0 Hz、慢跑 2.4–2.8 Hz、全速跑 2.8–3.2 Hz（短跑可到 4–5 Hz）；走跑轉換約 2.3 Hz | 出處 |
| 步長 | 走 0.55–0.85 L、跑 1.2–1.6 L；步長隨速度縮短（約 v^0.4–0.8），慢速不要用全速的大步 | 出處／建議 |
| 步態相位 | 用「走過的距離」累加，不用時間：phase += 距離 / 步長，踩地的腳才不會滑 | 出處 |
| 骨盆起伏（峰谷） | 走 0.03–0.06 L、跑 0.06–0.09 L；每步一個週期；走時最高在腳經過身體下方、跑時最低在踩地中段；**超過 0.07 L（走）就讀成彈跳／抖** | 出處（5 cm ≈ 0.055 L）／建議 |
| 骨盆基準高度 | 走 0.93 L、跑 0.88 L，永遠不把腿伸直（腿全伸會被 IK 夾斷再彈回） | 建議 |
| 身體高度怎麼算 | **身體高度 = 平滑的地面參考 + 由步態相位算出的起伏**；IK 只負責把腳放到地面，**不要用 IK 結果反推身體高度**（兩個頻率疊加就是「抖」） | 出處 |
| 腳 | 踩地時鎖定世界座標（不滑步）；擺盪離地 0.08–0.12 L（走）、0.2–0.3 L（跑）；腳掌滾動 heel strike → 放平 → toe off | 出處／建議 |
| 手臂 | 與對側腿同相；走擺幅 ±20–30°、肘近乎直；跑擺幅 ±40–55°、肘彎 80–100° | 建議 |
| 頭 | 反向補償軀幹俯仰，頭的上下起伏小於骨盆 | 出處 |
| 走↔跑 | 共用同一個相位變數，只改幅度（步長、起伏、膝角、前傾），0.15–0.25 秒連續過渡；速度門檻不可造成跳變 | 建議 |
| 加減速 | 加速前傾、煞車後仰，傾角約 atan(a/g) 並限幅（≤12°） | 推導 |

## 待機與 NPC（不要像機器人）

- 呼吸週期 3–5 秒、每次 ±10% 隨機，吸氣短呼氣長；胸 y ±0.006 L。（出處：靜息 12–20 次/分）
- 眨眼間隔用對數常態（中位數約 3.5 秒），一次 120–150 ms；說話時眨得更多。（出處）
- 重心轉移：每 4–12 秒隨機一次，0.6–1.0 秒緩入緩出，骨盆 ±0.02 L。（建議）
- 各骨頭用**互質的週期與不同相位**，不要用同一個正弦；緩動不用純正弦。（建議）
- 視線先動、頭後動、身體最後（差 0.05–0.15 秒）；說話手勢由重音觸發，不是固定循環。（建議）
- 每個角色自己的站姿、節奏、小動作寫在自己的資料檔，不共用。
- **已實作（NE-206，`NpcLife`，`game/rig/npc_life.gd`）**：預設在 `art/rigs/npc_animations.json` 的 `life`，每個角色在 `art/motion/<角色>.json` 的 `npc.life` 逐項蓋過（`tempo` 事件頻率、`amount` 整體幅度）。內容：drift（各骨頭兩個正弦疊起來、週期由「角色＋骨頭」決定且不同步）、breath（速率 ±10%、偶爾嘆氣只加深胸口不動骨盆）、shift（站著每 6–12 秒換腳，骨盆側移＋兩條大腿反向轉讓腳踝不動、空出來的腳膝微彎並把大腿反向轉一半，實測腳滑 ≤ 0.05 px）、glance（轉頭看一下，頭先動、頸與胸跟著）、beat（說話前吸氣、重音手勢與點頭、說完放鬆）、follow（頭、胸、前臂用欠阻尼二階彈簧追目標，有餘勢與過衝）。亂數種子是角色名稱：同一角色每次一樣，不同角色不同步。
- 踩過的坑：腳踩實地的重心轉移**不能只移骨盆**（腳跟著滑）；空出來的腳彎膝也會讓腳踝後退，要同時把大腿反向轉一半；嘆氣的起伏不能加在骨盆上（腳被帶著上下）。`npc.stand` 的角色專屬站姿調整以前因為 `_merge_into` 對空字典逐鍵蓋過而**從來沒套用**，現在整份採用且只在站著時加。
- 還做不到（需要美術，見 NE-221）：眨眼（頭是一整張圖、沒有眼睛分層）、大衣與圍裙的次級動態（NPC 骨架沒有衣襬骨頭與零件）。

## 姿勢（坐、蹲、靠、起身）

- **蹲不是坐在空氣椅子上**：真正的蹲臀部落到腳跟附近、膝蓋往前、上身前傾（`npc_animations.json` 的 crouch：`feet.sag` 0.75、前腳 x 0.6）；sag 0.55 以下髖比膝高，看起來像坐在看不見的椅子上（c01 的凜曾經如此）。改完用 `rig_preview --npc --bright` 看，並跑 `rig_pose_report`（腳離地應為 0、腳掌角度 0）。

- 重心要落在支撐面上：坐＝臀部在座面上、腳在地面（或腳踏）上；蹲＝腳掌放平、臀部降到腳跟上方；沒有支撐就不要擺出需要支撐的姿勢。
- **腳底與地面接觸要用數字驗證**：每個姿勢（每個骨架）量最低的腳底離地的距離（容許 ±0.5 px），不是目測。
- 換姿勢（坐→站、蹲→站）要有過渡：重心前移、腿伸直，不可瞬間換、也不可留在座位高度浮空。
- 姿勢切換前後的腳底離地距離要在容許範圍，違反就是浮空或陷地。

## 零件與關節

- **肢體關節網格（NE-204，已實作）**：上臂／前臂、大腿／小腿（骨頭名 `xxx_upper`／`xxx_lower` 且下段是上段的子骨頭）的零件，碰得到關節的自動做成 `RigPartMesh`（Polygon2D 網格，`game/rig/rig_part_mesh.gd`）：關節兩側各約下段骨長 0.3 倍（`limb_zone`，骨架定義或外觀定義可調）的頂點依距離在「跟自己的骨頭」與「跟夥伴骨頭」之間線性混合（關節正中 0.5），再把到肢體軸線的距離修回原本粗細（`volume_keep`）。**新角色不需要任何額外資料**；外觀定義 `limb_bend: false` 可關掉退回剛體。每格只重算關節附近的頂點、骨頭沒動就跳過、看不到的零件不算。折疊與縮腰由稽核量（`mesh_fold`、`limb_pinch`），彎到 90° 以上內側一定有皺褶，比例上限 40%。手腕、腳踝、髖、肩目前仍是剛體。看畫面：`rig_preview --chars=<角色> --joints --level=0~3`（左剛體、右網格）、`--rigid` 全部維持剛體；效能：`tools/rig_perf_probe.tscn`（每隻約 +36 µs/格）。
- **所有腳踩實地的角色（`grounding: true`）都要啟用等高跑法**（`move.level`、`bounce`、`rise`、`bob_slow`，數值抄 `art/motion/rin.json` 再依角色微調）：不寫的話骨盆起伏會有 0.10–0.16 L（sniper、stalker、reclaimer 曾經如此），`LocomotionSuite` 對所有 grounding 角色驗證起伏 ≤ 0.09 L、腳滑 ≤ 0.03 L。
- 零件節點的型別現在是 `Sprite2D` 或 `RigPartMesh`（都是 `CanvasItem`）：找零件用 `find_children("名稱", "CanvasItem")`，不要寫死 `Sprite2D`。
- 剛體零件在關節彎曲大時會露出切口與缺角：**彎曲角度 ≥ 60° 的關節（膝、肘）必須處理**——網格權重變形（Polygon2D＋Skeleton2D，權重在關節兩側各約 3 px 過渡、兩片零件用同一條權重函式）、或關節遮蓋、或彎曲姿勢的零件變體。
- 零件要在關節處重疊（目前流程只留 10 貼圖像素，約 0.6 世界像素，大角度不夠）。
- 相鄰零件的法線（打光）在切口附近要平順，否則切口會亮一條線。
- 後側的手腳比前側暗一點（亮度 0.62）以表示遠近。
- 圖層順序：**一個角色的所有零件是一組，不和其他角色或物件的圖層穿插**——見 skill `scene-staging` 的圖層章節與 `WorldLayers`。

## 業界做法速查（細節與出處在 `SKELETON_REFERENCE.md`）

| 主題 | 業界怎麼做 | 對我們的意思 |
|---|---|---|
| 工具慣例（Spine、Live2D、DragonBones） | 網格頂點同時權重到多根骨、關節附近加密並平滑權重；IK 約束的 mix 可以切換；繪製順序屬於 slot，換朝向要預先準備不同 slot；次要運動（頭髮衣物）用物理約束 | 關節用網格權重（Polygon2D＋Skeleton2D）；遠近側肢體的順序在建角色時就定好；彈簧骨輸入用軀幹加速度 |
| 雙手持槍（Spine 官方） | 武器骨掛在 root，不是身體骨的後代；兩隻手各有握點骨當 IK 目標 | 武器掛在 `Weapon` 節點、握點在武器資料（grip／foregrip），手臂用 IK |
| 零件切割（Live2D、Toon Boom、Adobe） | 會被遮住的部位多畫（脖子、大腿根）；關節用圓形重疊、旋轉軸在圓心；邊緣留透明邊 | 補全被擋住的部位（現有流程已做）；重疊量建議 ≥ 肢體寬度 25% |
| 逐格手繪（Cuphead 24 fps、Skullgirls、Hollow Knight） | 動畫格率低於遊戲 60 fps，靠強關鍵姿勢；輸入回應與動畫節奏分離 | 程式驅動不必平滑補間：關鍵姿勢要強、命中姿勢多停幾格 |
| 3D 偽 2D（Guilty Gear Xrd、Dead Cells、Hades） | Xrd 約 15 fps 無補間、招式 ≤ 20 格、關鍵格拉長停留；Dead Cells 為了手感調整可以快速改動畫 | 攻擊 3–6 個關鍵姿勢，命中姿勢 hold；動作資料化才能快速調手感 |
| 混用（Vanillaware、UbiArt） | 骨架負責大位移，關鍵時刻用手繪精靈或變形補足 | 骨架為主、少數姿勢用零件變體 |
| 程序動畫（Overgrowth 13 個關鍵姿勢、Rain World、Spore） | 極少關鍵姿勢＋程式內插＋IK；肢體由「固定距離連接的點」程序生成 | 姿勢資料少而精，步態由程式算（距離相位、腳鎖定） |
| 腳滑（Motion Matching、foot lock、stride warp） | 腳滑 = 移動速度與動畫速度不匹配；IK 只管垂直接地；踩地期間鎖腳的世界座標；高速時縮短擺動腿而不是拉伸動畫 | 距離相位＋踩地鎖腳＋步長隨速度縮放（本專案已實作） |
| 打擊停頓（Sakurai、Vlambeer） | 被打者多抖、停頓量可控、逐漸減弱；Vlambeer 開火鏡頭後座 6 px、震動 +4 | hit stop 輕/中/重三級（建議 2/4/6 影格），只凍結雙方動畫 |
| 預備與跟隨 | 預備 2–4 格（大動作 12–24 格）；輸入回應 < 100 ms；跟隨由彈簧骨做 | 判定不等動畫；預備 ≤ 3 影格 |
| 待機像人（生理數字） | 呼吸 12–20 次/分、眨眼 15–20 次/分（單次 100–150 ms）、掃視 30–120 ms、注視 200–600 ms | 見上方「待機與 NPC」 |
| 翻面（Godot／Unity 論壇、Spine） | `scale.x = -1` 翻綁骨角色會讓 IK 與附件出錯 | 只翻根節點，翻面時重設 IK 目標與彈簧狀態，並用測試驗證翻面前後的繪製順序 |
| Godot 4 | `SkeletonModification2D` 在 4.3 文件標為實驗性／過時 | 自寫 TwoBoneIK 與臨界阻尼彈簧（本專案已是自寫），不依賴它 |

## 骨架設計檢查清單

- [ ] 零件切到「會獨立旋轉的最小單位」（頭、頸、軀幹上下、骨盆、上臂前臂手、大腿小腿腳、頭髮、衣擺、配件），約 12–20 塊；被遮住的部位已補全
- [ ] 每個關節兩側零件重疊 ≥ 肢體寬度 25%，旋轉軸在圓心；肘、膝有網格權重或彎曲變體
- [ ] 骨頭命名一致（前後、上下、左右），父骨先於子骨；武器不掛在身體骨下
- [ ] 骨長 = 零件旋轉軸距離；IK 兩骨鏈總長 ≥ 目標最遠距離，否則夾限
- [ ] 遠側手腳在身體之後、亮度低 10–25%；需要改順序的零件預置兩個圖層，不即時重排
- [ ] 角度範圍寫進資料並有測試（肘 0–150°、膝 0–140° 等），骨長保持誤差 ≤ 0.5 px

## 動作設計檢查清單

- [ ] 待機：呼吸（髖領先）＋重心轉移＋眨眼＋視線，各自隨機且錯開；同畫面的 NPC 以角色 ID 為種子，相位不同步
- [ ] 走、跑：距離相位、踩地鎖腳、等高（膝蓋吸收）、起伏在預算內、步長隨速度縮放
- [ ] 跳：預備 2–4 影格 → 起跳拉伸 → 空中姿勢連續混合 → 落地吸收；起跳判定在按鍵當格
- [ ] 落地：擠壓 ≤ 10–15%（寫實）到 25–30%（卡通），2–4 影格回彈，體積守恆
- [ ] 蹲、坐：重心在支撐面上方，進出各 4–8 影格過渡，腳底接觸量測 ±0.5 px
- [ ] 說話：點頭與重音同步，手勢每 1.5–3 秒一次小的、強調時才大；被打斷可暫停再繼續
- [ ] 受擊：停頓 → 受擊姿勢立刻到位 → 抖動衰減 → 3–6 影格擺回
- [ ] 死亡：方向與力道取自致命一擊，主要部位先倒、次要部位跟隨，落地彈 1–2 次，結束後停掉彈簧運算
- [ ] 轉身：不瞬間翻面，窄化＋頭領先 2–4 影格；翻面時重設 IK 與彈簧

## 可自動化的測試（建議逐步補進 `tests/`）

骨長保持、關節角度範圍、腳滑（支撐相 ≤ 1 px/影格、累積 ≤ 3 px）、單格跳動尖峰（二階差分超過 P99 的 3 倍）、循環首尾閉合（≤ 1 px / 1°）、翻面前後繪製順序不變、關節遮蓋（極值角度渲染後關節 alpha ≥ 0.99）、呼吸 1000 影格不累積漂移、彈簧衝擊後 2 秒內衰減到 < 1%。已有：`AnimAuditSuite`、`LocomotionSuite`（移動量測門檻）。

## 工作流程（每次調動作都照著做）

1. 先讀上表對應的參考文件；改的是哪個角色就先看它的 `art/motion/<id>.json`。
2. 資料驅動：新欄位先在 `HumanoidAnimator.DEFAULT_MOTION` 給「不啟用」的預設值（其他角色不受影響），再寫進角色自己的資料檔；不要在程式裡寫死數字。
3. 量測，不憑感覺：
   `godot --headless --path . res://tools/rig_locomotion_report.tscn -- --skin=<id>` 印出各速度的骨盆起伏、主頻率、高頻比例、加速度倍率、單格變化、腳滑步。
4. 稽核與測試：`AnimAuditSuite`（關節範圍、骨長、腳踩實地、角度跳動）、`ProtagonistMotionSuite`、`LocomotionSuite`（移動量測門檻）、`RigActionsSuite`、`NpcAnimationSuite`。
5. 看畫面：`tools/rig_preview.tscn`（各動作並排）、`tools/screenshot.tscn --scenario=cutscenes:<場景>`。放大到過場倍率（約 3.4 倍）檢查關節。
6. 改完把新發現的規則、數字、坑補進這份 skill 與參考文件，不要只留在票或對話裡。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|---|---|---|
| 走路時身體持續上下抖 | 起伏幅度太大（凜曾經 7 px = 0.25 L）、步頻太高、骨盆高度由腳位置每影格重算又疊加 IK | 起伏 ≤ 0.09 L、拉長步長降低步頻、起伏用解析曲線 |
| 腳滑步 | 相位依時間而非距離；踩地沒鎖定 | 距離相位、踩地鎖腳 |
| 腿被拉直又彈回 | 基準高度太高，腿全伸被夾斷 | 基準高度 ≤ 0.93 L |
| 蹲、坐時浮空或陷地 | 姿勢用手調的 hip_y，沒有量腳底 | 用 IK 或量測補償；加姿勢稽核 |
| 關節切口、缺角 | 剛體零件大角度彎曲 | 網格權重、關節遮蓋或彎曲變體 |
| 站起來浮空 | 位置還在座位高度 | 過渡與落回地面 |
| 待機像機器人 | 單一正弦、固定週期、各骨同相位 | 隨機週期、不同相位、非對稱緩動 |
| 角色零件一半在別人前面一半在後面 | 圖層沒有成組 | 每個演員一組 z（`WorldLayers.stage_actor_z`） |
