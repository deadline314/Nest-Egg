# 使用者在意的事

這份是跨票的偏好清單。細節與做法在各 skill，這裡只放「他在意什麼、為什麼、怎麼避免再被退回」。使用者用繁體中文溝通，不要太多 emoji；全權交給我決定時，以業界最佳實例為主，不憑感覺調參數。

## 1. 畫面要真的對，不是「大致可以」

- **每個部件連接處都不能破圖**：關節、臀部、腰（上下半身交界）、肩、腕、踝、頸，在**過場倍率（約 3.4 倍）**與遊戲倍率下，任何動作、任何姿勢都不能有縫、缺角、直線切口。只看特寫、只檢查膝與肘就結案是被退回過的（NE-204、NE-220 → NE-222）。
- **外套、左右手的形狀要像外套與手**：圖層順序、分片、與槍的關係都要看；零件圖本身不行就開美術票，不要帶過。
- **動作與姿勢要有理由**：開場不能無故蹲著；蹲、坐、跪、靠都要符合場景。蹲姿修好之後不能退化（要有回歸檢查）。
- **主角的霓虹發光要保留**（鞋、軀幹、骨盆），同時**不能過曝**：頭在燈下變成一團白被退回過（NE-213）。畫面問題一律在 Forward+ 下驗證（skill `visual-verification`）。
- 不確定時看畫面，數字通過但畫面怪就是不通過。

## 2. 文字要好懂

- **不要用一兩個字的片段裝酷**（「地點，倉庫。目標，盤。」）：一句話講完一件事，完整句子。角色聲音靠用詞與語氣，不靠斷句。見 `design/13-story-v2/DIALOGUE_READABILITY.md`、票 ST-15。
- 任務標題、提示、tooltip 一樣：動詞開頭、完整、一行內。tooltip 與提示一句講重點，不寫廢話。

## 3. 玩家要知道要做什麼、去哪裡

- 要有任務目錄、地圖指引、目標列、鎖住的路的原因（`design/18-quest-map-ux/DESIGN.md`、票 NE-223）。新功能的提示與說明要完整，這也是 CLAUDE.md 的品質要求。
- 遊戲要有頭有尾：開頭有序章（`design/13-story-v2/PROLOGUE.md`、票 ST-16）；過場少、地圖上的短對話為主、不要走一段看一段。

## 4. 票要確實解決問題

- 票寫清楚驗收目標（可觀察、可驗證），開票後「確實修復所有相關問題或實作所有功能」，不是只處理最顯眼的一項。
- **不要提早結案**：驗收條件沒有逐條達成就不要改成完成；使用者推翻過的結案要在票上承認並重開／封存。
- 需求先整理進 `design/`，再依 `pm-ticket` 開票；每張票做完各自 commit 並 push（CLAUDE.md §4），commit 作者 `Stanley Li <stanley890314@gmail.com>`，訊息不得出現 AI 名稱或署名行。
- 使用者說「只開票」就只開票，不順手實作；說「花久一點沒關係」就花時間做到對。

## 5. 工程品質（每張票的前提）

可維護、資料驅動、可擴充、高容錯（錯誤訊息指出具體位置並退回安全預設）、高效能與低記憶體（不要每格配置、能用物件池就用）、不破壞原有功能（受影響範圍測試全過、CI 紅了優先處理）。詳見 `CLAUDE.md` §1。
