# 全角色、全部件的骨架與立繪接合驗證

適用於玩家、人形敵人、NPC、過場演員與非人形角色。不是只驗膝肘或上下半身：角色上每一個會顯示的零件、它連到的身體部位、附件與裝備都須登記並檢查。沒有該部件／動作時寫「不適用＋理由」，不可用主角通過代表其他角色通過。

閱讀時機：新增或替換角色、重新分割／補全、改支點／骨架／網格／圖層／彈簧／動作、處理破圖、交付角色相關票前。

## 0. 判定與證據

完成須同時成立：**立繪正確、零件正確、綁定正確、全部接點正確、動作與操作合理、實際渲染正確**。任一失敗都保留未驗收。**小裂縫、一像素孔洞、缺角與漂浮碎片也不得給過；大缺口已消失不代表通過。**

- 資料檢查、無頭測試、像素量測、逐格檢視、實際播放與操作是不同證據，各自記錄。通過其中一項不能替代其他項。
- 使用者同意、人工試玩／試聽不能自行勾選。沒有 GPU、沒有播放、没有執行的檢查寫「未驗證」，不得以示意圖或文字冒充實機截圖。
- 每個失敗記錄角色、部件／接點、動作、方向、時間或影格、倍率、武器／裝甲狀態、圖像與重現指令。
- 修前修後比較使用同一姿勢、方向、時間、倍率、光照與裝備。截圖不可裁掉手、腳、槍口、頭或要檢查的接點。
- 2026-10-08 的使用者實例：`pm/Nest-Egg/images/NE-181-user-body-disconnection.png`。軀幹與腿沒有正確接合，即使沒有程式錯誤，仍是破圖。該图是失敗例，不是驗收通過圖。

## 1. 建立角色與部件帳本

從目前版本的角色定義、骨架、動作、武器與零件圖片列出角色；對照實際遊戲及過場載入路徑，找出借用外觀、未使用圖、缺圖與備援外觀。不得只檢查資料夾內第一個角色。

每個零件至少登記：

| 欄位 | 內容 |
|---|---|
| 角色／部件 | 唯一 ID，近側／遠側與用途 |
| 來源 | 原圖、提示詞、種子、補全步驟、分割遮罩、手工修正依据 |
| 裁切 | 原圖座標、貼圖尺寸、支點、縮放、旋轉／偏移 |
| 綁定 | 主骨、父骨、受影響骨、權重／網格或剛體原因 |
| 接點 | 接到哪個零件、接點座標、正常遮擋與容許動作範圍 |
| 圖層 | 近遠側順序、武器／衣物／護甲遮擋與翻面規則 |
| 狀態 | 常態、受傷、脫甲、死亡、隱藏／備援 |
| 驗證 | 資料、像素、逐格、播放、遊戲內的結果與證據連結 |

建立接點表，包含下面所有適用項目；不能只列骨頭名稱：

| 區域 | 必查連接 |
|---|---|
| 頭臉 | 頭－頸－胸、前後髮－頭皮、劉海／髮束根部、眼白－虹膜－眼皮、眉與臉、面罩／帽／頭盔掛點 |
| 身體 | 胸－腰－骨盆、前後肩－胸、臀／髖－前後大腿、腹部與腰帶／槍套 |
| 雙臂 | 左右／近遠側肩－上臂－肘－前臂－腕－手、袖窿－袖子－袖口、手－持物握點 |
| 雙腿 | 左右／近遠側髖－大腿－膝－小腿－踝－腳、褲口／靴口、腳掌與地面 |
| 衣物 | 領－肩－衣身、衣身－前後衣襬、圍裙／大衣／裙擺的固定邊與活動邊 |
| 裝備 | 護肩／胸甲／護腕／護膝的固定部位、背包／槍套／武器、脫落後底層 |
| 非人形 | 頭／顎－頸－軀幹、各足根－上段－下段－足、尾根－尾段、翼／角／觸手／機械附件；依解剖與設計登記 |

## 2. 原立繪與分割：先確認畫的是對的

1. 對照定稿全身圖、臉部、側面與頭像，確認身份、比例、服裝與配色一致。保持已同意定稿的來源，派生修復不冒充重新批准。
2. 人形按設計確認一個頭、一個軀幹、兩臂兩手兩腿兩腳；遮住的肢體仍須能說明位置。四足角色確認四足外觀與步態，不能借人形外觀交差。
3. 放大檢查手指黏連／多指、額外手或腳、重複臉／眼睛、融化裝備、無來源的線條與配件、不合理衣物結構、左右比例及遠近側錯誤。不能只用「AI 感較低」的主觀一句話。
4. 每張零件獨立放在棋盤格、淺灰與深灰底檢視，再以原座標拼回原圖。兩種看法都要做：完整角色會遮住錯切的手，單件會暴露它。
5. 一張近側腿貼圖只含一條腿與一個腳；一張手貼圖只含一隻手。近遠側重用圖片時，不能再把原圖的另一條腿／手一起切入。護甲和手若在腿零件中留下第二份，必須移除。
6. 分群先後順序、未認領像素的歸屬及批次 SAM 回傳遮罩逐項核對。不能依輸出執行順序猜 prompt 對應；每張遮罩與命名須一一相符。
7. 膚色、布料、頭髮與金屬的輪廓／陰影要有結構，不能用大片插值漸層補一整個髖或大腿。小邊緣修補與大面積缺失分開處理。
8. 被手臂、頭髮、護甲遮住的身體要有完整底層。先用現有原圖重分割；確實缺圖才補全。檢查補全圖是否真的移除了遮擋物，以及腰帶、髖部等是否被遮罩漏掉。
9. 補全可見區的改動必須可比較；不得把多餘的手、護甲或新的服装線條當成底層。未受影響的定稿與原圖不重跑。
10. 原圖、原尺寸補全圖、遮罩、分割依據、配方和種子保留。只重跑受影響步驟；合成背景與檢視圖另存，不能覆蓋原透明圖。

**通過：**解剖／穿著合理；每件内容單一且正确；靜止拼合吻合；移開遮擋物後底層仍完整；沒有額外肢體、孔洞、孤立碎片或大面積假補色。

## 3. 骨架與支點：先驗靜止拼合，再驗動態

- 統一原圖像素、貼圖像素、骨架世界單位、角色縮放、過場縮放。記錄轉換倍率；縮放支點和貼圖時使用同一套轉換。
- 骨頭命名唯一、父子鏈無循環；參考骨與部件存在，資料有限且有效；缺資源有明确錯誤與安全備援，不能靜默假裝交付外觀正確。
- 支點放在解剖旋轉中心，不能放在裁切矩形中心。裁切／去透明邊／旋轉後重新換算支點，尺寸變動同步更新角色定義。
- 骨長對應原圖實際接點距離；IK 的上、下段及彎曲方向正確，不能反膝、反肘或為追握點無限拉長骨頭。
- 靜止姿勢關閉次級動態、IK 修正與武器，拼回全身；再逐一啟用。逐骨單獨轉動並觀察跟著走的零件，找出綁錯骨、重複變換與兩次縮放。
- 外套衣身跟軀幹，袖子跟手臂；領口固定在肩頸，衣襬根部固定在衣身。頭髮根部跟頭，髮尾可以跟隨。腳與手不能依附於衣襬或無關骨頭。
- 若使用蒙皮，權重非負、有限且總和規範化；靜止姿勢不變形；新增頂點有權重。關節兩側使用一致座標與變形規則，不能各做一套互相分離的位移。
- 在會彎曲的位置配置內部頂點及適當三角形。整片矩形綁錯骨不能靠增加頂點數修好；缺失貼圖也不能靠網格拉出身體。
- 翻面只在適當根節點進行；世界／骨架座標的握點、槍口、IK 和彈簧狀態一起驗證。轉身、傳送、重生不甩飛附件。

**通過：**靜止拼合正確、支點一致、各骨只帶動應帶動的零件、完整父子鏈、有限且合理的 IK／權重、兩面向都正確。

## 4. 接合修復：從缺圖到幾何，不靠遮暗

依根因選最小有效修復：缺底層→補全；錯切／夾入他物→重分割；裁切座標錯→修支點；綁错骨→改綁定；大角度直線切口→網格／合理重疊／姿勢變體；光照線→修接縫法線。

1. 對每個接點在原圖與骨架中標定同一中心，檢查兩側實際可見像素是否都延伸到該中心。只讓裁切矩形重疊不算有像素重疊。
2. 切線不能離關節中心一大段，否則旋轉時兩片像門扇分開。重疊須包含被遮住的有效材質，不是透明邊或別隻手。
3. 重疊量依零件寬度、角度極值與放大畫面決定；既有「寬度 25%」是起試建議，不是通過保證。採用數字後仍須檢查所有目標姿勢。
4. 軀幹、骨盆、髖與肩等寬部位不能只用細小膝肘模型假設。網格轉動時保留合理橫截面，處理接點兩側，避免只拉伸其中一片。
5. 變形不得造成大幅縮腰、反轉三角形、扭結、材質長條拉伸或不合理穿插。折疊及宽度指標須保留有效性；換算法時以實際幾何重驗，不能移除稽核或提高門檻來讓失敗通過。
6. 手腕、踝、頸、領口、髮根、衣襬根部與附件固定邊亦須連續。活動邊可離開身體；固定邊不能漂浮。預期的衣口、雙腿間空隙不要誤判為漏縫。
7. 修前修後除錯顯示骨頭、支點、遮罩／網格；正式驗收畫面關掉除錯圖層，確認真的没有縫和切斷感。

## 5. 像素接縫量測：要能定位失敗

沿接點量測不是單取骨頭中心的 alpha：中心不一定在實際材質內，且鄰近手、武器或其他角色可能把缺口遮住。

1. 對每個登記接點，在姿勢變換後取得相鄰零件的接點與切線；建立只涵蓋預期接合材質的小範圍。
2. 以透明背景輸出該角色／相鄰零件的 alpha；排除其他演員、武器、特效與無關遮擋，另驗全角色正式渲染。
3. 沿兩件延伸方向之間的局部剖面取多條樣本，確認兩側有效材質連通、預期輪廓內沒有背景洞或跨過整個接合區的背景裂線。不能只驗包圍盒交疊。
4. 抗鋸齒只容許實際外輪廓的半透明邊；輪廓內裂線不能當成抗鋸齒忽略。alpha 門檻、採樣解析度、區域、容差與排除的正常開口都写入報告。
5. 相同影格輸出透明材質、深灰背景、淺灰背景。alpha 檢查通過後仍檢查法線亮邊、斷線、錯色、重複輪廓與衣物穿插。
6. 對全部適用動作、兩面向、遊戲倍率及約 3.4 倍過場倍率逐格量測；已聲稱「全部逐格」時不得只抽三格。
7. 每個違規輸出角色、接點、狀態、影格／時間、尺度、背景洞／斷裂數與圖片。先用故意移開一片的失敗案例驗證稽核確實會報錯，再對修復結果要求違規數為 0。

現有 `check_parts.py` 檢查單張零件，AnimAudit 檢查動畫幾何／姿態；**兩者都不能單獨證明動態渲染接縫沒有洞**。若本次要求接縫逐格檢查，而目前沒有此工具，先補工具和能抓到破圖的回歸檢查，不能假称已自動驗過。

## 6. 動作與狀態覆蓋

先從動畫器、動作資料、玩法與過場資料列出實際支援項目。每個循環至少審查四個相位；每個非循環至少起始、峰值、結束，另外播放整段與檢查狀態切換。有逐格驗收要求則整段逐格檢查。

| 類別 | 檢查狀態 |
|---|---|
| 移動 | 待機、走、跑、起步、煞車、轉身、上坡／下坡與落差（遊戲有支援時） |
| 空中 | 起跳、上升、頂點、下落、落地、衝刺與取消／結束 |
| 蹲 | 蹲入／蹲出、蹲待機、蹲走、蹲瞄準、過場蹲；腳掌平放、臀部近腳跟、膝蓋向前，上身不穿入大腿 |
| 戰鬥 | 全瞄準角、射擊／後座、單手／雙手／空手、每個近戰招式、格擋／完美格擋、受擊／硬直 |
| 專屬 | 換彈、換武器、爬梯、上下載具、打電話／握話筒、操作機關、角色獨有招式 |
| 死亡／損傷 | 前後方向、輕重致命一擊、倒下、最終靜止、各脫甲／破損階段、燒融（已有功能時） |
| NPC／過場 | 站、坐、靠、蹲、跪、倒下、起身、說話、聆聽、揮手、工作循環及場景實際姿勢 |
| 非人形 | 該角色實際待機、移動、攻擊、受擊、倒下；四足的支撐順序、四足接地及重心 |

每個項目驗全部接點，不只該動作最顯眼的肢體。重要狀態配對要測：蹲＋瞄準、跑＋射擊、換武器＋轉身、受擊＋脫甲、過場放大＋坐／蹲等。不要無意增加角色尚未支援的新玩法。

**穿著與附件專項：**

- Rin 外套須看出領口、肩線、袖窿、袖子與衣身是穿在身上的一件衣物；不能读成披肩或懸浮藍塊。站、跑、跳、蹲、瞄準、受擊及死亡檢查固定邊、前後衣襬與圖層。
- 衣襬／髮尾彈簧不影響固定邊；根部位置連續、運動有跟隨和收束，翻面／傳送／重生不炸開，靜止時不持續漂移。新零件套用角色受光與法線流程。
- 左右手對應握點，槍柄／前握把／刀柄／話筒不能浮在手外；手腕不斷裂、前後手輪廓清楚、無第三隻手。槍口、近戰命中與護盾掛點使用實際變換。
- 把每片護甲依序移除，檢查底層和其餘固定件；脫落碎片由當時姿勢生成，不突然跳回靜止位置。
- 眼白、虹膜、眼皮各有正確位置與層序；眨眼不能把整顆頭壓扁、虹膜穿出眼皮或留下一條洞。

## 7. 遊戲內、光照與操作

- 開真實關卡／過場，在角色實際出現位置檢查光影、鏡頭、倍率與遮擋，不能只驗排隊展示工具。
- 坐有座面、靠有支撐、蹲跪有劇情理由；腳底與地面接觸，從坐／蹲站起後不留在座位高度。舞台姿勢规则交給 scene-staging，故事內容由所屬 Session 處理。
- Forward+ 使用實際可用 GPU；無硬體時才用已存在的軟體 Vulkan。記錄引擎、GPU／驅動、渲染模式與解析度。
- 霓虹發光与過曝限制分別確認：看得到適度泛光，白色護甲仍保留細節；與原版在相同光照下量測。不用關閉發光讓過曝測試過關。
- 真正操作或可重現輸入重播檢查：移動起停、轉向、跳躍、蹲、射擊、近戰、格擋與取消，判定與畫面對得上。次級動態不可延遲輸入或改變既有命中／碰撞時序。
- 手感數值以本專案目前設定及可信原始資料為起點；沒有公開可靠數字时標為「專案建議／實測值」，不能编造業界標準。紀錄輸入回應時間、轉換時間、腳滑与起伏等實測及調整理由。

## 8. 重跑方法與 GPU 協調

以下是**現有工具**，從 repo 根目錄執行。先查看目前參數支援及票的指定範圍；把示例中的 `rin`、路徑與倍率換成實際項目。Windows 可用已存在的 Godot 絕對路徑及 Git Bash，不安裝第二套引擎。

```powershell
# 先設定實際存在的工具；COMFYUI_DIR 從現有流程查得，不照舊票硬編。

# Godot 匯入、Forward+ 截圖與效能量測都走共享 GPU 鎖。
```

## 蹲姿臀腿輪廓驗收（2026-10-08，NE-222）

使用者指出凜蹲下時臀部圖形怪異。**接點沒有洞不代表臀腿合格**：重複臀部、球狀凸塊、截斷輪廓、尖角、折片、穿插與不合理體積都須修復。

1. 在原尺寸來源標示骨盆、近側股骨頭與大腿、遠側大腿的歸屬。骨盆保留一份臀部體積；兩條可獨立旋轉的大腿各保留一條腿，不能把完整臀部或另一條腿一起複製進去。源圖被遮住時先查既有底層，不靠擴大圓形遮蓋片來湊接點 alpha。
2. 以原圖座標拼合；移開衣襬、槍套與前後腿，分別看單件、接點隔離與完整角色。檢查髖支點是否位於股骨旋轉中心，腿根權重是否平順接回骨盆。錯切或錯綁先修正，增加頂點不能修好部件歸屬錯誤。
3. 記錄蹲入、最深蹲、蹲走／反向、蹲瞄高低角度、蹲起，以及過場蹲／坐到站的實際時間軸；兩面向、遊戲與最大過場倍率都查。臀部應與骨盆一起移動並自然過渡至大腿，不能拖出第二個臀部或在不同姿勢忽大忽小；重心、腳底支撐、膝與上身穿插也同時檢查。
4. 一般蒙皮在深蹲仍造成不合理輪廓時，可採用局部姿勢修正或同風格彎曲變體。只修受影響材質，記錄來源、角度範圍、觸發方式與切換證據；驗證進出與中間角度，不能只換一張好看的峰值圖或改整張已同意定稿。
5. 同時通過逐格接點與全彩輪廓檢視，保留修前／修後原生畫面。像素量測、AnimAudit 與骨長通過，仍不能代替解剖／外觀檢視；沒有實際覆蓋的动作標為未驗證。不能放寬孔洞、折疊、體積、頂點或效能門檻來取得通過。

## 持槍單膝跪姿（2026-10-08 使用者指定）

持槍且停下來蹲瞄時使用合理的單膝跪地姿勢：前腳掌支撐、前膝朝腳尖方向，後膝接近地面並確實承重，後側小腿向後折、後腳跟抬起。胸腹保持可支撐射擊的姿態；雙手貼握把與前握點，槍托、肩、瞄準方向與槍口一致。依角色骨架與裝備調整，不能直接抄用參考圖片做零件。

區分一般蹲姿、持槍靜止跪瞄與低姿移動。移動時解除跪姿，避免膝蓋拖地；換向、換槍、卸槍、蹲入、蹲起、瞄準上下掃描都檢查完整中間影格。電話、空手與非槍械物件不套用槍械跪瞄。維持原有操作數據，視覺過渡不能造成輸入延遲或槍口與實際射擊方向偏離。

骨架檢查：骨長不變、髖與膝朝向合理、前腳底及後膝的實際材質輪廓接觸同一地面、後脚及靴筒無穿地。不能以腳支點坐標代替材質接地，也不能只檢查最低一隻腳。全彩檢查：臀部只保留一份，臀腿不長出球狀凸塊，外套下襬不穿入大腿，靴筒折彎不折成尖角或斷裂，所有接點仍遵守一像素缺口不通過。兩面向、遊戲與過場倍率、所有瞄準角及起落切換需逐格接點＋原生全彩證據；測試骨架通過不代表立繪通過。


### 過場移動的速度空間（NE-222）

過場的骨架動畫不得固定餵一個「走路速度」。必須以演員的舞台位移除以影格時間，再除以演員倍率與骨架本身倍率，換回腿部求解器的座標空間。角色向左時保留實際負速度，由動畫器做一次面向轉換；不要再乘第二次面向。鏡頭移動不算演員走動，首次加入舞台的位置不算移動，停在原地須停止踏步。播放速度加快、不同移動距離／時間及不同角色倍率均須依實際位移驗證，不修改劇情的移動時間或舞台配置來掩蓋滑步。

用真正的 CutscenePlayer 播放凜返家及老 K 往返段落，保留連續原生畫面、位移／步態速度資料與修前修後對照。兩面向、起步、四個步態相位、停止、走跑切換、空手／持物均需檢查腳掌接地、膝蓋和臀腿輪廓、手臂擺動與衣物接點；靜態三格或一般關卡正常不能替代過場通過。測試與實機外觀分開記錄，部件瑕疵仍須拒收。


## 仰躺／俯臥與完整倒地（NE-222，2026-10-09 使用者指定）

1. 拒收只將站姿整體旋轉90度的結果。先在遊戲鏡頭方向畫出失衡、身體下降、軀幹接地、四肢跟隨及安定的關鍵姿勢；仰躺臉朝上、背接地，俯臥臉朝下、胸腹接地。姿態參考見NE-222的兩張使用者附件，不直接剪成遊戲零件。
2. 從真正致命一擊記錄來源位置、角色死亡時的面向及衝擊力，選擇後倒仰躺或前撲俯臥；左右翻面只鏡射一次，選擇後鎖定到動作結束。來源不存在、正上方、零擊退及已被釋放的攻擊者都要有可重跑安全預設與回歸，不憑下一格的瞄準方向重選。
3. 每個關鍵姿勢分別檢查頭頸、胸腰骨盆、兩側肩肘腕／髖膝踝；手臂自然落在身體兩侧或前方，腿有合理屈伸與錯開，不能仍保持站立握槍。重擊可改倒下速度與過渡，不可讓最後姿勢持續翹起。現有動作插值／資料流程能用就沿用；若側面素材無法表達俯臥或仰躺，準備局部姿態變體及進出證據，不能過度扭曲或重新生成已同意的整张定稿。
4. 用實際可見材質檢查背部／胸腹支撐及地面接觸；頭髮尾端、腳尖或透明貼圖邊碰地不能替代軀幹接地。實際腳底來源平面與步行踝中心平面分清，保留骨長與穿地檢查。髮束、衣襬與附件應隨倒下慣性跟隨、接觸後安定，不能用站姿風力懸垂、穿地或持续彈跳。
5. 兩面向、正背致命攻擊、輕重击、從空中死亡再落地、場景坡面／平台邊緣及必要護甲狀態都檢查。先用隔離接點逐格稽核，再看完整原生全彩與真正戰鬥播放；至少保留失衡、落地、安定及過渡格，連續影片辅助閱讀，不能取代單像素量測。
6. 檢查跑步、瞄準、近戰與電話等姿態能被死亡正確打斷；死亡判定、操控禁止、物理落地、掉落與重生流程不退化。資料測試、AnimAudit、接縫零違規、全彩外觀與實際戰鬥分開記錄，仍有一项未通過就不勾選。


### 可脫落裝甲與完整身體（NE-222）

外觀零件有受損層，不代表整張圖可當成物理裝甲碎片。區分真正裝甲片與包含軀幹／骨盆／四肢的衣物圖；凜這類衣物受損須保留完整身體和既有受傷變化，不拋出整段身體、重複肢體或完整衣服剪影。從真正受傷事件逐級降低HP、回血，再致死；確認衣物受損與回血恢復仍運作、身體仍完整，兩面向和前後來源的原生畫面中地面沒有誤用身體零件。真正裝甲敵人另驗證裝甲片仍會飛散，不能全面關掉命中效果。
