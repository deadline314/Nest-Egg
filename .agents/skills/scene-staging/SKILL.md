# 場景佈景與過場舞台 skill

目的：之後做關卡與過場，不再反覆犯「燈籠比人大」「梯子只有三格高」「站起來浮空」「圖層穿插」這類錯。**所有尺寸都用角色身高 H 當尺，所有位置都有明確的接觸線，做完用量測與截圖檢查，不憑感覺。**
性質標記：**出處**（有文獻或業界資料）、**建議**（我們的起點，要用畫面實測調整）。完整資料與連結：`design/10-presentation/STAGING_REFERENCE.md`（讀過才動手）；骨架與動作的規則在 skill `rig-animation`。

## 五條鐵則

1. **一個場景只有一個 H**（角色站立身高，像素）。所有物件登記成 H 的倍數；過場裡的門與關卡裡的門要一致。
2. **每個站在地上的東西都有接觸線 y**（物件底邊、演員腳底）。同一深度的物件接觸線差 ≤ 2 px；演員腳底 = 站位接觸線（誤差 ≤ 1 px）。排序、縮放、陰影都用這條線。
3. **一個角色的所有零件是一組**，不和別的角色或物件的圖層穿插（`WorldLayers`）。
4. **坐、靠、蹲要有支撐，換姿勢要有過渡**：臀部在座面上、腳在地面上；站起來先鎖腳再升骨盆，不浮空、不瞬移。
5. **尺寸算「縮放」不要寫死倍率**：貼圖解析度各不相同，縮放 = 場景 H 比例 × 邏輯大小 ÷ 貼圖寬（麵攤燈籠曾經因為把縮放寫死成 ÷4 而大 2.5 倍）。

## 我們的場景怎麼組成（要改的地方在哪）

**關卡**（`data/levels/*.tres` + `*_map.json`，由 `tools/level/build_ch1.py` 產生）
- 格子 16 px，角色站立約 56 px（H ≈ 3.5 格）。室內天花板用 `Area.ceiling(x0, x1, rows)`，淨高 = 地面列 − rows 列。
- 出入口 `PORTALS` 的 `w`／`h`（像素）決定視覺與互動範圍。**室內的梯子高度必須通到天花板**（`Chapter1MapSuite` 檢查：梯子高 ≥ 地面到天花板的 80%）；屋頂等頭上沒有天花板的梯子不檢查。
- 圖層（`game/level/world_layers.gd`）：靜態場景（背牆、導軌、裝飾、背景道具、地形）在 −24 ~ −20，**所有角色零件在 −9 ~ +12**，非角色的實體（看板、檢查點、出入口、開關、拾取物、箱子）一律排在 `WorldLayers.ENTITY_BEHIND`（−10）。前景道具、水面刻意在角色之上的有自己的 z，不動。新增一種實體時若 z 預設為 0，會被 `Level._send_behind_characters` 自動排到角色之下；要蓋在角色上必須明確指定 z。

**過場舞台**（`data/cutscene/stages/*.json`，第一章由 `tools/story/build_ch1_story.py` 產生）
- 舞台是 BG-11 場景立繪（1536×864）縮成 0.5 倍鋪滿（`pos [-64, -36]`），座標範圍約 −64..704 × −36..396；對話框在畫面下緣約 22%，腳底要落在畫面約 70% 以上。
- 圖層種類：gradient、sprite、glow、poly、rain、motes、grain…（`StageLayers`）；`depth: back|front`：back 在所有演員之下、front 在其上。
- **腳底線 `FLOOR`、演員縮放 `SCALE`、坐姿的髖高 `HIP_SIT`**：先從立繪裡量參考物（門、櫃台、欄杆、桌椅）定出 H，再定演員縮放（同一舞台上的人縮放一致）；坐姿腳底 y = 座面 + (坐姿髖高 − 骨盆半高) × 縮放（`sit_y`）。
- 補在立繪上的場景專屬物件（`art/environment/scene_props/`）：縮放 = `actor_scale × 邏輯寬 ÷ 貼圖寬`（邏輯大小是 `data/props` 的世界像素）；吊掛物（燈籠）掛在支撐物上，`lift` 也要乘縮放。
- 演員的圖層：`CutscenePlayer` 每個演員佔一組 z（`WorldLayers.stage_actor_z`，後登場的在前面，actor 步驟的 `layer` 可指定），最多 `MAX_STAGE_ACTORS` 個。

**自動檢查（NE-210，`SceneAudit` ＋ `SceneSanitySuite`）**：對 `data/levels/` 底下**每一張**關卡自動跑（新增關卡放進資料夾就會被檢查，不用登記）。
| 代碼 | 抓什麼 | 嚴重度 |
|---|---|---|
| `embedded` | 敵人、人物、機關、出入口的身體與實心地形重疊超過 4 像素（尺寸取自各資料：敵人 `body_size`、出入口寬高、機關與可破壞物 `size_tiles`） | 錯誤 |
| `floating` / `overhang` / `on_hazard` | 腳下沒有地、一半以上懸空、站在尖刺或雷射上（飛行敵人與道具不需要地） | 錯誤／警告 |
| `ladder_short` | 梯子頂端離天花板超過 1 格（「梯子三格高、房間十格高」）；`ladder_open`：露天的梯子頂端附近沒有平台可踏 | 錯誤／警告 |
| `ladder_pair` | 梯子兩端都是梯子但高度不同；梯子可以接 `hidden`／`door`（另一端是樓梯間的門） | 警告 |
| `door_small` | 出入口矮於 32 像素（比主角還矮） | 警告 |
| `unreachable` | 從主角起點走、跳（上 5 格、橫 7 格）、落下到不了的出入口、人物、商店、道具、檢查點（升降梯與水坑浮橋算平台） | 警告 |
| `prop_floating` / `prop_outside` / `prop_buried` | 擺設腳下沒地表、超出地圖、陷進實心地形超過 4 像素（背景道具貼著高牆時會出現；看過畫面確認是景深就在地圖 JSON 的那一筆加 `"allow_overlap": true`） | 錯誤／警告 |
| `stage_feet` / `stage_scale` | 過場演員腳底離舞台地板線超過 14 像素（坐、蹲、跪、倒除外）、同舞台同角色縮放差超過一成 | 警告 |
所有關卡都不允許未處理的警告或錯誤：看過畫面確認沒問題的警告，在資料裡標記（例如擺設的 `allow_overlap`）。報告：`godot --headless --path . res://tools/scene_report.tscn [-- --level=ch1_street]`。截圖定位：`--scenario=place:關卡id:欄[:標籤[:enemies]]`。
**出入口 `style: hidden`**：什麼都不畫，只留互動範圍與提示；用在擺設本身就有門的地方（屋頂樓梯間），不要在已經有門的圖上再疊一條梯子或門框。

**檢查**：`CutsceneChecker`（步驟欄位、台詞限制、`layer` 範圍）、`LayerOrderSuite`（角色 z 範圍、場景在角色之下、演員不穿插、實體不落在角色圖層中間）、`Chapter1MapSuite`（地圖、出入口、梯子高度、道具在地圖內）。

## 踩過的坑（每一條都出過事）

- **`life: true`（窗光閃爍）不能開在整張背景上**：它每 16 像素一格、讓約兩成的格子忽明忽暗，整張場景立繪會被切成一格一格的深色方塊，看起來像「破圖」。`life` 只能用在窗光、信標這類小面積的層（`StageLibrary.validate` 會抓整張背景開 life）。
- **場景專屬物件的縮放不能寫死倍率**：麵攤 6 倍、其他物件 10 倍，寫死 ÷4 會讓燈籠與桌子大 2.5 倍。縮放 = 演員縮放 × 邏輯寬 ÷ 貼圖寬。
- **對話框蓋住畫面下緣約 25%**：演員的腳底在畫面上的 y 不能超過 266（共 360）。鏡頭中心 y ≥ 地面線 − 82 ÷ 縮放；`CutsceneChecker.staging_problems` 會檢查（新寫的過場要通過）。產生器的 `stage()`／`cam()` 會自動夾住鏡頭 y。
- **頭頂不能進上方黑邊（ST-10）**：過場整段是 21:9，上下各有約 43 像素的黑邊；可用的高度只有黑邊到對話框之間約 219 像素。演員站立高度 = 骨架身高（凜 58、老 K 56 像素）× 縮放，超過就一定被切：廚房的凜 221、老 K 236，所以那個舞台鏡頭要拉遠到 0.86，推近最多 0.9。`CutsceneChecker.staging_problems` 會在台詞、等待、旁白這些「畫面停下來」的步驟檢查腳底與頭頂，違規會指出場景、步驟與演員。
- **坐在高處時不要用舞台地板夾鏡頭**：診間的凜坐在檢查台邊、腳懸空，鏡頭照地板線往下壓就把頭切掉了。`stage(..., feet=她的腳底 y)` 用實際最低的腳底夾鏡頭；她站起來落回地板的那一步用 `cam(..., feet=FLOOR[st])` 把鏡頭跟下去。
- **舞台上補的擺設由場景檢查把關**：`SceneAudit.stage_prop_issues` 檢查畫出來的大小是否等於「擺設世界尺寸 × 演員縮放」（差兩成以上報 `stage_prop_scale`），以及底邊是否在地面線上（`stage_prop_floating`）；掛著或放在別的東西上的圖層要寫 `"support"`（產生器的 `sprite(..., lift)` 會自動加 `hang`）。
- **特寫鏡頭放大倍率受腳底規則限制**：腳底要在畫面 266 之上，放大 1.9 倍時鏡頭中心被夾到 y ≥ 地面線 − 82 ÷ 1.9，高的演員（縮放 3.8–4.2）頭就被切掉，只剩腿和靴子（c14 章末曾經如此）。要拍臉就把演員縮放定小一點或只放大到 1.05–1.2；放大後一定要看截圖確認頭還在畫面裡。
- **圖層**：非角色實體 z 預設 0 會落在角色零件中間（後腳被看板蓋住）；過場演員共用 z 會互相穿插。
- **全白的舞台會吃掉白頭髮**：診間的白窗加白色柔光讓凜的頭髮和背景糊成一片（NE-251）。亮的舞台要把立繪色調壓到比白髮暗一階、柔光改有色並調弱（`tools/story/build_ch1_story.py` 的 `STAGE_TONE`），不要調暗角色；新舞台做完跑 `tools/ne251_wake_probe.tscn -- --mode=sweep`，純白 ≤ 2%、糊掉 ≤ 5%。

## 位置與構圖

- 站位用槽位（畫面寬 W 的 0.12、0.30、0.50、0.70、0.88）：兩人對話在 0.30W 與 0.70W，朝向對方；三人在 0.15、0.50、0.85W 並前後錯開；4–5 人分兩排。（出處：Mask of the Rose 的 5 槽位）
- 左邊的人面向右、右邊的人面向左；一段對話內不跨 180 度線。
- 臉朝的方向留視線空間；頭頂留 0.15–0.35H；眼睛接近畫面上 1/3 線；說話者用前後位置強調，不用放大。
- 側視平面背景：不依 y 縮放，多人只靠前後排序；背景畫了明顯透視（長走廊、地板格線）才用 `scale(y) = (y − y_horizon) / (y_ref − y_horizon)`。兩種不可混用。
- 地平線 = 眼高；背景的 eye level 要和角色一致。
- 前景遮擋物只放畫面邊緣 1/6 內或不擋臉的下緣，不擋對話角色的臉與字幕框。
- 每個站地物件（含演員）加壓扁的接觸陰影（寬 = 底座 × 1.1–1.4、高 = 寬 × 0.2–0.35、不透明 30–50%），這是修「飄浮感」最便宜的做法，也會暴露接觸線對不齊的物件。
- 會包住演員的家具（桌、吧台、椅）拆成 `back`（永遠在演員後面）與 `front`（永遠在前面）兩層，演員坐著時夾在中間：腿在桌下、手在桌上。

## 工作流程

1. 讀 `design/10-presentation/STAGING_REFERENCE.md` 對應章節；改過場先看同場景現有資料與 `tools/story/build_ch1_story.py` 的常數。
2. 先定 H 與地面線：量立繪裡的參考物，不是猜。畫出 H 的刻度與地面線的偵錯圖。
3. 物件逐一登記尺寸（H 的倍數）與接觸線；用比例表檢查每一件（吊燈、桌、凳、梯、門…）。
4. 資料產生器改完重新產生：`python3 tools/story/build_ch1_story.py`、`python3 tools/level/build_ch1.py`（輸出有 diff 才提交；`__pycache__` 不要提交）。
5. 跑檢查：`GODOT=… tools/run_tests_changed.sh`（`LayerOrderSuite`、`CutsceneSuite`、`Chapter1MapSuite`、`ChapterCutscenesSuite`）。
6. **看畫面**：`godot --path . res://tools/screenshot.tscn -- --out=<資料夾> --scenario=cutscenes:<場景 id>`（過場）或 `--scenario=spots:<關卡檔>:<名稱>`（關卡）；放大檢查接觸線、前後遮擋、比例。需要有顯示環境。
7. 修前修後截圖並排，存到 `pm/<專案>/images/`。
8. 學到的新規則、新尺寸、新的坑補進這份 skill 與參考文件。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|---|---|---|
| 燈籠、桌子比人還大 | 縮放寫死倍率；沒登記 H 倍數 | 縮放 = 演員縮放 × 邏輯寬 ÷ 貼圖寬；用比例表檢查 |
| 梯子只有三格高、房間十格高 | 出入口高度沒跟著空間 | 室內梯子通到天花板；橫桿數 = 高度 ÷ 0.18H（`ladder_short` 會抓） |
| 屋頂的門上疊了一條三格高的梯子 | 另一端的樓梯間已經有門，出入口又畫一次 | 用 `style: hidden`，互動範圍對在擺設的門上 |
| 敵人貼著牆出生、身體卡進去 | 地圖字元放得離牆不到身體寬度的一半 | 離牆至少半個身體寬（`embedded` 會抓） |
| 腳底與地面線沒對齊 | 用精靈中心定位；沒量地面 | 站位直接給接觸線 y；原點在腳底 |
| 坐在椅子上但椅子懸空、桌椅不成比例 | 座面高沒對骨盆；桌椅各自縮放 | 座面 = 0.25–0.30H；桌面比座面高 0.14–0.24H；坐姿用 `sit_y` |
| 站起來浮空 | 位置還在座位高度 | 起身過渡：先落回地面接觸線 |
| 演員與家具遮擋錯誤 | 零件各自排序；家具沒拆 back/front | 演員一組 z；家具分層 |
| 角色的後腿在看板後面 | 實體 z = 0 落在角色圖層中間 | 非角色實體排在 `ENTITY_BEHIND` |
| 兩個角色的身體零件互相穿插 | 兩個演員共用同一組 z | 每個演員一組 z |
| 角色縮放與背景透視不一致 | 背景有透視但角色縮放固定 | 單一模式；有透視用 scale(y) |
| 多人站位像合照、背對對方 | 沒有槽位與朝向規則 | 槽位化、預設朝向對方 |
| 同一道具在不同場景大小不同 | 各場景各自縮放素材 | 以資料的邏輯大小為準 |

## 玩家文字交付基線（ST-15；2026-10-07 UTC）

- 先讀 `design/13-story-v2/DIALOGUE_READABILITY.md`；完整句子規則優先於舊「短句」稿。先讓玩家看懂誰在哪裡、要做什麼、為什麼，再處理節奏。

- 一行最多一個三字以內子句且不相鄰；首次出現的專名在同場景交代身分／地點／用途。名稱、按鈕、編號、數值是標籤，只有明確分類的標籤免用句子門檻；廣播、公文與 formal 講者沒有可讀性豁免。
